This is the human-facing status page for Coppice integrations. It separates
what is implemented from what has been exercised in a real app or device. A
route, DTO, or successful server replay is not by itself proof that every client
works.

For route-level details and pinned source references, see [client
verification](/docs/developer/client-verification), [platform
status](/docs/developer/platforms), and [protocol standards](/docs/developer/standards).

## Evidence labels

- **Shipped** — the implementation is present in this fork.
- **Contract-tested** — a pinned fixture, replay, or server harness exercised a
  protocol surface. It does not prove that a physical app works.
- **Device-tested** — a real app or device ran the flow against Coppice.
- **Source-only** — pinned client or protocol source was inspected without a
  live run.
- **Planned** — a future capability or design item.
- **Blocked** — a prerequisite is missing, so the flow is not currently
  claimable.

## Provider status

### Hardcover

Hardcover metadata mapping is **Shipped** and **Contract-tested** against
offline payload fixtures. Coppice has not been verified with a live Hardcover
credential; live-credential verification is **Blocked** until a controlled
credential run is available.

Hardcover account, reading progress, and journal synchronization are
**Planned** and currently **Blocked**. They are not implied by metadata lookup,
and no OAuth or account-sync workflow is shipped. See the [Hardcover developer
record](/docs/developer/hardcover-integration) for the exact boundary.

### Storyteller and read-aloud

Synchronized Storyteller read-aloud EPUB playback is **not shipped**. Storyteller
is a future worker-side alignment backend, not a search provider, catalog
provider, or bundled dependency. The current product keeps ordinary EPUB
playback and ordinary audiobook playback separate.

A future alignment flow starts only after an EPUB and audiobook pair has been
confirmed. It can then import existing timing data, run a Storyteller worker,
and use a native CTC fallback candidate. The worker and synchronized playback
remain **Planned**; current app playback is therefore **Blocked**. See [read-aloud
architecture](/docs/developer/read-aloud).
