# Kobo Sync

Coppice exposes a Kobo-shaped sync profile for compatible Kobo clients. The
server route and payloads are **Shipped** and **Contract-tested**. No physical
Kobo has run against Coppice, so physical-device compatibility is **Blocked**
and must not be inferred from a server replay. See the [compatibility and
integration status](/docs/guides/integrations/compatibility) and the [Kobo
developer record](/docs/developer/kobo-sync-capabilities) for the detailed
route contract.

<Callout title="Permission required">
	This functionality is gated behind the `ACCESS_KOBO_SYNC` and `ACCESS_API_KEYS` user permissions.
	To learn more about permissions, see the [permissions](/docs/guides/access-control/permissions)
	guide.
</Callout>

## What is covered

The contract-tested profile covers initialization, library sync, metadata,
reading-state GET/PUT, file delivery with `Range`, and KEPUB delivery where the
conversion option is enabled. ReadingState can carry progress, status,
statistics, and a Kobo location. It does not make Kobo highlights or
annotations available as Coppice records. Store purchases are not proxied or
synchronized through this profile.

## Setup

To set up Kobo sync with Coppice:

<Steps>

<Step>

### Enable the Kobo routes

The server must be compiled with the Cargo `kobo` feature. In the default
`full` profile it is included; in a leaf build use the [modular deployment
guide](/docs/guides/configuration/modular-deployment).

Enable the runtime route with `ENABLE_KOBO_SYNC=true`, or set
`enable_kobo_sync=true` in the `Stump.toml` configuration file. The runtime
switch does nothing if the binary was compiled without `kobo`.

See the [configuration guide](/docs/guides/configuration/server-config) for
other server settings.

</Step>

<Step>

### Add the device in the Home app

Open the Home app at `/app`, choose **Devices** → **Add client**, and select
**Kobo**. The [Devices guide](/docs/guides/features/devices) explains the
one-time secret and Kobo endpoint card. Copy the endpoint URL shown by the app;
it is the value to use for `api_endpoint` below. Configure the Kobo before
closing the dialog because the full secret is shown only once.
</Step>

<Step>

### Fallback: Create an API key

<Callout type="warn" title="API-key fallback">
	This still works, but a raw API key does not provide a device kind, per-device
	library scope, last-seen tracking, or device credential rotation. For reader
	devices, the Home app flow above is the preferred path.
</Callout>

<Callout title="Permission required">This step requires the `ACCESS_API_KEYS` user permission.</Callout>

The key is stored in plaintext on the Kobo device. In the Coppice web UI:

1. Navigate to the app settings (`/settings`).
2. Open the **API keys** tab (`/settings/api-keys`).
3. Select **Create API key**.
4. Grant `ACCESS_KOBO_SYNC` and `DOWNLOAD_FILE`.
5. Save the complete value when it is shown; it cannot be recovered later.

</Step>

<Step>

### Point the Kobo at Coppice

Connect the Kobo to your computer and open
`.kobo/Kobo/Kobo eReader.conf`. Replace the store endpoint:

```ini
api_endpoint=https://storeapi.kobo.com
```

with the Coppice endpoint:

```ini
api_endpoint=http(s)://your-server(:port)(/baseUrl)/kobo/{api_key}
```

For example:

```ini
api_endpoint=http://192.168.4.100:10801/kobo/98765432109876543210876543210987
```

For the API-key fallback, `api_key` is the complete key from the previous step.
With the Home app flow, use the complete endpoint URL it showed instead. Keep
the endpoint private: anyone who obtains the key can use the permissions granted
to it.
</Step>

</Steps>

## Optional KEPUB conversion

Coppice can convert an EPUB to Kobo's KEPUB form when the server has the
converter compiled and `KOBO_KEPUB_CONVERSION=true` is enabled. Conversion
changes the delivered bytes and creates Kobo-specific `koboSpan` coordinates;
it is separate from ReadingState persistence. If conversion is disabled, the
server can still deliver ordinary EPUB files.

## Force a sync

If the server-side sync state needs to be rebuilt, use an authenticated request:

```http
DELETE /api/v2/kobo/sync-sessions
Authorization: Bearer <your-token>
```

This removes stored sync sessions for the account. Trigger a fresh sync on the
Kobo afterwards. If the device still skips the library sync step, restore
`.kobo/Kobo/Kobo eReader.conf` to its original endpoint, sync once, then point
it back to Coppice and sync again.

## Evidence boundary

- **Shipped:** the Kobo adapter, ReadingState contract, file/range delivery,
  and optional KEPUB conversion are in the server.
- **Contract-tested:** initialization, library sync, ReadingState round-trip,
  KEPUB output, and `Range` delivery have been replayed.
- **Blocked:** no physical Kobo run has been recorded, so battery, firmware,
  store-account, and device-database behavior are not claims.
- **Planned:** broader device verification and any future annotation channel
  require an explicit device-side contract; they are not implied by the current
  ReadingState endpoint.
