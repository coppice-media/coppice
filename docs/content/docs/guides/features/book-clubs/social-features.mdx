<Callout type="info" title="Member rooms versus guest sessions">
	GraphQL implements book-club member discussions and message reactions, replies, edits, and
	deletes, but Home does not yet expose member-room controls. The [guest reader](/docs/guides/features/book-clubs/guest-reader)
	has its own live discussion UI with a separate session-scoped plain-text contract; guests
	never gain access to club member rooms.
</Callout>

## Member discussions

The server supports pinned and book-specific member discussions. GraphQL
operations include reactions (standard and custom emoji), inline replies,
one level of threading, and editing/deleting your own messages; moderators
can also edit/delete others' messages. Member-room mutations do not publish
live message events yet (`crates/graphql/src/mutation/book_club_discussion.rs`).
The Home **Social** screen currently has no member-room controls, so these
operations are API-only from that app.

The guest-reader session discussion is distinct: it has live SSE-triggered
updates, per-participant aliases and moderation controls in the organizer
panel. See [Guest reading links](/docs/guides/features/book-clubs/guest-reader)
for its access, privacy, and format limits.

Future member-room UX may include notifications, spoiler-safe formatting, or
live event delivery; none is required to use the guest reader.

## Recommendations and scoped reading shares

Recommendations are directed to one active user and keep an immutable snapshot
of the title, authors, cover, provider, and remote identifiers. A recipient can
accept, decline, dismiss an accepted recommendation, or request it through the
normal private request flow. Accepting never starts a download and never grants
access to the sender's library.

Reading shares are separate, explicit grants. The recipient must accept a
pending grant before any projection is visible, and the sender or recipient can
revoke it. Each grant names its scopes: metadata, rating, review text,
completion, coarse percentage, or annotations. Shared annotations are
recipient-side projections; they do not become the recipient's own highlights,
notes, or bookmarks and are removed from view when the grant is revoked.

The server stores only normalized snapshots and opaque target keys for adaptive
recommendations. Tracker credentials, private review text outside an accepted
scope, raw download URLs, and sender-only media/work identifiers never cross a
social boundary. Users can opt out of recommendations or sharing independently.
Shared highlight colors are deterministic per source and work (yellow, green,
blue, pink, purple, or orange), so a page remains visually stable.

## Important Disclaimers

<Callout type="warning" title="Not a secure messaging platform">
	Club discussions and guest session messages are for casual book conversation,
	not secrets or sensitive communications. Messages are stored as plaintext in
	the database; this is not an end-to-end encrypted messaging service.
</Callout>
