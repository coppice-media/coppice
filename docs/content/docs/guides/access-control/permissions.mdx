title: Permissions
---

Users can be assigned permissions that grant access to features or actions within Coppice. Without a grant, an action may be refused; there is no separate explicit-deny permission.

## Granting permissions

The server owner, or a user with `MANAGE_USERS`, grants permissions on the Home
app's **Users** screen (`/app/users`): **New user** creates a local account and
**Edit** changes an existing one. Permissions are grouped by area. Ticking one
also grants the permissions it includes, which the editor shows as *Included*
and saves with it. Saving an edit replaces the account's permissions, age
restriction, and session limit and signs the account out everywhere, so the
change applies at its next sign-in.

- Nobody changes their own permissions: the server ignores permission, age
  restriction, and session-limit changes to your own account, so another user
  manager or the server owner makes them.
- The server owner's account cannot be edited; the owner already holds every
  permission.
- Locking an account, signing it out everywhere, and deleting it are reserved
  for the server owner. `READ_USERS` alone shows the list without edit controls.
- For accounts that sign in through OIDC, [permission synchronization](#oidc-group-mappings)
  can replace these permissions at every sign-in.

| Granting                                     | Also includes                                                       |
| -------------------------------------------- | ------------------------------------------------------------------- |
| `CREATE_BOOK_CLUB`, `SHARE_BOOK_CLUB_READER` | `ACCESS_BOOK_CLUB`                                                  |
| `EMAILER_MANAGE`                             | `EMAILER_CREATE`, `EMAILER_READ`, `EMAIL_SEND`                      |
| `EMAILER_CREATE`                             | `EMAILER_READ`, `EMAIL_SEND`                                        |
| `EMAILER_READ`, `EMAIL_ARBITRARY_SEND`       | `EMAIL_SEND`                                                        |
| `DELETE_LIBRARY`                             | `MANAGE_LIBRARY`, `SCAN_LIBRARY`, `EDIT_LIBRARY`, `EDIT_THUMBNAILS` |
| `MANAGE_LIBRARY`                             | `SCAN_LIBRARY`, `EDIT_LIBRARY`, `EDIT_THUMBNAILS`                   |
| `CREATE_LIBRARY`                             | `EDIT_LIBRARY`, `SCAN_LIBRARY`                                      |
| `MANAGE_NOTIFIER`, `DELETE_NOTIFIER`         | Each other, `CREATE_NOTIFIER`, `READ_NOTIFIER`                      |
| `CREATE_NOTIFIER`                            | `READ_NOTIFIER`                                                     |
| `MANAGE_USERS`                               | `READ_USERS`                                                        |
| `READ_PERSISTED_LOGS`                        | `READ_JOBS`                                                         |
| `WRITE_BACK_METADATA`                        | `EDIT_METADATA`                                                     |

| Change own avatar | `CHANGE_AVATAR` | Allows replacing the account's own avatar |
| API Keys            | `ACCESS_API_KEYS`      | Allows access to read/create their own API keys             |
| KoReader Sync       | `ACCESS_KOREADER_SYNC` | Allows access to the KoReader sync integration              |

| Remote source | `ACCESS_REMOTE_SOURCE` | Allows a source worker to advertise configured roots and serve explicitly authorized reads |
| Remote worker | `ACCESS_WORKER` | Allows a worker to claim jobs and upload outputs |
| Access Book Club    | `ACCESS_BOOK_CLUB`     | Allows access to the Book Club feature                      |
| Create Book Club    | `CREATE_BOOK_CLUB`     | Allows creating new Book Clubs                              |
| Share Book Club Reader | `SHARE_BOOK_CLUB_READER` | Allows club Admins/Creators to issue [guest reading links](/docs/guides/features/book-clubs/guest-reader) (implies `ACCESS_BOOK_CLUB`) |

| Access Smart List   | `ACCESS_SMART_LIST`    | Allows access to the Smart List feature                     |

| Download File       | `DOWNLOAD_FILE`        | Allows downloading files from a library                     |
| Create Library      | `CREATE_LIBRARY`       | Allows creating new libraries                               |
| Edit Library        | `EDIT_LIBRARY`         | Allows editing basic details about libraries                |
| Scan Library        | `SCAN_LIBRARY`         | Allows scanning libraries for new files                     |
| Manage Library      | `MANAGE_LIBRARY`       | Allows managing libraries (scan, edit, manage relations)    |
| Edit thumbnails | `EDIT_THUMBNAILS` | Allows changing media and series thumbnails |
| Edit Metadata       | `EDIT_METADATA`        | Allows editing database-level metadata for media/series     |
| Write Back Metadata | `WRITE_BACK_METADATA`  | Allows writing database metadata back to files              |

| Manage metadata fetches | `METADATA_FETCH_RECORD_MANAGE` | Allows managing metadata fetch records |
| View metadata providers | `METADATA_PROVIDER_READ` | Allows reading configured metadata providers |
| Manage metadata providers | `METADATA_PROVIDER_MANAGE` | Allows managing metadata provider configurations |
| Delete Library      | `DELETE_LIBRARY`       | Allows deleting libraries                                   |
| Read Users          | `READ_USERS`           | Allows reading user information via user-specific endpoints |
| Manage Users        | `MANAGE_USERS`         | Allows creating users and editing other users' permissions, age restriction, and session limit (locking, signing out, and deleting stay with the server owner) |
| Acquire releases | `ACQUIRE_RELEASES` | Allows manager-only search and confirmed grabs for approved requests via Coppice's GraphQL API; see [acquisition](/docs/guides/integrations/acquisition) |
| Read Notifier       | `READ_NOTIFIER`        | Allows reading configured notifiers                         |
| Create Notifier     | `CREATE_NOTIFIER`      | Allows creating new notifiers                               |
| Manage Notifier     | `MANAGE_NOTIFIER`      | Allows managing existing notifiers                          |
| Delete Notifier     | `DELETE_NOTIFIER`      | Allows deleting notifiers                                   |
| Read Jobs           | `READ_JOBS`            | Allows reading job information                              |
| Manage Jobs         | `MANAGE_JOBS`          | Allows managing jobs (pause, resume, delete, cancel)        |
| Read Persisted Logs | `READ_PERSISTED_LOGS`  | Allows reading application-level logs (e.g., job logs)      |

| Manage Server       | `MANAGE_SERVER`        | Allows managing server settings and features                |

## OIDC group mappings

When OIDC permission synchronization is enabled, Coppice maps the configured
provider groups to these permissions at login. The result is the union of every
matching group's permissions; duplicate permissions are removed and unknown
provider groups are ignored. If no configured group matches, the synchronized
set is empty and clears previously synchronized permissions for non-owner users.

An `admin_group` can grant every available permission, but it never grants the
server-owner flag. The owner status remains a local database property. See the
[OIDC group-to-permission configuration](/docs/guides/access-control/oidc#group-to-permission-synchronization)
section for the environment-variable and TOML forms.
