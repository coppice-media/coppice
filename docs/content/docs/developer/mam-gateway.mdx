---
title: Private MAM gateway
description: The narrow Torznab and qBittorrent sidecar boundary for request fulfillment
---

The optional `mam-gateway` is a separate Rust binary, not another mode of the
Coppice server. It exists to keep tracker credentials and tracker egress out of
Coppice. The gateway owns the MAM cookie/session, talks to MAM through a fixed
allowlisted host/path, and talks to qBittorrent only through loopback. Coppice
receives normalized metadata and opaque handles only.

## Wire contract

The gateway implements the small Torznab surface needed by request search:

- `GET /torznab/api?t=caps` with `Authorization: Bearer ...` advertises `q`
  and `cat` book search. A query `apikey` is accepted only as a legacy
  Torznab compatibility form; Coppice must not put its token in a URL.
- `GET /torznab/api?t=search&q=...&cat=...` with the bearer header returns XML
  rows. Each row contains an opaque, expiring result id; no tracker download
  link is emitted.
- `POST /v1/grabs` with gateway authentication and
  `{ "result_id": "...", "idempotency_key": "..." }` reserves an idempotent
  grab; an optional `Idempotency-Key` header must exactly match the body field.
  The gateway fetches the tracker artifact inside the gateway and uploads bytes
  to qBittorrent with a gateway-owned tag.
- `GET /v1/grabs/{grab_id}` polls by that tag and returns a camelCase
  `{ grabId, resultId, status, failureCode?, failureMessage?, handoff? }`.
  `status:"COMPLETED"` is emitted only after qBittorrent reports completion and
  exactly one canonical regular supported book payload is discoverable under
  `MAM_GATEWAY_HANDOFF_ROOT`; `handoff` contains only a relative path, filename,
  SHA-256, byte size, and media kind.
- `GET /v1/results/{result_id}` returns safe normalized metadata.
- `GET /v1/health` is unauthenticated process liveness only; it is not an
  authentication or upstream-health proof.

A repeated idempotency key returns the original `grabId`; it does not issue a
second qBittorrent add. Handles are random UUID-v4 values represented as 32
hexadecimal characters and expire from the gateway's in-memory cache. A process
restart invalidates them. This sidecar does not create or alter Coppice request
rows, permissions, ingest jobs, or provider-source rows.

## Boundary and threat controls

The client allowlist is intentionally small: `q`, `cat`, `limit`, `offset`, and
`apikey` are the only Torznab query parameters. The client cannot submit a
tracker URL, magnet, cookie, qBittorrent URL, or arbitrary request body. The
tracker URL parsed from a MAM row is checked again before download and must stay
on the configured MAM host family. qBittorrent is validated as an HTTP
loopback endpoint. Reqwest disables redirects; response streams have explicit
body limits and timeouts; upstream 401/403, redirects, oversized bodies,
invalid JSON, timeout, and qBittorrent failures map to stable redacted error
codes.

Cookies, raw tracker URLs, qBittorrent session ids, and upstream response bodies
are gateway runtime state only. They are not serialized into Coppice, returned
in XML/JSON, or included in tracing fields. Secret values should be supplied by
`MAM_COOKIE_FILE` and `MAM_GATEWAY_TOKEN_FILE` (qBittorrent credentials may also
use secret files), with file values taking precedence over environment values.

## Network deployment

Use `services/mam-gateway/deploy/compose.yml` as the reference topology:

```text
Coppice -- private coppice-control --> Gluetun:8088 (mam-gateway)
                                           |
                                           +-- loopback:8080 qBittorrent
                                           +-- VPN egress --> MAM
```

Gluetun joins an external Docker network created with `--internal
coppice-control`. Both gateway and qBittorrent use
`network_mode: service:gluetun`; qBittorrent binds `127.0.0.1:8080`; the
gateway's `/downloads` bind is read-only while qBittorrent is the sole writer,
and Coppice mounts the same completed-download volume read-only at its
configured handoff root. No tracker, qBittorrent, or gateway port is published
on the host. Only the private gateway control port is admitted by the Gluetun
firewall. The VPN kill-switch must fail closed. The gateway image has no
Prowlarr, Jackett, Lodestarr, or other indexer-manager dependency.

## Evidence

The synthetic MAM/qBittorrent fixtures under `services/mam-gateway/tests` are a
focused contract test: they assert cookie-gated tracker fetching, bounded
normalized search output, opaque identifiers, qBittorrent tagging, and
idempotent duplicate behavior. They are **Contract-tested** evidence, not proof
of a live MAM account, VPN routing, or a physical client.
