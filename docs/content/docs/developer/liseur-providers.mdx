This page is an endpoint-level index of the backends the Liseur Android app talks to. It records what the client requests, what it parses, and what it sends back. It is intentionally a protocol inventory rather than a compatibility promise for every implementation of any one protocol.

## Evidence and reading guide

Current source-only review is pinned to released Liseur v0.20.0 [`d8f0304c1c03ecdd0f4ed4ec1daf246f3dfb6d9f`](https://github.com/chmouel/liseur/commit/d8f0304c1c03ecdd0f4ed4ec1daf246f3dfb6d9f) and liseur-sync [`d8000293ffcfa70072a3ce5543cc57e66e0d039b`](https://github.com/chmouel/liseur-sync/commit/d8000293ffcfa70072a3ce5543cc57e66e0d039b). Annotation wire/CAS, token and measured-session contracts remain unchanged. New folder UI uses the existing `next_after` pagination contract; insights are optional and remain unsupported by Coppice. Development Liseur `6c4e4165` was reviewed separately and is not the released pin. The immutable v0.19.0 table below retains its original evidence; the 2026-09-04 device run remains separately pinned to `31f8182d`.

## Shared Liseur boundary

[observed] Liseur v0.19.0 has five selectable server kinds: Calibre-Web (`calibre`), Komga (`komga`), liseur-sync (`liseur-sync`), BookOrbit (`bookorbit`, new in v0.19.0), and user-configured Custom (`custom`). Grimmory is no longer a provider kind, though the client still recognizes the legacy `grimmory:` book-URL prefix. KOReader/KOSync remains a separate peer rather than a catalog kind ([`ServerKind.kt`](https://github.com/chmouel/liseur/blob/62ecb5a5c9dd8eb4e7fa6d97ce50d1bddae0bcd6/app/src/main/kotlin/com/chmouel/liseur/data/remote/ServerKind.kt#L40-L91)). The BookOrbit provider talks BookOrbit's own REST API with a renewable session and CFI-based positions; Coppice does not implement it and is reached from Liseur through the Komga provider or liseur-sync.

| Credential | Wire behavior | Used by |
| --- | --- | --- |
| `Anonymous` | No `Authorization` header. | An open Custom OPDS catalog. |
| `Basic(username, password)` | `Authorization: Basic <base64(username:password)>`. | Calibre-Web OPDS and browser session; password-protected Custom OPDS. |
| `ApiKey(key)` | `X-API-Key: <key>`. | Komga. |
| `Bearer(token)` | `Authorization: Bearer <token>`. | Native liseur-sync after login/token minting. |
| KOReader pairing | `x-auth-user` and lowercase hexadecimal MD5-derived `x-auth-key`; not `RemoteCredentials`. | A KOReader/KOSync peer. |

The first four credential forms are implemented by [`RemoteCredentials`](https://github.com/chmouel/liseur/blob/31f8182d524e3536cf9020594185e709a033094f/app/src/main/kotlin/com/chmouel/liseur/data/remote/RemoteCredentials.kt#L1-L66). The KOReader form is implemented separately by [`KosyncCredentials`](https://github.com/chmouel/liseur/blob/31f8182d524e3536cf9020594185e709a033094f/app/src/main/kotlin/com/chmouel/liseur/data/kosync/KosyncClient.kt#L16-L60).

## Compatibility interpretation (inference)

* [inference] The Komga profile implements Liseur's observed Komga identity, catalog, file, and Readium progression routes; the native liseur-sync profile independently implements the Liseur companion's supported `/v1/*` subset. Neither claim implies full upstream parity or a v0.20.0 physical-client test.
* [inference] The Calibre-Web and Kobo lanes overlap Coppice's OPDS/Kobo families, including current per-book state GET/PUT; Calibre-Web login/token provisioning and exact account semantics differ, so the Calibre-Web pairing remains partial.
* [inference] The native liseur-sync profile implements user-scoped Work/Edition/Alias identity, read-only catalog and book resolution, position ops/changes/snapshots, account settings, measured sessions with linked native projections, managed device tokens, and revisioned annotations with eligible bidirectional native Readium projection. Upload/delete, series order/book claims, insights, token listing/scope updates, and SSE remain unsupported (authenticated 404 for `/v1/events`).
* [inference] OPDS or KOReader percentage sync alone cannot represent Liseur's revisioned locator/annotation semantics; the native `/v1/*` routes and their auth scopes provide those semantics.
* [inference] Grimmory's Komga shim remains a Coppice compatibility surface for older/external clients; it has not been a Liseur server kind since v0.17.0 (`0b44543`). Current source-reviewed Liseur v0.20.0 reaches Coppice through its Komga provider or the native liseur-sync profile, without a new v0.20.0 device run.
