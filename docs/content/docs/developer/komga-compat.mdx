This page is the authoritative specification for Stump's Komga compatibility adapter. It describes the **implemented compatibility profile**, not the full Komga API. The target is the route and DTO profile observed from Komelia **0.19.0**; an endpoint or field not described here is not implied to be supported.

## Scope and evidence

### Current facts

The adapter is a protocol boundary over Stump's existing authenticated library, media, reading-progress, collection, and read-list services. It does not introduce Komga persistence or a second identity system. All route handlers are mounted by [`apps/server/src/routers/komga/mod.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/mod.rs), and DTOs are defined in [`crates/komga/src`](https://github.com/stumpapp/stump/tree/nightly/crates/komga/src).

The compatibility claims in this document have two sources:

- **Source facts:** the linked adapter, middleware, configuration, and contract source files in this repository.
- **Interoperability evidence:** the external **komga-compat harness**, using a sanitized Komelia 0.19.0 capture. The capture establishes the client profile exercised by the adapter; it is not evidence that every Komga client or every Komga endpoint is supported.

### Pinned upstream contracts

The identity and session routes follow the Komga **1.26.3** OpenAPI
document ([`openapi.json`](https://raw.githubusercontent.com/gotson/komga/1.26.3/komga/docs/openapi.json)).
The request and response DTO shapes are corroborated by the pinned
[`komga-client` 0.11.0 commit
`74412a6e`](https://github.com/Snd-R/komga-client/commit/74412a6e27402b90f73672c7452f60a0f05914ca)
and the Komelia client snapshot
[`65f92fde`](https://github.com/Snd-R/Komelia/commit/65f92fde60b7b7b62b85a55ceb80b92adf50eec8).


### Built-in Komf-compatible API

Coppice implements the Komf 2.0.1 HTTP contract consumed by Komelia 0.19.3;
this is a native Rust server adapter, not a separately deployed Komf process.
The contract is pinned to [Komf
`5ad67370c5da6d94372e7c51bff62dd75053ac64`](https://github.com/Snd-R/komf/commit/5ad67370c5da6d94372e7c51bff62dd75053ac64)
and [Komelia
`3c5f501ef24b3acc239302adcab28efe0772c513`](https://github.com/Snd-R/komelia/commit/3c5f501ef24b3acc239302adcab28efe0772c513),
which bundles `komf-client` 2.0.0. `stump_komf` owns the HTTP DTOs and router;
the server adapter uses native metadata providers and Stump metadata storage.

The `komf` Cargo feature is included in `headless` and `full`, but not
`minimal`. Routes mount only when `STUMP_ENABLE_KOMF=true`; the Komga media
server profile must also be enabled with `STUMP_ENABLE_KOMGA=true` for
Komelia's library browsing and reading API.

| Method and path | Contract |
| --- | --- |
| `GET/PATCH /api/config` | Return sanitized Komf-shaped config; provider secrets are `null`. Patch uses native provider settings only. |
| `GET /api/jobs`, `GET /api/jobs/{job_id}`, `GET /api/jobs/{job_id}/events`, `DELETE /api/jobs/all` | List/get owner jobs, stream progress events, or delete that owner's jobs. |
| `GET /api/komga/metadata/providers`, `GET /api/komga/metadata/search`, `GET /api/komga/metadata/series-cover` | List enabled native providers and search/serve their series metadata. |
| `POST /api/komga/metadata/identify` | Start an explicit provider identify job; response is `200` with `jobId`. |
| `POST /api/komga/metadata/match/library/{library_id}` and `POST /api/komga/metadata/match/library/{library_id}/series/{series_id}` | Match a whole visible library (`202`) or one series (`200` with `jobId`). |
| `POST /api/komga/metadata/reset/library/{library_id}` and `POST /api/komga/metadata/reset/library/{library_id}/series/{series_id}` | Reset native metadata and fetch history (`204`). |
| `GET /api/komga/media-server/connected`, `GET /api/komga/media-server/libraries` | Return Komf media-server connection status and device-visible libraries. |

The `apiKey` query lane is accepted only on these Komf routes, and only when
the key resolves to a device-bound credential. An invalid key returns `401`
before session or other authentication fallback. The server request span
redacts the query value; a reverse proxy or browser history may still record
the URL, so treat the complete Komf URL as a secret.

| Operation | Required access |
| --- | --- |
| Providers, search, cover, config GET, jobs list/get/events, media-server status/libraries | Authenticated user/device; library-dependent data uses device `library_scope`. |
| Identify, series/library match, series/library reset, jobs DELETE | `EditMetadata`; new Komelia credentials receive it only through owner opt-in. |
| `PATCH /api/config` | `MetadataProviderManage`, matching native GraphQL provider mutations (`crates/graphql/src/mutation/metadata_provider.rs:28,44,66,87`). Neither download-only nor `EditMetadata` Komelia credentials receive it by default. |

Job records and SSE history are process-local. Provider matching writes through
the native metadata merger and respects field locks; it does not create a
second metadata store or perform acquisition. `removeComicInfo=true` is not
implemented and returns `422` without resetting metadata; the default reset
mode clears Coppice metadata and fetch history without editing archive files.

### Route-collision proof

Komf registers at root `/api/config`, `/api/jobs*`, and `/api/komga/*`. These
paths are disjoint from the simultaneously enabled compatibility routers:

| Router | Mounted route namespace | Why it does not capture the Komf paths |
| --- | --- | --- |
| Native API | `/api/graphql`, `/api/v2` (`apps/server/src/routers/api/mod.rs:9-19`) | No root `/api/config` or `/api/jobs` route is registered. |
| ABS | Many explicit authenticated routes below `/api`, including `/libraries`, `/items`, `/session`, and `/playlists` (`crates/abs/src/routes/mod.rs:394-490`) | The ABS table has no `/config`, `/jobs`, or `/komga` route and no generic `/api/{*path}` fallback. |
| Kavita | Explicit `/api/<Controller>` routes plus selected controller fallbacks (`crates/kavita/src/routes/mod.rs:474-537`) | `route_ci` adds lowercase twins only for registered literals (`:426-452`); neither `Config`, `Jobs`, nor `Komga` has a route or fallback. |
| Komga / Grimmory | Komga `/api/v1` and identity routes; Grimmory is nested under `/komga` (`crates/komga/src/routes/mod.rs:441-459`; `apps/server/src/routers/komga/mod.rs:31-53`) | Komga's fallback starts at `/api/v1`; Grimmory's `/komga/api/...` prefix is distinct from `/api/komga/...`. |
| Other protocols | OPDS `/opds/...`, Kobo `/kobo/...` and `/api/v2/kobo/...`, KOReader `/koreader/...`, Liseur `/v1/...` plus its separate `/api/v2` device route (`apps/server/src/routers/opds_backend.rs:49-76`; `crates/kobo/src/lib.rs:184-230`; `crates/koreader/src/lib.rs:71-88`; `crates/liseur-sync/src/lib.rs:916-976`; `apps/server/src/routers/liseur_sync/touch.rs:30-32`) | Their registered paths do not overlap Komf's root config/jobs or `/api/komga` paths. |

`apps/server/tests/komf/mod.rs::abs_kavita_komga_and_komf_mount_together_without_route_collisions`
builds the complete router with ABS, Kavita, Komga, and Komf enabled and probes
`/api/config`; successful construction and the expected unauthenticated `401`
prove the Komf route is mounted without an Axum/matchit route-build panic.

The checked-in `scripts/contracts/komf-media-server.json` is source-derived
from the pinned Kotlin contract; it is not runtime proof. Server routes,
fixtures, permissions, and SSE are exercised by:

### Historical Komelia 0.19.0 Komga profile client evidence

**Live client verdict (2026-09-03, Komelia 0.19.0 on Android against a headless debug build):** login, library/series/book browsing, filters, reading (CBZ pages and EPUB via Readium), read-progress and mark-read, series/book metadata editing with immediate refresh through the SSE mutation events, collections, and background downloads all worked end to end. Three regressions were found and fixed during that session and are covered by the harness: a stale session cookie triggering Stump's `401` cookie clears and wiping the live session across Komelia's shared cookie jar; `book.url` returning an API path instead of a filesystem-style path, which broke downloaded filenames; and missing `remember-me` support, which left Komelia's background download worker without credentials. Remaining observed gaps at that time were the user-settings screens (`POST /api/logout`, password changes, user management), tracked below.

**Live client verdict (2026-09-04, Komelia 0.19.0 on Android, same build
profile, real commercial EPUBs added to the fixture library):** reading and
offline downloads of both CBZ and EPUB work end to end. Four regressions were
found from the app's error messages and the server log, fixed, and pinned in
the harness; all were specific to real EPUBs (the synthetic fixture EPUB had no
`dc:date`, publisher, or TOC, so the 09-03 session never exercised them):

| Symptom in Komelia | Cause | Fix (pinned by) |
| --- | --- | --- |
| `GET /api/v1/books/{id}/pages` → 500 "Failed to get chapter"; blocks open **and** download | The adapter walked `1..=pagesCount` as EPUB chapters, but Stump's EPUB `pagesCount` is a synthetic position count larger than the spine | EPUB page list is `[]`, Komga's behaviour for non-Divina EPUBs (`apps/server/src/routers/komga_backend.rs` `book_pages`); `replay-readium` asserts it |
| `Unexpected JSON token … $.links[0].rel` | komga-client 0.11 types `WPLink.rel` as `String?`; Stump's Readium generator emits the spec's array form | `normalize_manifest_for_komga_client` in `crates/komga/src/routes/readium.rs` flattens `rel`; harness asserts `isString` |
| `DateTimeParseException '1994-07-14T10:00:00+00:00' … index 10` | `WPMetadata.published` is `LocalDate`; `dc:date` is passed through verbatim | same normalizer truncates to `YYYY-MM-DD`; harness asserts the pattern |
| (latent) `publisher` as string | `WPMetadata.publisher` and the other contributor fields are `List<String>` | same normalizer wraps scalar contributor fields; harness asserts `isCollection` |

Also on that build: an out-of-range single page (`/pages/{n}` past the spine)
and a missing EPUB resource now return `404` instead of `500`
(`FileError::PageNotFound` / `ResourceNotFound`), and every failed response
logs its method and URI so the next client report can be matched to a request.
The native Stump Readium routes are unchanged; only the Komga alias is narrowed
to the pinned client's DTO types.

The current harness/replay evidence covers the route and DTO observations used here, including non-empty read-list and collection responses with seeded ordered membership, collection `PATCH` returning `204` followed by a readback, successful and boundary sibling navigation, and the observed media/auth method behavior. In particular, `GET /api/v1/books/{id}/read-progress` returns `405 Method Not Allowed` because progress reads are provided by the Readium progression route, while `PATCH /api/v1/books/{id}/read-progress` returns `204`; a byte-range request to a page or thumbnail asset served through `cached_bytes` returns `200` without `Content-Range`, whereas the full-file `/api/v1/books/{id}/file` route is served through tower-http `ServeFile` and returns `206 Partial Content` with `Content-Range`; and `POST /api/v1/auth/login` returns `404` by design. Komelia's probe is `HEAD /login`, followed by Basic authentication on the protected route scope.

### Non-goals and proposals

- This is not a claim of complete Komga server compatibility.
- Komga endpoints outside the route matrix below are not part of the current contract.
- Additional event types, unsupported metadata fields, broader search operators, and other endpoints outside this profile require an explicit implementation and compatibility probe before they become supported.

## Enabling the adapter

Two independent gates must both allow the adapter:

1. **Cargo feature:** the server must be compiled with the `komga` feature. In [`apps/server/Cargo.toml`](https://github.com/stumpapp/stump/blob/nightly/apps/server/Cargo.toml), `komga` enables `readium` and the optional `stump_komga` contract crate. The route module itself is compiled only under `#[cfg(feature = "komga")]` in [`apps/server/src/routers/mod.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/mod.rs).
2. **Runtime configuration:** the effective `enable_komga` setting must be `true` (normally set with `STUMP_ENABLE_KOMGA=true`). [`core/src/config/protocols.rs`](https://github.com/stumpapp/stump/blob/nightly/core/src/config/protocols.rs) defines this key (`StumpConfig.protocols.enable_komga`), defaulting to `false` in release configuration and `true` for the debug configuration.

When both gates are open, `routers::mount` merges the Komga router. If `STUMP_ENABLE_KOMGA=true` is used with a binary compiled without the `komga` feature, the server logs a warning and does not mount the Komga route tree; native API routes remain available. This distinction is enforced in [`apps/server/src/routers/mod.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/mod.rs).

## Authentication

The mounted adapter uses the common authenticated context. The top-level Komga router applies [`auth_middleware`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/middleware/auth.rs) once to all protected modules. `HEAD /login` is the sole public route and returns `200 OK`; every other route in the matrix requires an authenticated user.

### Basic-auth path scope

Basic authentication is intentionally narrow. [`is_komga_basic_auth_path`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/middleware/auth.rs) returns true only for:

- any path beginning with `/api/v1/` (or the Grimmory prefix `/komga/api/v1/`);
- exactly `/api/logout`, `/api/v2/users`, `/api/v2/users/me`, `/api/v2/users/me/authentication-activity`, `/api/v2/users/authentication-activity`, or `/api/v2/authors`;
- the Grimmory identity alias `/komga/api/v2/users/me`;
- a path beginning with `/api/v2/users/` and ending with `/authentication-activity/latest`;
- a path beginning with `/api/v2/series/` (or `/komga/api/v2/series/`) and ending with `/read-progress/tachiyomi` — Mihon's built-in Komga tracker sends only Basic or `X-API-Key` on this path ([`KomgaApi.kt:54,91`](https://github.com/mihonapp/mihon/blob/21af65b10012f23e53dba9d01fd2474fcb810f7c/app/src/main/java/eu/kanade/tachiyomi/data/track/komga/KomgaApi.kt#L54)); or
- exactly `/sse/v1/events`.

The latest-activity and tracker rules are the only non-exact `/api/v2` matches. Thus `/api/v1`
(without the trailing slash), `/api/v1x/...`, `/api/v2/users/me/books`,
`/api/v2/users/{id}/authentication-activity/latest/other`,
`/komga/api/v2/users/{id}/authentication-activity/latest`, `/api/graphql`, and
`/sse/v1/events/other` are not Komga Basic-auth paths. Basic credentials on a
Komga path create a Stump session cookie for follow-up requests; OPDS keeps
its separate opt-in session behavior. The logout route deliberately does not
save a new session when a client authenticates with Basic or remember-me
credentials.

When no `Authorization` header is present, `X-API-Key` is considered only on those same Komga-scoped paths. The adapter parses the prefixed key and authenticates it through [`validate_api_key`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/middleware/auth.rs), which requires a matching unexpired key, a server owner or `AccessApiKeys` permission, and a valid long-token hash. The header is not a general-purpose API-key bypass for non-Komga routes. Bearer credentials and Stump session authentication continue to use the common middleware rules.

### Remember-me cookie

The Komga login shape `GET /api/v2/users/me?remember-me=true` issues
`komga-remember-me` only after Basic authentication succeeds. The response
contains both the normal `stump_session` cookie and an opaque
`komga-remember-me` cookie with `Path=/`, `HttpOnly`, `SameSite=Lax`, and
`Max-Age=1209600` (14 days). The lifetime is a code constant matching Komga's
default `komga.remember-me.validity=P14D`; Stump does not currently expose a
separate setting for this compatibility value.

The remember-me value is a fresh random session ID stored as its own row in
the existing `sessions` table with the authenticated user ID and an expiry
of 14 days from issuance. It never reuses or exposes the browser
`stump_session` ID. Existing session expiry cleanup, deletion/revocation, and
`enforce_max_sessions` therefore apply to the token row.

On a Komga Basic-auth path, the middleware considers this cookie only when
there is no session user, `Authorization` header, or `X-API-Key` header. A
present token must resolve to an unexpired session row whose user still
exists and is not deleted or locked. Successful resolution authenticates the
request and saves a fresh short-lived `stump_session`; missing, malformed,
expired, unknown, deleted-user, or locked-user tokens return `401`.

`POST /api/logout` invalidates the current Stump session and, when present,
deletes the `komga-remember-me` session row as well. It returns `204 No
Content` and emits clearing `Set-Cookie` headers for both `stump_session` and
`komga-remember-me` (both use `Path=/`, with `Max-Age=0`; the existing
session cookie also retains `HttpOnly` and `SameSite=Lax`). This is the
intentional logout exception to the normal Komga `401` cookie-clear stripping:
an authenticated logout must clear both client cookies.

On a `401 Unauthorized` response, Stump attaches a session-clearing `Set-Cookie` (`stump_session=; Max-Age=0`) from [`APIErrorResponse`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/errors.rs), and a request that carried a dead session cookie receives a second clear from the tower-sessions layer. Komga never clears the session cookie on a `401`, and Komga clients such as Komelia run several HTTP clients (REST, SSE, image loading) over one shared cookie jar, so a stale cookie on one client would otherwise wipe the live session of the others. [`strip_komga_unauthorized_cookie_clears`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/middleware/auth.rs), layered outside the session layer in `http_server.rs`, removes only those `stump_session` clears from `401` responses on the Komga-scoped paths above; fresh session cookies and other cookies pass through, and every non-Komga path keeps the clearing behavior. The harness spec `session-cookie-scope.hurl` covers stale-cookie isolation and the remember-me exchange.

## Grimmory shim

Stump also exposes the Grimmory Komga-shaped profile below `/komga`. This is a
prefix alias over the same authenticated Komga book, media, and identity
handlers; it does not add a second database or identity store. The route shape
matches Grimmory main [`65f92fde`](https://github.com/grimmory-tools/grimmory/commit/65f92fde)
and its `KomgaController`
(`backend/src/main/java/org/booklore/controller/KomgaController.java:45-46`):

| Method | Path | Contract |
| --- | --- | --- |
| `GET` | `/komga/api/v2/users/me` | Basic-authenticated Komga user projection. |
| `GET` | `/komga/api/v1/books` | Grimmory listing profile; accepts `page` and `size` query parameters and returns the Komga `Page` envelope. |
| `GET` | `/komga/api/v1/books/{id}/file` | Basic-authenticated book-file download. |
| `GET` | `/komga/api/v1/books/{id}/thumbnail` | Basic-authenticated book thumbnail (the catalog-derived cover URL). |

The listing route is intentionally `GET /api/v1/books`, rather than Komga's
`POST /api/v1/books/list`, matching Grimmory's controller
(`backend/src/main/java/org/booklore/controller/KomgaController.java:146-155`).
Liseur's Grimmory catalog requests `GET /api/v1/books?page=&size=200`, filters
locally on `media.mediaType == application/epub+zip`, and derives thumbnail and
file links under `/komga/api/v1/books/{id}/...`
(`app/src/main/kotlin/com/chmouel/liseur/data/grimmory/GrimmoryCatalogClient.kt:34-64,364-419`;
`app/src/main/kotlin/com/chmouel/liseur/data/grimmory/GrimmoryFileSource.kt:17-29`).
Its setup probe is `GET /komga/api/v2/users/me` with an OPDS user's Basic
credentials, and the client treats an authenticated account as download-capable
(`app/src/main/kotlin/com/chmouel/liseur/data/grimmory/GrimmorySetupClient.kt:28-49,144-175`).

The shim accepts the same Basic-auth middleware as the ordinary Komga profile,
but only under the `/komga/api/v1/` and `/komga/api/v2/` prefixes. Grimmory's
identity response is Komga-shaped; no Grimmory-specific persistence is created.

### Library, book, and series metadata behavior

Metadata PATCH bodies use the three-state `PatchValue` form: omitted means unchanged, `null` clears a nullable value, and a value replaces it. Series patches persist `status`, `title`, `titleSort`, `summary`, `publisher`, `readingDirection`, `language`, `alternateTitles`, `ageRating`, `genres`, `tags`, `totalBookCount`, and `links`, plus their supported lock fields. For `titleSort`, a `null` value clears the stored override and GET responses fall back to the series title; `readingDirection` stores the Komga enum name and `language` stores the supplied BCP-47 tag. `alternateTitles` is stored as a JSON array of `{label,title}` objects. A `null` lock value clears the lock (`false`), while a boolean sets it. `sharingLabels` and `sharingLabelsLock` have no Stump equivalent; if either is present (including `null`), the request returns `400`.
Book patches persist `title`, `summary`, decimal `number`, `releaseDate`, `authors`, `tags`, `isbn`, and `links`, plus their supported lock fields. Authors are mapped to Stump's CSV columns only for the seven roles `writer`, `penciller`, `inker`, `colorist`, `letterer`, `cover` (Komga's name for the cover artist; `cover_artist` is accepted as an alias), and `editor`; roles are case-insensitive, names are trimmed and de-duplicated, and an empty name or any other role returns `400`. `numberSort` is derived from `number`: it cannot be cleared independently, and a supplied value must equal the finite numeric value derived from the patched number (or the existing number when `number` is omitted), otherwise the request returns `400`. Fields outside this DTO are not applied by the serde update mapping.

`tags` replaces the existing relation (with duplicate names removed); `links`, genres, and other legacy multi-value metadata use Stump's comma-separated columns, while `alternateTitles` uses its JSON column. Metadata writes and management jobs do not fabricate persistence for unsupported Komga settings.

Sources: [`library.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/library.rs), [`book.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/book.rs), [`series.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/series.rs), and [`settings.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/settings.rs).
For Tachiyomi progress, the adapter counts only the authenticated user's
latest reading session for each visible, non-deleted book. `FINISHED` is read;
any other existing session is in progress; no session is unread. The series
continuous prefix sorts by finite metadata number and stops at the first unread
or in-progress book; it reports `0` when the prefix is empty. Books with missing
numbers receive a stable 1-based visible-order number for this tracker route;
`maxNumberSort` still falls back to the visible book count when any source
number is missing. Writes use the existing `upsert_reading_session` path, so
normal progress events are emitted. This ordinal treatment of missing numbers
is a deliberate compatibility deviation: it makes the fixture's unnumbered
books trackable without inventing persisted metadata. The wire contract follows
Mihon's pinned [`KomgaApi.kt` and
`KomgaModels.kt`](https://github.com/mihonapp/mihon/tree/21af65b10012f23e53dba9d01fd2474fcb810f7c/app/src/main/java/eu/kanade/tachiyomi/data/track/komga).

## Search-condition profile

The JSON search DTOs are defined in [`crates/komga/src/search.rs`](https://github.com/stumpapp/stump/blob/nightly/crates/komga/src/search.rs). For `POST /api/v1/books/list` and `POST /api/v1/series/list`, the adapter recursively evaluates these condition forms:

- `AllOfBook` / `AllOfSeries`: all nested conditions are combined with logical AND.
- `AnyOfBook` / `AnyOfSeries`: nested conditions are combined with logical OR.
- Book `LibraryId` with `operator: { "is": ... }`.
- Book `SeriesId` with `operator: { "is": ... }`.
- Book `MediaStatus` with `operator: { "is": ... }`: `READY`, `UNKNOWN` (Stump `UNKNOWN`), `ERROR`, and `UNSUPPORTED` map to Stump file statuses. `OUTDATED` is intentionally always false, so it matches no books. Stump `MISSING` is not reachable through this filter: a book the scanner could not find on disk — including every book of a series whose folder disappeared — is dropped from `POST /api/v1/books/list`, legacy `GET /api/v1/books`, and `GET /api/v1/series/{id}/books` unless `deleted=true` is requested, because upstream Komga marks such a book deleted and hides it rather than serving an entry that 404s on read. The single-book routes (`GET /api/v1/books/{id}`, pages, file) still answer for it, and it still maps to `UNKNOWN` where a DTO carries its status.
- Book `ReleaseDate` with `operator: { "isInTheLast": ... }`.
- Series `LibraryId` with `operator: { "is": ... }`.
- Series `Language` with `operator: { "is": ... }`; matching is case-insensitive against the language stored on a book's metadata and then projects the matching series.

The `allOf` and `anyOf` arrays default to empty when their keys are omitted. This matches the pinned Komelia client payload shape and is part of the deserialization contract; it does not expand the set of supported leaf conditions.

Every other condition variant or operator returns `400 Bad Request` through the adapter's unsupported-filter error. Before returning that error, the adapter writes a warning whose `condition` field contains the rejected condition serialized as JSON. Unsupported filters are not accepted as if they had been applied. `fullTextSearch` is a separate supported search field; book full-text search covers book, book-metadata, series, and series-metadata text columns, while series full-text search covers series name, title, summary, and writers. The condition allowlist and full-text behavior are implemented in [`catalog.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/catalog.rs).

## Pagination contract

Catalog feeds, book/series list requests, author results, list endpoints, and authentication-activity results use a Komga/Spring-style `Page<T>` envelope from [`crates/komga/src/common.rs`](https://github.com/stumpapp/stump/blob/nightly/crates/komga/src/common.rs). The envelope contains `content`, `pageable`, `totalElements`, `totalPages`, `last`, `number`, `sort`, `first`, `numberOfElements`, `size`, and `empty`. The two by-parent endpoints (`/books/{id}/readlists` and `/series/{id}/collections`) are the deliberate plain-array exceptions.

- `page` is zero-based and must be non-negative.
- `size` is non-negative and defaults to `20`; values above **200** are clamped to `200`. Catalog and authentication-activity pagination warn when clamping; list pagination clamps without that warning.
- `size=0` is a count-only request on paged endpoints: content is empty while `totalElements` remains populated (and `totalPages` is `1` when the total is non-zero).
- `unpaged=true` is accepted. An unpaged response reports page number and offset as zero, uses the content length as its page size, and reports zero or one total pages depending on whether content is empty.
- For paged requests, the SQL offset is `page * size` and the response preserves the requested page and size.

For book and series list/feed endpoints, sort expressions are `field` or `field,direction`, with `asc` or `desc` direction. The six supported book-list keys are `lastModified`, `createdDate`, `metadata.titleSort`, `metadata.numberSort`, `metadata.releaseDate`, and `readProgress.readDate`. Series list/feed sorting supports `lastModified`, `createdDate`, and `metadata.titleSort`. Unknown fields, malformed expressions, and invalid directions are warned about and fall back to the endpoint's default order; they do not return `400`. The on-deck feed additionally accepts its observed aliases for created date (`created`, `createdAt`, `created_at`), last modified (`lastModified`, `lastModifiedDate`, `last_modified`), and title/name (`name`, `title`, `metadata.title`, `relevance`), with unknown values also using the default order.

Read-list and collection sorting is stricter: the supported keys are `name`,
`createdDate`, and `lastModifiedDate`; unsupported or malformed expressions
return `400` instead of silently falling back.

The validation and envelope construction are implemented in [`catalog.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/catalog.rs), [`lists.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/lists.rs), [`settings.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/settings.rs), and [`common.rs`](https://github.com/stumpapp/stump/blob/nightly/crates/komga/src/common.rs).

## DTO mapping and intentional losses

### Identity and IDs

Book, series, library, collection, and read-list IDs are the underlying Stump IDs wrapped in typed Komga newtypes; they are not regenerated Komga IDs. Komga's `book.url` and `series.url` are filesystem paths, and Komelia derives a downloaded book's local filename (and therefore its format) from the last segment of `book.url`. Stump never exposes real library paths to users, so the mapper emits a virtual path made only of the series directory name and the file name (`/<series dir>/<file.cbz>` for books, `/<series dir>` for series), with the `virtual_book_url`/`virtual_series_url` helpers in `mapper.rs`. Thumbnail IDs are deterministic adapter IDs:

- book thumbnail: `stump-book-<book-id>`;
- series thumbnail: `stump-series-<series-id>`.

The media handler accepts only the corresponding generated ID for each book or series. These rules are implemented by [`mapper.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/mapper.rs), [`media.rs`](https://github.com/stumpapp/stump/blob/nightly/apps/server/src/routers/komga/media.rs), [`collection.rs`](https://github.com/stumpapp/stump/blob/nightly/crates/komga/src/collection.rs), and [`read_list.rs`](https://github.com/stumpapp/stump/blob/nightly/crates/komga/src/read_list.rs).

### Mapped fields and losses

The following are current mapping decisions, not compatibility proposals:

- `series.metadata.titleSort` is emitted from the persisted sort-title override, falling back to the series title when it is unset.
- Series-level `metadata.readingDirection` and `metadata.language` are emitted from their persisted values, or `""` when unset because Komga declares both fields as non-null strings. Series language conditions still search book metadata and project matching series.
- Book, series, and representative-book summaries are converted from source HTML to plain text only when building Komga DTOs. The persisted source metadata remains unchanged. This matches Komga's EPUB provider and avoids exposing literal OPF `<p>`/`<br>` tags in Komelia, whose `ExpandableText` renders the value as plain Compose text.
- `metadata.alternateTitles` is emitted from the persisted JSON array, or `[]` when unset; its lock and the reading-direction/language/title-sort locks are emitted from their dedicated persisted booleans.
- `metadata.sharingLabels` remains empty and its lock remains false because Stump has no sharing-label model.
- `scanInterval` is always `DISABLED`; Stump's watcher boolean is not converted into a fictional periodic interval.
- Page metadata uses synthetic `page-N` file names because archive entry names are not persisted in the mapped row.
- The separate admin-only `/api/v1/transient-books` scan/analyze lifecycle is not implemented. Persisted book page images already support conditional private caching, but that is not a substitute for Komga's transient repository and one-hour lifecycle.
- The Komga catalog exposes only formats Komga readers can represent: EPUB, PDF, CBZ/CBR, and ZIP/RAR. Audiobook rows remain available through Coppice's native surfaces but are excluded from Komga book/series/list queries and direct media routes; Komga has no audio media profile, and `mediaProfile: null` with zero pages causes duplicate cards and a white-screen reader failure in Komelia.
- PDF books require a loadable PDFium shared library through `PDFIUM_PATH` when the server starts. A failed PDFium initialization is cached for the process lifetime, so provisioning the library requires a server restart before `/books/{id}/pages` can render.
- Each book lists its deterministic `GENERATED` thumbnail (`stump-book-{id}`) and, when a cover was uploaded, a `USER_UPLOADED` one (`stump-upload-book-{id}`) marked `selected`. Series lists contain only the uploaded cover (`stump-upload-series-{id}`, `USER_UPLOADED`) or are empty: Komga's `ThumbnailSeries.Type` is only `SIDECAR | USER_UPLOADED` and Komelia decodes it with an unguarded `valueOf`, so a `GENERATED` series entry must never be emitted; generated series covers are served solely through `/series/{id}/thumbnail`. `POST /{books,series}/{id}/thumbnails` (multipart `file` + `selected`) stores the cover through the same helper as the GraphQL upload mutations and returns the full thumbnail DTO; `DELETE .../thumbnails/{tid}` removes an uploaded cover (`204`) and answers `400` for a generated id, as Komga does. See `crates/komga/src/routes/media.rs` and the Komf study for the client sequence.
- Library fields without Stump equivalents use neutral values from [`mapper.rs`](https://github.com/stumpapp/stump/blob/nightly/crates/komga/src/routes/mapper.rs), including disabled scan/conversion/import switches where no persisted Stump setting exists.
- Book metadata is projected from Stump metadata when present, with the media name as the title fallback; series aggregates derive counts, tags, and representative book metadata from visible books.

## Replay observations and diagnostics

The replay observations above are compatibility evidence, not new routes. They are included because clients depend on the negative space as well as successful responses:

- `GET /api/v1/books/{id}/read-progress` is not mounted and therefore returns `405`; use the Readium progression GET route when a progression read is needed.
- `PATCH /api/v1/books/{id}/read-progress` returns `204` on a valid update.
- A Range request to a page or thumbnail asset served through `cached_bytes` returns `200` without `Content-Range`; this is the observed behavior for those cached asset endpoints, not a promise of byte-range semantics. The full-file download at `/api/v1/books/{id}/file` is served through tower-http `ServeFile` and honors Range, returning `206 Partial Content` with `Content-Range`.
- `POST /api/v1/auth/login` returns `404`; login discovery is `HEAD /login`, and credentials are sent through the common Basic-auth path scope.

The Komga router also mounts a scoped `ANY /api/v1/{*path}` fallback. Any unmatched request under `/api/v1/` that reaches this wildcard, including an unsupported method, is warned with its HTTP method and URI (`Unmatched Komga-profile route`) and returns `404`. This route-scoped handler does not affect the browser apps mounted at `/app` and `/editor`. Unsupported search conditions are separately warned with the rejected condition serialized as a JSON log field before the `400` response.

The external **komga-compat harness** and its sanitized Komelia 0.19.0 capture/replay provide the interoperability evidence. Harness specifications are referred to by filename only, including `management-pending.hurl`; their machine paths are not part of this contract. They do not turn unlisted methods into supported endpoints.


## Compatibility boundary

A client may rely on the route paths, authentication scope, pagination rules, search allowlist, progress numbering distinction, Readium aliases, generated thumbnail IDs, virtual `url` paths, the library DTO field mapping, and the SSE event set specified here. It must not rely on unlisted Komga routes, unsupported search operators, persisted sharing-label data, archive-entry filenames, `GET` echoing the ignored library fields, real filesystem paths, or event types that the adapter deliberately ignores.
