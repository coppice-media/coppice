## Lifecycle, profiles, operations

- **Lazy lifecycle.** `Ctx` owns config, connection and events only; the job
  runtime appears on first enqueue, the watcher only when needed, the scheduler
  only for enabled rows; the server stops only what it created.
  `/api/v2/health` reports `jobs`, `watcher` and `rate_limit`
  (`core/src/context.rs`, `apps/server/src/http_server.rs`).
- **Profiles.** `full` (default) = `headless` + `webui`; `headless` carries every
  backend route feature (`formats`, `graphql`, `opds`, `readium`, `kobo`,
  `koreader`, `komga`, `kavita`, `abs`, `liseur-sync`, `providers`, `watcher`,
  `qr`, `ingest`, `apalis`); `minimal` keeps REST/auth/database and links neither
  `async-graphql`, `notify` nor `apalis` (`apps/server/Cargo.toml:7-51`).
- **Inbound rate limiting.** Implemented as one outer layer with `auth`, `write`
  and `stream` classes keyed on a credential fingerprint, `429` + `Retry-After`,
  and counters on `/api/v2/health`
  ([Server architecture › inbound rate limiting](/docs/developer/server-architecture#inbound-rate-limiting)).
- **Writes.** Every write transaction goes through `models::txn::begin_write`
  (SQLite `BEGIN IMMEDIATE`); migrations run on a dedicated one-connection pool
  because `sea-orm-migration` does not transact SQLite DDL.
- **Idle RSS.** Optimized headless vs pristine nightly: 29,924 vs 40,776 KiB,
  5 vs 21 threads
  ([measurement gates](/docs/developer/server-architecture#measurement-gates)).

## Known limitations

- **ABS socket.io.** The Engine.IO v4 / Socket.IO v5 lane is not in this commit;
  the protocol is analysed in `docs/audiobook-study.md` §2 and the crate says so
  (`crates/abs/README.md:12`). The official ABS app needs it for bookmarks, so
  "ABS-compatible" means Lissen-shaped REST at `7de64602`. Implementation is in
  flight ([Roadmap › Open](/docs/developer/roadmap#open), item 4).
- **No live keys** for Hardcover, Metron, Open Library or Google Books: those
  mappers are unit-tested against recorded payloads, never against the vendor.
- **Cover pick is decided but not written** — `HIGHEST_RESOLUTION` ranks
  candidates, yet `CoverUrl` is outside `STORABLE_FIELDS`, so the decision comes
  back `applied: false`. Title-language preference is still fixed per provider
  ([policy table](/docs/developer/provider-status#what-the-policy-layer-covers)).
- **Komga is a target profile, not parity**: no persisted settings, no
  sidecar/artwork CRUD, narrower search operators; the filesystem browser is
  partial and owner-only (`crates/komga/src/routes/media.rs`).
- **Kobo**: device tokens are dummy and non-persistent; tags/archive and other
  advertised routes remain catch-all no-ops.
- **liseur-sync**: retention/compaction, insights, token administration,
  upload/delete and series claims are deferred, and only the device `sync` scope
  is enforced (`crates/liseur-sync/src/lib.rs:1025-1043`).
- **Calibre-Web facade for Liseur** is absent — no `/opds/...` web-form
  contract, no Calibre-Web login/token/delete lane
  ([Liseur providers](/docs/developer/liseur-providers)).
- **CBZ has no KOReader hash**: the branch is commented out
  (`crates/media/src/media/format/zip.rs:61,68-75`), so fixture sync needs
  `generate_koreader_hashes` on a hashable format first.
- **Modular extraction is partial**: core still links PDFium, unrar, apalis and
  notify unconditionally; there are no processor-sized Cargo features.
- **Operations**: no metrics endpoint, no backup/restore surface, and
  `.github/workflows/ci.yaml` still has no profile matrix.
- Known upstream lints untouched: `emailer/sender.rs` and
  `tests/reading_progress/manual_progression_changes.rs` (`useless vec!`).
