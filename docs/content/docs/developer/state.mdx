# Current State

This page records the current Coppice integration worktree after the nightly
merge. Every claim names a path, symbol, or document; nothing here is a promise.
The labels are exact: **Shipped**, **Contract-tested**, **Device-tested**,
**Source-only**, **Planned**, and **Blocked**. A replay or source inspection
never becomes app/device proof. Details are defined in [Client
verification](/docs/developer/client-verification), and ownership boundaries
are defined in [Integration architecture](/docs/developer/integration-architecture).
The gate and replay commands live in `.omp/PROJECT_STATE.md`. The one-table view
of crates → features → profiles → clients is [Server architecture › Architecture
map](/docs/developer/server-architecture#architecture-map).

enqueue, cache-path, and result-validation paths are in
`crates/library/src/sync_maps.rs`; GraphQL exposes `Media.pairedPosition`,
`importSyncMap`, and `enqueueAlignment`. The generic remote-worker protocol,
durable `worker_jobs`, and transcode/challenge runners also ship.

`crates/worker/src/alignment.rs` supplies the typed alignment input, capability,
`SyncMapV1`, identity check, and duration-aware validation contracts. The
authenticated handlers in `apps/server/src/routers/api/v2/read_aloud.rs` are
cache-only: they serve an accepted EPUB derivative and never enqueue alignment,
call Storyteller, or render a fallback during a GET. Native CTC/Viterbi
alignment, full synchronized playback, a user-facing synchronized-playback UI,
and deployment/device evidence remain **Planned** or **Pending**. Ordinary EPUB
playback and ordinary audiobook playback remain separate.

The request backend/provider ledger is covered below. Its shipped server
surface does not imply live MAM deployment, physical delivery, or complete
read-aloud product playback.

## Request ledger and acquisition boundary

The metadata-backed request ledger, GraphQL create/list/detail and
approve/reject operations, Home request UI, permissions, per-user visibility,
notifications, and social handoff are **Shipped**.

```text
Universal-style metadata search or recommendation
  -> request metadata + optional destination intent
  -> permission and visibility checks
  -> operator approval or rejection
  -> notifications and audit history
```

Approval does not acquire a file or enqueue ingest. MAM acquisition is deferred;
Coppice ships no release search/selection, grab, polling, retry, downloader, or
gateway settings. If acquisition is added later, it must run as a separate
authenticated provider sidecar that owns provider credentials and transport
state. This is an architecture boundary, not an implementation or delivery
promise.

## Lifecycle, profiles, and operations

- **Lazy lifecycle — Shipped.** `Ctx` owns config, connection, and events only;
  the job runtime appears on first enqueue, the watcher only when needed, the
  scheduler only for enabled rows; the server stops only what it created.
  `/api/v2/health` reports `jobs`, `watcher`, and `rate_limit`
  (`core/src/context.rs`, `apps/server/src/http_server.rs`).
- **Profiles — Shipped:** `full` (default) = `headless` + `webui`;
  `headless` carries every backend route feature (`formats`, `graphql`, `opds`,
  `readium`, `kobo`, `koreader`, `komga`, `kavita`, `abs`, `liseur-sync`,
  `providers`, `watcher`, `qr`, `ingest`, `apalis`). `minimal=["formats"]`.
  The bare `--no-default-features` server is leaner than `minimal`; it keeps the
  base REST/auth/database without the `formats` bundle. The WebUI feature is
  `webui=["graphql", "graphql/web"]`, so WebUI implies GraphQL.
- **KOReader-only composition — Shipped:** compile with
  `cargo run -p stump_server --no-default-features --features koreader` and set
  `ENABLE_KOREADER_SYNC=true`. No WebUI, GraphQL, provider host, ingest, or
  other protocol feature is implied by this composition.
- **Inbound rate limiting — Shipped.** One outer layer with `auth`, `write`, and
  `stream` classes keyed on a credential fingerprint, `429` + `Retry-After`, and
  counters on `/api/v2/health` ([Server architecture › inbound rate limiting](/docs/developer/server-architecture#inbound-rate-limiting)).
- **Writes — Shipped.** Every write transaction goes through
  `models::txn::begin_write` (SQLite `BEGIN IMMEDIATE`); migrations run on a
  dedicated one-connection pool because `sea-orm-migration` does not transact
  SQLite DDL.
- **Idle RSS — Source-only historical measurement.** Optimized headless vs
  pristine nightly: 29,924 vs 40,776 KiB, 5 vs 21 threads
  ([measurement gates](/docs/developer/server-architecture#measurement-gates)).

## Known limitations

- **ABS socket.io.** The Engine.IO v4 / Socket.IO v5 lane is implemented by `crates/abs/src/socket/mod.rs` and `crates/abs/src/socket/protocol.rs`; `apps/server/src/routers/abs_backend.rs::compose` mounts it alongside the REST router. `crates/abs/src/socket/tests.rs` covers authenticated websocket frames. The official ABS app's scoped run does not establish complete parity, so broader official-client/device verification remains **Pending** ([ABS compatibility](/docs/developer/abs-compat)).
- **No live keys** for Hardcover, Metron, Open Library, or Google Books: those
  mappers are **Contract-tested** against recorded payloads, never against the
  vendor. Hardcover account/progress/journal sync is **Planned** and **Blocked**.
- **Cover pick is decided but not written** — `HIGHEST_RESOLUTION` ranks
  candidates, yet `CoverUrl` is outside `STORABLE_FIELDS`, so the decision comes
  back `applied: false`. Title-language preference is still fixed per provider
  ([policy table](/docs/developer/provider-status#what-the-policy-layer-covers)).
- **Komga is a target profile, not parity:** no persisted settings, no
  sidecar/artwork CRUD, narrower search operators; the filesystem browser is
  partial and owner-only (`crates/komga/src/routes/media.rs`).
- **Kobo:** device tokens are dummy and non-persistent; tags/archive and other
  advertised routes remain catch-all no-ops.
- **liseur-sync:** retention/compaction, insights, token administration,
  upload/delete, and series claims are **Planned**, and only the device `sync`
  scope is enforced (`crates/liseur-sync/src/lib.rs:1025-1043`).
- **Calibre-Web facade for Liseur** is absent — no `/opds/...` web-form
  contract, no Calibre-Web login/token/delete lane ([Liseur providers](/docs/developer/liseur-providers)).
- **CBZ has no KOReader hash:** the branch is commented out
  (`crates/media/src/media/format/zip.rs:61,68-75`), so fixture sync needs
  `generate_koreader_hashes` on a hashable format first.
- **Modular extraction is partial and honest:** core still links PDFium, unrar,
  apalis, and notify unconditionally; there are no processor-sized Cargo
  features.
- **Operations:** no metrics endpoint, no backup/restore surface, and
  `.github/workflows/ci.yaml` still has no profile matrix.
- Known upstream lints are untouched: `emailer/sender.rs` and
  `tests/reading_progress/manual_progression_changes.rs` (`useless vec!`).
