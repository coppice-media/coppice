## Lifecycle and profiles

- Lazy lifecycle: `Ctx` owns config/conn/events only; `JobRuntime` on first
  enqueue, watcher only when needed, scheduler only for enabled scheduled-job
  rows; server stops only what it created. `/api/v2/health` reports `jobs`
  (disabled/enabled/idle/running) and `watcher` (disabled/inactive/active).
  Verified live on the fixture (`core/src/context.rs`,
  `apps/server/src/http_server.rs`).
- Idle RSS: the lifecycle change itself is noise (62→66 MB debug, 19 threads,
  same fixture copy); the structural win is lazy construction. Measured idle
  RSS for optimized headless vs pristine nightly: 29,924 vs 40,776 KiB RSS,
  5 vs 21 threads ([Server Architecture](/docs/developer/server-architecture)).
- Profiles: `full` (default), `headless` (all backend routes, no SPA), `minimal`
  (REST/auth/database only). Headless dependency count 779 with formats, 770
  without. See [Server Architecture](/docs/developer/server-architecture).

## Known limitations

From the feature-gap analysis (`local://feature-gaps.md` in session storage;
rows reproduced honestly here):

- Komga is a target-profile subset, not full API parity: no persisted settings,
  no sidecar/artwork CRUD, narrower search operators/events
  ([Komga Compatibility](/docs/developer/komga-compat)). Collection creation is
  not mounted: `crates/komga/src/routes/lists.rs` has GET routes and a PATCH,
  but no POST. The Komga filesystem browser is partial and owner-only
  (`crates/komga/src/routes/media.rs`).
- Kobo: device tokens are dummy/non-persistent; tags/archive and other
  advertised routes remain catch-all no-ops; no physical Kobo device
  verification ([Kobo Sync Capabilities](/docs/developer/kobo-sync-capabilities)).
- liseur-sync: local `media_annotations`/`bookmarks` projection, retention and
  compaction, insights, token administration, upload/delete, and series claims
  deferred ([liseur-sync Integration](/docs/developer/liseur-sync-integration)).
- Calibre-Web facade for Liseur: missing — no `/opds/...` web-form contract, no
  Calibre-Web login/token/delete facade
  ([Liseur Providers](/docs/developer/liseur-providers)).
- OPDS: strict facets, v2 path-key auth nuances, and EPUB chapter/resource
  streaming gaps ([Server Architecture](/docs/developer/server-architecture)).
- Modular extraction is partial: core still unconditionally links jobs, watcher,
  and processor dependencies; no processor-sized Cargo features (`pdf-render`,
  watcher, jobs, metadata, email) ([Server Architecture](/docs/developer/server-architecture)).
- KOReader hash: the CBZ processor returns no KOReader hash — the branch is
  commented out in `core/src/filesystem/media/format/zip.rs`; fixture sync
  requires `generate_koreader_hashes` first.
- Operations: no inbound API rate limiting, no metrics, no backup/restore,
  health/readiness is partial, CI lacks a profile matrix
  (`local://feature-gaps.md` §3).
- Highlights/notes as a durable cross-device capability: partial — native and
  liseur CAS storage exist, canonical heads and reconciliation are design/deferred
  ([Unified Reading State](/docs/developer/unified-reading-state)).
- Known upstream lints untouched: `emailer/sender.rs` and
  `tests/reading_progress/manual_progression_changes.rs` (`useless vec!`).
- In-flight: worker `LiseurCatalog` is implementing liseur catalog routes and
  the `/v1/works/{id}/annotations` SQL fix against the pinned Liseur client.
