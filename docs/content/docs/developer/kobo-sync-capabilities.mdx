This page separates three things that are easy to conflate: the Kobo HTTP protocol, the `KoboReader.sqlite` database on a device, and Coppice's current adapter. Statements marked **[observed]** describe pinned external source snapshots; they are references, not a current-source status. Statements marked **[inference]** are recommendations drawn from those observations. Current Coppice behavior and client/device evidence are stated separately below and in the [client verification matrix](/docs/developer/client-verification).

### Library sync and headers

**[observed]** `GET /v1/library/sync` consumes the `x-kobo-synctoken` request header. A local page can contain `NewEntitlement` items, `ChangedEntitlement` items, and `ChangedReadingState` items; shelf changes are added as tag items. The response carries a new sync token in headers. When more local results remain, Calibre-Web sets `x-kobo-sync: continue`; when proxying the official store, it also preserves the store's sync-mode and recent-read headers and merges the store response into the local response (`cps/kobo.py:143-224@a97826402f1b39c45b7ea8d906efddc9f1750934`, `cps/kobo.py:264-332@a97826402f1b39c45b7ea8d906efddc9f1750934`).

**[observed]** Calibre-Web's local format map is exactly `{"KEPUB": ["KEPUB"], "EPUB": ["EPUB3", "EPUB"]}`. When a KEPUB is unavailable but conversion is configured, delivery can queue EPUB-to-KEPUB conversion (`cps/kobo.py:55-57@a97826402f1b39c45b7ea8d906efddc9f1750934`, `cps/kobo.py:207-224@a97826402f1b39c45b7ea8d906efddc9f1750934`).

### ReadingState GET and PUT

**[observed]** `GET /v1/library/<book_uuid>/state` returns a one-element JSON array. The element contains `EntitlementId`, timestamps, `StatusInfo`, `Statistics`, and `CurrentBookmark` (`cps/kobo.py:758-819@a97826402f1b39c45b7ea8d906efddc9f1750934`, `cps/kobo.py:857-913@a97826402f1b39c45b7ea8d906efddc9f1750934`).

The wire shape can be summarized as:

```json
[
  {
    "EntitlementId": "book-uuid",
    "Created": "timestamp",
    "LastModified": "timestamp",
    "PriorityTimestamp": "timestamp",
    "StatusInfo": {
      "LastModified": "timestamp",
      "Status": "ReadyToRead | Reading | Finished",
      "TimesStartedReading": 0,
      "LastTimeStartedReading": "timestamp"
    },
    "Statistics": {
      "LastModified": "timestamp",
      "SpentReadingMinutes": 0,
      "RemainingTimeMinutes": 0
    },
    "CurrentBookmark": {
      "LastModified": "timestamp",
      "ProgressPercent": 0,
      "ContentSourceProgressPercent": 0,
      "Location": {
        "Value": "opaque value",
        "Type": "KoboSpan",
        "Source": "resource href"
      }
    }
  }
]
```

PUT request:

```json
{
  "ReadingStates": [
    {
      "CurrentBookmark": { "...": "fields above" },
      "Statistics": { "...": "fields above" },
      "StatusInfo": { "...": "fields above" }
    }
  ]
}
```

`LastTimeStartedReading` and the numeric fields shown as optional are emitted only when the corresponding local values exist; the handler's accepted input and response update results are the contract (`cps/kobo.py:758-819@a97826402f1b39c45b7ea8d906efddc9f1750934`, `cps/kobo.py:857-913@a97826402f1b39c45b7ea8d906efddc9f1750934`).

**[observed]** `PUT /v1/library/<book_uuid>/state` reads `ReadingStates[0]` and handles only these structured fields:

- `CurrentBookmark`: `ProgressPercent`, `ContentSourceProgressPercent`, and, when present, `Location.Value`, `Location.Type`, and `Location.Source`.
- `Statistics`: `SpentReadingMinutes` and `RemainingTimeMinutes`.
- `StatusInfo`: `Status` and `TimesStartedReading` (the handler updates the local reading status and increments the start counter when entering `Reading`).

It returns `RequestResult: Success`, an `UpdateResults` array, and last/priority timestamps (`cps/kobo.py:758-819@a97826402f1b39c45b7ea8d906efddc9f1750934`). The `CurrentBookmark` JSON object is not the same thing as the KoboReader.sqlite `Bookmark` table: this HTTP handler does not parse `Text`, `Annotation`, or an annotation collection (`cps/kobo.py:758-819@a97826402f1b39c45b7ea8d906efddc9f1750934`).

### Shelves as tags

**[observed]** Calibre-Web models Kobo shelves as its local shelf records and exposes them as Kobo tags. `POST /v1/library/tags` accepts `Name` and `Items`; members are keyed by `RevisionId` and `Type: ProductRevisionTagItem`. The item add/remove routes accept an `Items` collection, and sync emits `NewTag`, `ChangedTag`, and `DeletedTag` records (`cps/kobo.py:506-757@a97826402f1b39c45b7ea8d906efddc9f1750934`).

### Proxy, redirect, and fallback behavior

**[observed]** With proxying enabled, Calibre-Web sends unknown or unimplemented requests to `https://storeapi.kobo.com` using the incoming method, headers, and body. It returns an HTTP `307` redirect for `GET`; it proxies non-`GET` requests itself because Kobo turns redirected writes into `GET`. Connection-specific headers are removed from proxied responses (`cps/kobo.py:89-130@a97826402f1b39c45b7ea8d906efddc9f1750934`). In proxy mode, the official `/v1/library/sync` response and token are merged into the local sync response (`cps/kobo.py:308-332@a97826402f1b39c45b7ea8d906efddc9f1750934`). Without proxying, unimplemented requests return `{}` or their route-specific empty result (`cps/kobo.py:969-1037@a97826402f1b39c45b7ea8d906efddc9f1750934`).

## 2. What a stock Kobo syncs for third-party books

**[observed]** A third-party server can receive progress, status, and statistics through the ReadingState contract above: the writable fields are percentages, an optional Kobo `Location`, reading minutes, remaining time, status, and reading-start count (`cps/kobo.py:758-819@a97826402f1b39c45b7ea8d906efddc9f1750934`). This is distinct from the `Bookmark` table in `KoboReader.sqlite`.

**[observed]** Highlights and annotations are not part of the Calibre-Web ReadingState API evidence. The state handler reads `CurrentBookmark`, but only its progress/location members; there is no `Text`, `Annotation`, highlight field, or annotation collection in the handler (`cps/kobo.py:758-819@a97826402f1b39c45b7ea8d906efddc9f1750934`).

**[observed]** Calibre-Web's authentication comments mention an official Kobo `AnnotationService` that uses a Bearer token obtained through device authentication, but the pinned Calibre-Web implementation has no local AnnotationService implementation or annotation parser. Its analytics catch-all either blindly relays requests to Kobo in proxy mode or returns `{}` (`cps/kobo_auth.py:43-58@a97826402f1b39c45b7ea8d906efddc9f1750934`, `cps/kobo.py:969-991@a97826402f1b39c45b7ea8d906efddc9f1750934`).

**[inference]** Therefore, “progress yes, highlights/annotations no” is the reliable answer for a stock Kobo pointed at a third-party server using this API shape: ReadingState can carry progress, but analytics or official AnnotationService traffic that is proxied remains official-store traffic, not a local annotation record. A server-owned highlight archive needs a device-side database import or another explicitly implemented channel.

**[observed]** Store books are different from third-party books. A Calibre-Web instance can make store traffic appear to work only by proxying/redirecting official Kobo requests and merging the official store's sync response; that is not a local third-party entitlement (`cps/kobo.py:89-130@a97826402f1b39c45b7ea8d906efddc9f1750934`, `cps/kobo.py:308-332@a97826402f1b39c45b7ea8d906efddc9f1750934`).

## 3. EPUB versus KEPUB

**[observed]** KEPUB remains an EPUB container, but `kepubify` transforms an EPUB into Kobo's form: it applies Kobo styles and pagination markup and adds mandatory `koboSpan` elements around text fragments. The source explains that spans provide better references to text chunks and that highlighting, bookmarking, and related features do not work without them (`kepub/transform.go:102-129@9546034bc023891af5ce30709de6ae2dcf264628`).

**[observed]** The kepubify documentation describes Kobo EPUBs as improving page turns, font changes, highlighting, and searching, while the KEPUB reader supports EPUB 3 features and Kobo statistics such as a chapter graph and estimated read time (`public/index.html:100-117@448534694374e195f8a915c5caf16cdf22ec7792`). The converter can use `.kepub` rather than `.kepub.epub` as its output extension (`cmd/kepubify/kepubify.go:35-41@9546034bc023891af5ce30709de6ae2dcf264628`).

**[observed]** Calibre-Web advertises format labels `KEPUB`, `EPUB3`, and `EPUB` using the exact `KOBO_FORMATS` map above. It prefers an existing KEPUB and can queue conversion when only EPUB is available (`cps/kobo.py:55-57@a97826402f1b39c45b7ea8d906efddc9f1750934`, `cps/kobo.py:207-224@a97826402f1b39c45b7ea8d906efddc9f1750934`).

**[observed]** Komga provides a second delivery precedent: its Kobo controller can select KEPUB conversion and emits `Format.KEPUB` when that delivery path is selected; its ordinary EPUB path uses the corresponding EPUB format labels (`KoboController.kt:637-783@656001eb03bf8b54ca909f3e74fe2ec1b95dac48`).

**[inference]** KEPUB conversion and ReadingState persistence are separate features. Conversion changes the bytes and creates a stable Kobo-span coordinate space; persistence can first store percentages and Kobo locations even when delivery remains plain EPUB. A `KoboSpan` is meaningful only against the exact transformed resource and position map, so it must not be treated as portable across arbitrary EPUB and KEPUB variants.

### Coppice's optional EPUB-to-KEPUB converter and cache

**[implemented]** Coppice includes a pure-Rust EPUB-to-KEPUB converter in
`crates/kepub` and an adapter hook in
`apps/server/src/routers/kobo_backend/kepub.rs`. It is disabled by default and
is enabled with `KOBO_KEPUB_CONVERSION=true` (`StumpConfig.kobo_kepub_conversion`).
The Kobo URL remains `/v1/books/<book_id>/file/epub` for compatibility; when
enabled, EPUB is served as KEPUB with `KEPUB` metadata.

The converter is a 1:1 port of kepubify's `kepub` package at commit
`9546034bc023891af5ce30709de6ae2dcf264628` (parser fork
`pgaskin/kepubify/_/html@6ee2cc632cdc`): lenient self-closing repair,
HTML5 tree building, the `div#book-columns > div#book-inner` wrapper,
`kobostylehacks`, `koboSpan` sentence splitting and `kobo.N.M` numbering,
Adept/MS Word cleanup, the polyglot XHTML renderer, the OPF rewrite (cover
property, Calibre metadata removal, 4-space re-indent), and the dummy
title-page heuristic. Optional converter controls (smart punctuation,
find/replace, extra CSS, hyphenation, full-screen fixes, charset) are exposed
on `TransformOptions` with kepubify semantics.

**Historical contract evidence, not device evidence:** the 35/35 KEPUB parity
sample compares decompressed ZIP entries with pinned kepubify output. The
independent real-book test is opt-in and uses a local corpus; neither record is
a physical Kobo run.

The parity contract is enforced by `crates/kepub/tests/transform_content.rs`,
`transform_opf_and_files.rs`, `split_sentences.rs`, `convert.rs`, and the
stored-output fixture in `crates/kepub/tests/transform.rs`.

One deliberate deviation: kepubify (via Go `encoding/xml`) rejects packages
whose OPF declares `<?xml version="1.1"?>`; Coppice converts them.

**Historical performance measurement, separate from the 35/35 parity sample:**
release build on AMD Ryzen 7 5800X, a 36-book / 37 MB corpus, best-of-3 process
wall-clock including startup; kepubify is itself multi-threaded per book:

| | Coppice | kepubify | ratio | peak RSS Coppice / kepubify |
|---|---|---|---|---|
| pinned to one core | 1160 ms | 1742 ms | 1.50× | 14 MB / 22 MB |
| 8 cores | 386 ms | 1060 ms | 2.75× | 29 MB / 34 MB |

Design: the HTML tree is an index-linked arena (`crates/kepub/src/dom.rs`,
a custom html5ever `TreeSink`) and `koboSpan` markup is emitted while
serializing rather than materialised as nodes; content documents are inflated,
transformed, and deflated on a `rayon` pool in bounded batches (2 × threads in
flight) and written in source order; untouched entries are sliced from the
source archive by offset (never inflated); the ZIP container is written by
`crates/kepub/src/archive.rs` straight into any `Write` sink
(`transform_epub_to`), so the server converts directly into the cache file and
the whole KEPUB is never held in memory. Deflate/inflate use `libdeflate`;
the default deflate level is 6 (kepubify's default).

**[implemented]** Non-content ZIP entries are copied through verbatim,
preserving their compressed bytes, timestamps, and Unix mode. Converted output
is cached lazily at
`<config_dir>/cache/kepub/<media_id>-<file_mtime>-<options digest>-d<deflate level>.kepub.epub`,
where `file_mtime` is the source modification time in nanoseconds since the
Unix epoch and the deflate level is part of the cache key. The file is written
to a unique temp name and renamed into place, and served with `ServeFile`
(range requests supported). Replacing a source file or changing converter
options or compression selects a new cache key; conversion never mutates the
original EPUB.

KEPUB cache warming is enabled by the same `KOBO_KEPUB_CONVERSION=true`
switch. New EPUB entitlements in `GET /v1/library/sync` are queued for
background conversion. The queue is process-wide, bounded, deduplicated by
cache path, and converts one book at a time on Tokio's blocking pool. Set
`KOBO_KEPUB_PRECONVERT=true` to enqueue every EPUB in a library when its scan
completion event arrives. Cache files are touched on delivery hits and an age
sweep runs at startup and every 24 hours; files unused longer than
`KOBO_KEPUB_CACHE_MAX_AGE_DAYS` are removed, while temporary files younger than
one hour are retained.

## 4. Coppice today

**Historical source snapshot (`37fdb7d`):** this older inventory is not the
current Coppice behavior. It recorded initialization, library sync, metadata,
thumbnails, device auth, EPUB file delivery, and a fallback route.

**[implemented]** Current initialization rewrites library sync, reading state,
metadata, tags, profile, and book-access resources to Coppice URLs; store-only
resources remain official Kobo URLs. `POST /v1/auth/device` is compatibility
data only and does not create a persistent device session.

**[implemented]** `GET` and `PUT /v1/library/{book_id}/state` persist and
reconstruct Kobo ReadingState, including the native JSON payload; incremental
sync reports state changes. Shelves and tags write through to collections and
reading lists, retaining device provenance and delete tombstones.

**[implemented]** EPUB remains the default. `KOBO_KEPUB_CONVERSION=true`
enables optional KEPUB output; comics transformation is a separate shipped
feature and remains disabled by default (`STUMP_TRANSFORM_ENABLED=false`).

### Fixture probe

The fixture server can exercise the state round trip without restarting the
server. Run this against `http://127.0.0.1:25600` with the fixture key from
`scripts/dev-fixture-server.sh`:

```bash
BASE=http://127.0.0.1:25600
KEY=stump_VGQQpvVAkun_KyDK1NExypMM2cQJA7XtcXCzHgEiWczYc

# Initialization must point the state resource back at Coppice.
curl -fsS "$BASE/kobo/$KEY/v1/initialization" \
  | jq -e --arg url "$BASE/kobo/$KEY/v1/library/{Ids}/state" \
      '.Resources.reading_state == $url'

# The first sync supplies a fixture book id and a token for the next sync.
curl -fsS -D /tmp/stump-kobo-sync.headers \
  "$BASE/kobo/$KEY/v1/library/sync" \
  -H 'x-kobo-deviceid: fixture-kobo' >/tmp/stump-kobo-sync.json
BOOK_ID="$(jq -r '.[].NewEntitlement.BookEntitlement.Id // empty' \
  /tmp/stump-kobo-sync.json | sed -n '1p')"
TOKEN="$(sed -n 's/^[Xx]-[Kk]obo-[Ss]ynctoken: *//p' \
  /tmp/stump-kobo-sync.headers | tr -d '\r')"

cat >/tmp/stump-kobo-state.json <<'JSON'
{"ReadingStates":[{"CurrentBookmark":{"ProgressPercent":73,
  "ContentSourceProgressPercent":42,
  "Location":{"Value":"kobo.3.7","Type":"KoboSpan",
  "Source":"chapter.xhtml"}},"Statistics":{"SpentReadingMinutes":4,

  "TimesStartedReading":1}}]}

  -H 'Content-Type: application/json' \
  -H 'x-kobo-deviceid: fixture-kobo' \
  --data-binary @/tmp/stump-kobo-state.json | jq -e \
  '.RequestResult == "Success" and .UpdateResults[0].CurrentBookmarkResult.Result == "Success"'

curl -fsS "$BASE/kobo/$KEY/v1/library/sync" \
  -H "x-kobo-deviceid: fixture-kobo" \
  -H "x-kobo-synctoken: $TOKEN" | jq -e --arg id "$BOOK_ID" \
  'any(.[]; .ChangedReadingState.ReadingState.EntitlementId == $id)'
```


## 5. NickelHardcover and richer community extractors

### NickelHardcover

**[observed]** NickelHardcover is a device-side push integration to Hardcover, not a server-pull integration for Coppice. Its CLI opens `/mnt/onboard/.kobo/KoboReader.sqlite` read-only and sends calculated progress to Hardcover. This remains separate from Coppice's stock Kobo sync and annotation boundary.

**[observed]** Its bookmark query reads `BookmarkID`, `Text`, `Annotation`, `DateCreated`, and `ChapterProgress`, joins `content` for chapter/book word counts, and normalizes a bookmark position. It combines `Text` and `Annotation` into a Hardcover journal quote (`cli/src/database.rs:17-80@149ab0ec224b8cf49da269338731b8eade1a809a`, `cli/src/commands/updatejournal.rs:178-220@149ab0ec224b8cf49da269338731b8eade1a809a`). The current pinned source does **not** select `StartContainerPath`, and it does not query `Event` or `Activity`; those richer fields must not be attributed to NickelHardcover. Codeberg citations: [`cli/src/database.rs:17-80@149ab0e`](https://codeberg.org/StrayRose/NickelHardcover/src/commit/149ab0ec224b8cf49da269338731b8eade1a809a/cli/src/database.rs#L17-L80), [`cli/src/commands/updatejournal.rs:178-220@149ab0e`](https://codeberg.org/StrayRose/NickelHardcover/src/commit/149ab0ec224b8cf49da269338731b8eade1a809a/cli/src/commands/updatejournal.rs#L178-L220).

**[observed]** The README warns that firmware 5.x is not supported ([`README.md:10-15@149ab0e`](https://codeberg.org/StrayRose/NickelHardcover/src/commit/149ab0ec224b8cf49da269338731b8eade1a809a/README.md#L10-L15)). ### Richer database extractors

**[observed]** `kobo-highlights-to-calibre` documents the richer `Bookmark` schema, including `StartContainerPath`, `EndContainerPath`, child indexes and offsets, `Text`, `Annotation`, `ChapterProgress`, timestamps, and other fields. Its examples include anchors such as `OEBPS/chap.xhtml#point(/...)`, which are CFI-like resource anchors (`README.md:104-176@7f04a7a760f61b7d36688c0ab1e4415e12150016`, `index.js:68-108@7f04a7a760f61b7d36688c0ab1e4415e12150016`).

**[observed]** `kobo-db-tools` parses `AnalyticsEvents` rows (`Type`, `Timestamp`, `Attributes`, `Metrics`) into reading sessions and metrics and also parses bookmarks. Its README warns that a sync can clear `AnalyticsEvents`; the remaining `Event.ExtraData` trace is an encrypted/opaque blob (`README.md:1-46@6c6b2903c58512e8714935048a30d0cc72923bc8`, `src/parser.rs:689-710@6c6b2903c58512e8714935048a30d0cc72923bc8`). The database can be opened read-only as a fallback (`src/parser.rs:441-445@6c6b2903c58512e8714935048a30d0cc72923bc8`).

**[observed]** `kobuddy` reads device `content` rows for book identity, percentage, status, last-read time, and time spent, and iterates both `Event` and `AnalyticsEvents` tables. Its own comments mark Event meanings as uncertain; this is useful extraction evidence, not a stable firmware contract (`src/kobuddy/__init__.py:398-446@4e972ce6256d9499394de211c2873cc8b94ee58a`, `src/kobuddy/__init__.py:454-570@4e972ce6256d9499394de211c2873cc8b94ee58a`, `src/kobuddy/__init__.py:659-757@4e972ce6256d9499394de211c2873cc8b94ee58a`).

**[observed]** `Activity` appears in some database table listings, but the pinned tools above do not establish stable Activity semantics. Treating it as a contract requires firmware fixtures and validation (`README.md:104-137@7f04a7a760f61b7d36688c0ab1e4415e12150016`).

**[inference]** A device importer must copy/read the database promptly and read it without mutation. Analytics rows may disappear during a later sync, and richer CFI fields come from supplementary extractors rather than the current NickelHardcover path.

## 6. Current Coppice compatibility matrix

The historical external-source matrix above describes reference behavior, not
the current server. Current client/device evidence is in the
[client verification matrix](/docs/developer/client-verification).

| Capability | Current Coppice behavior | Boundary |
| --- | --- | --- |
| DRM-free local EPUB | **Shipped.** Visible EPUB media is delivered through the Kobo sync profile. | Kobo entitlement is local library access; store purchases are not proxied. |
| KEPUB conversion | **Shipped; optional.** `KOBO_KEPUB_CONVERSION=true` enables conversion; default delivery is EPUB. | Separate from reading-state persistence and from comics transformation. |
| Comics transformation | **Shipped; disabled by default** (`STUMP_TRANSFORM_ENABLED=false`). | Per-device output profiles; contract evidence is not physical-Kobo evidence. |
| ReadingState | **Shipped.** GET/PUT read and write state fields and preserve the native request payload. | Stock sync carries progress/location/status/statistics, not annotation objects. |
| Incremental state sync | **Shipped.** A changed reading-session row produces `ChangedReadingState`. | A server contract, not proof of stock-device behavior. |
| Shelves and tags | **Shipped.** Tag and tag-item operations write through to collections/reading lists, with `source_device` provenance and delete tombstones. | See `apps/server/src/routers/kobo_backend/tags.rs`; device verification is separate. |
| `/v1/auth/device` | Compatibility-only, non-persistent response. | Does not establish a durable device identity or account/store session. |
| Stock Kobo annotations | Not transported by stock Kobo sync; there is no server-side SQLite importer. | `nickelcoppice` contains a separate source-derived `.kobo/markups` reader; no device run is recorded. |
| KOReader annotations | Not supported by KOSync. | The route contract carries progress only, not highlights or notes. |
| KOReader progress | Available through the separate KOSync profile. | The `coppice.koplugin` source has not been loaded into the native app; see the client matrix. |
| Physical Kobo run | No physical-device run is recorded here. | The 35/35 parity sample and separate 36-book / 37 MB performance corpus are not device evidence. |

## 7. Reading-state mapping and future import notes

Stock Kobo sync does not provide a server-side pull of `KoboReader.sqlite`.
Any future database importer would require a device-side hook or a timely
read-only USB/database copy. Do not interpret database-extractor research as
shipped annotation import.

### Normalize Kobo reading-state fields

**[inference]** Komga's Kobo controller is a useful wire-mapping precedent:

| Kobo field | Coppice normalized field |
| --- | --- |
| `Location.Source` | `ReadiumLocator.href` |
| `Location.Type=KoboSpan` plus `Location.Value` | `ReadiumLocator.kobo_span` |
| `ContentSourceProgressPercent / 100` | `ReadiumLocator.locations.progression` |
| `ProgressPercent / 100` | `ReadiumLocator.locations.total_progression` |
| `StatusInfo` | Separate reading-session/status fields |
| `Statistics` | Separate reading-session/statistics fields |

The reference mapping is from Komga's `R2Locator` construction and
ReadingState DTO (Komga commit
[`656001eb`](https://github.com/gotson/Komga/tree/656001eb03bf8b54ca909f3e74fe2ec1b95dac48)).
Coppice has `ReadiumLocation.progression`, `total_progression`, and
`partial_cfi`, plus `ReadiumLocator.kobo_span`
(`crates/models/src/shared/readium.rs`).

If database import is added later, `StartContainerPath` would need to be split
into resource href and CFI-like fragment; `Text` and `Annotation` would map to
distinct annotation fields. A `KoboSpan` is meaningful only for the exact
transformed resource and position map; it is not portable across arbitrary
EPUB/KEPUB variants.
