# Annotation sync

Annotation sync projects native annotations/bookmarks, liseur-sync CAS rows, and
reading heads/sessions into one deterministic per-user export batch. Markdown
and Git share the same writer; Git adds a commit/push lane.

```
annotation / bookmark / reading-head change
   ──▶ Ctx::note_annotation_activity(user)      (re)arms a deadline
   ──▶ debounce loop                            deadline passed → enqueue
   ──▶ StumpJob::AnnotationSync { user_id }     one task per enabled sink
        decrypt settings → build batch → Sink::export
        persist state + last_run_at + last_error
```

## Config keys

| Key | Env | Default | Meaning |
| --- | --- | --- | --- |
| `annotation_sync_root` | `STUMP_ANNOTATION_SYNC_ROOT` | `<config_dir>/annotations` | Admin-mounted export root; each user gets `<root>/<user_id>/` |
| `annotation_sync_debounce_secs` | `STUMP_ANNOTATION_SYNC_DEBOUNCE_SECS` | `30` | Quiet period before a user's export runs |

The root is server configuration, not a user-controlled path. A user may only
choose a contained relative `destination` below their own directory. Existing
sink rows without `format_version` remain on the legacy lane until explicitly
upgraded.

## Markdown and Git settings

| Setting | Required | Format-2 default | Purpose |
| --- | --- | --- | --- |
| `format_version` | no | `2` for new connections | Explicit opt-in; omission preserves UUID filenames and legacy bytes |
| `preset` | no | `obsidian` | `obsidian`, `flat`, or `author` safe layout |
| `destination` | no | empty | Bounded relative directory below the user directory |
| `path_template` | no | `{{author}} - {{title}}/annotations.md` | Fixed variables only: `author`, `title`, `source`, `source_id`, `book_id` |
| `body_template` | no | — | Optional fixed-variable template; `{{content}}` inserts the generated body |
| `base_url` | no | — | Public server URL for native reader links |
| Git `remote_url` | no | — | HTTPS or local remote outside the worktree; empty means local commit only |
| Git `branch` | no | `main` | Branch to commit/push |
| Git `token` | no | — | Secret access token, encrypted at rest and never returned |
| Git `author_name` / `author_email` | no | `Coppice` / `annotations@stump.local` | Commit signature |

Templates are parsed, not evaluated. Root/absolute paths, `..`, empty or
reserved components, control bytes, oversized segments, malformed/unknown
variables, and symlinked root/parent/final paths are rejected. Book title and
author components are NFC-normalized and sanitized without producing path
separators.

Both sinks serialize settings with the existing server encryption boundary.
Object updates merge omitted keys, so leaving a secret out of an update keeps
the encrypted value rather than deleting it.

## Format 2 layout

The default new Markdown connection writes exactly:

```text
<STUMP_ANNOTATION_SYNC_ROOT>/<user>/Author - Book/annotations.md
```

Duplicate normalized paths receive deterministic suffixes such as
`Author - Book (2)/annotations.md`. A source-key → relative-path map is kept in
`SinkState.data`; an existing source keeps its mapped path across title changes
and never overwrites another source.

Frontmatter is ordered structured YAML and contains no volatile generation time:

```yaml
schema: "coppice.annotation/v2"
book:
  key: "native:m1"
  title: "Book"
  authors:
    - "Author"
  identifiers: {}
source:
  kind: "native"
  id: "m1"
  media_id: "m1"
  key: "native:m1"
source_updated_at: "2023-11-14T22:14:30Z"
reading:
  progression: 0.5
  page: 42
  completed: false
  finished: false
  last_read_at: null
  source_protocol: null
  session_count: 0
  total_seconds: null
  last_session_at: null
annotations:
  - id: "a1"
    kind: "highlight"
    source: "native"
    source_id: "m1"
    provenance:
      kind: "native"
      source_id: "m1"
    created_at: "2023-11-14T22:14:20Z"
    updated_at: "2023-11-14T22:14:20Z"
    deleted: false
bookmarks: []
```

Rows remain ordered by canonical model order. Tombstones stay in frontmatter
for provenance but are omitted from body sections. V2 body blocks use a source-
aware id (`^native-m1-a1`); legacy files retain `^a1`. Files are compared
before writing, so unchanged bytes retain their mtime. Writes use a per-user
lock, a same-directory 0600 temporary file, `sync_all`, and an atomic rename.

## Git safety

Git stages only the managed relative paths returned by the shared writer; it
never uses a wildcard that could include an unmanaged vault file. Local remote
paths overlapping the worktree are rejected. A rejected push is rebased once;
conflicts abort and leave the local branch intact.

## GraphQL

| Operation | Purpose |
| --- | --- |
| `annotationSinks: [AnnotationSink!]!` | Compiled sinks, setting schemas, and safe preset descriptors |
| `annotationSyncStatus(userId: ID): AnnotationSyncStatus!` | Per-user sink state and debounce status |
| `setAnnotationSinkSettings(...)` | Set/merge settings; secrets are encrypted at rest |
| `runAnnotationSync(userId: ID): AnnotationSyncStatus!` | Enqueue an immediate export |
| `annotations(filter: AnnotationFilterInput, pagination: OffsetPagination)` | Cross-source annotation hub; `sourceDeviceId` filters durable `devices.id` |

`sourceDeviceId` resolves liseur rows through the durable device registry and
not an active-credential predicate, so revoked-device history remains linkable.
Native rows continue to report a null source device.

## Incremental model

Native books rebuild in full because native rows are hard-deleted. Linked
liseur works fold into their native book; standalone liseur works advance by CAS
`seq`. The job builds from the oldest sink cursor and advances only successful
sinks to the observed high-water mark.
