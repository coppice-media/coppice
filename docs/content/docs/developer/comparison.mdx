Where this fork stands against six comparable self-hosted library servers. The
point of the page is the **missing** and **partial** cells: they are the honest
gap list, and they feed [Roadmap › Future](/docs/developer/roadmap#future).

## How to read this

- **This fork.** Every cell cites a path in this working tree. `dev/x.mdx:N`
  means `docs/content/docs/developer/x.mdx` at that line; other paths are
  repo-relative. `missing` and `partial: …` are used literally.
- **Competitors.** Every cell links the page it was read from — the project's
  own docs, README, or feature page. `n/e` means *no evidence on the cited
  page*: the feature is absent from that project's own feature list, which is
  weaker than a documented "no".
- **BookOrbit is AGPL-3.0** ([LICENSE][bo-repo]). Its code cannot be reused in
  this MIT tree. Only its **behaviour and public specs** — what a feature does,
  what the wire looks like — inform us; no BookOrbit source is read, copied, or
  adapted. Grimmory is AGPL-3.0 too and is treated the same way, except that we
  impersonate its published `/komga` alias as a compatibility target
  (`dev/komga-compat.mdx`).
- Snapshot date 2026-09-07 (`7de64602`). Competitor docs move; the links are the
  evidence.

## Where this fork is behind

Four rows are outright **missing**:

1. **Read-aloud** — ebook ↔ audiobook position sync. The design is accepted
   (`dev/read-aloud.mdx:6`) and nothing is built. No peer in this set documents
   it either, so this is a lead we have not taken rather than a deficit.
2. **ABS socket.io lane** — Audiobookshelf's own server "requires a websocket
   connection" ([README][abs-readme]); our profile is REST-only, which is enough
   for Lissen and not enough for the official app (`dev/roadmap.mdx:74`).
3. **Achievements** — the console has statistics, not goals or streak
   gamification (`dev/home-app.mdx:64`). BookOrbit ships reading goals, a daily
   streak and a diversity score.
4. **Backup / restore** — no surface at all (`dev/state.mdx:169`); ABS ships
   metadata backups with an automated daily schedule.

Five rows are **partial**, i.e. something real exists but a peer does more: the
annotations model (two stores, never reconciled), cover selection (decided but
not written), bulk metadata edit (staged items only), dashboards (fixed
composition), and Cloudflare-challenged sources (a pasted cookie that expires
within the hour). Each is carried in
[Roadmap › Future](/docs/developer/roadmap#future).

Rows where nothing in this list matches us: OPDS 2.0 alongside Komga *and*
Kavita *and* Audiobookshelf profiles on one server, the provider host with
data-driven theme engines and a frozen definition schema, the e-ink comics
transform, per-device library scope and per-device audio delivery, device
pairing with QR, built-in ntfy/webhook notifications, one documented event bus
with pluggable sinks, inbound rate limiting, an audiobook quality report, and a
measured idle RSS number.
