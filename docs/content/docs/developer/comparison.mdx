Where this fork stands against six comparable self-hosted library servers. The
point of the page is the **missing** and **partial** cells: they are the honest
gap list, and they feed [Roadmap › Gaps vs peers](/docs/developer/roadmap#gaps-vs-peers).

## How to read this

- **This fork.** Every cell cites a path in this working tree. `dev/x.mdx:N`
  means `docs/content/docs/developer/x.mdx` at that line; other paths are
  repo-relative. `missing` and `partial: …` are used literally.
- **Competitors.** Every cell links the page it was read from — the project's
  own docs, README, or feature page. `n/e` means *no evidence on the cited
  page*: the feature is absent from that project's own feature list, which is
  weaker than a documented "no".
- **BookOrbit is AGPL-3.0** ([LICENSE][bo-repo]). Its code cannot be reused in
  this MIT tree. Only its **behaviour and public specs** — what a feature does,
  what the wire looks like — inform us; no BookOrbit source is read, copied, or
  adapted. Grimmory is AGPL-3.0 too and is treated the same way, except that we
  impersonate its published `/komga` alias as a compatibility target
  (`dev/komga-compat.mdx`).
- Snapshot date 2026-09-06. Competitor docs move; the links are the evidence.

## Where this fork is behind

Four rows are outright **missing**:

1. **Audiobook formats** — no audio processor in `stump_media` (`crates/README.md:29`).
   BookOrbit, Grimmory, and Audiobookshelf all serve M4B/MP3.
2. **Web audio player** — the reader set is ebook, image, PDF only
   (`docs/content/docs/apps/web/readers.mdx:5-38`).
3. **First-party KOReader plugin** — we ship the sync API
   (`dev/provider-status.mdx:174`) and a Kobo Nickel plugin
   (`dev/platforms.mdx:52`), but nothing that runs inside KOReader. BookOrbit
   and CWA both ship one, and a plugin is what buys highlights and per-book
   sweeps over plain kosync.
4. **Achievements** — the home app has devices, reading, account
   (`dev/home-app.mdx:47-52`); nothing gamified.

Six rows are **partial**, i.e. something real exists but a peer does more:
the Kavita API (wave 1 only), per-field provider rules and merge, bulk metadata
edit, the annotations model, the annotations UI, and dashboards/analytics. Each
is carried as a candidate item in
[Roadmap › Gaps vs peers](/docs/developer/roadmap#gaps-vs-peers).

Rows where nothing in this list matches us: OPDS 2.0 plus Komga *and* Kavita
profiles on one server, the provider host (remote sources as libraries), the
e-ink comics transform, device pairing with QR, built-in ntfy/webhook
notifications, and a measured idle RSS number.
