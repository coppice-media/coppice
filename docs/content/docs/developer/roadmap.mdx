# Roadmap

This roadmap tracks the current Coppice integration worktree. Two sections carry
weight: **[Open](#open)** — five items, each blocked on something nameable — and
**[Future](#future)**, candidates that are neither scheduled nor promised.
Everything above them is history, kept because each phase names the document it
came from and because the compatibility boundary matters.

Evidence labels are exact: **Shipped**, **Contract-tested**, **Device-tested**,
**Source-only**, **Planned**, and **Blocked**. A replay or source inspection is
never app/device proof. The integration classes and their ownership are defined
in [Integration architecture](/docs/developer/integration-architecture).

## Open

Five items. Nothing else is in flight, and each of these names what it is
waiting on.

### 1. Device runs that need hardware or an account we do not have

**Blocked** on physical access, not on a known code change. The remaining gaps
are a physical Kobo run against `/kobo/{api_key}`, loading `stump.koplugin` in
KOReader on a device, and delivering a Kindle message to a real `@kindle.com`
address. The official Audiobookshelf app has a scoped **Device-tested** emulator
run; it is not a substitute for complete Audiobookshelf parity. See [Current
state › verification](/docs/developer/state#verification-per-client).

### 2. API keys for Hardcover, Metron, Open Library, and Google Books

The four metadata clients are **Shipped** and **Contract-tested** against
recorded payloads, and the editor's API-keys page stores their tokens. No live
request has been made with a real credential, so live field/error/rate-limit
verification is **Blocked** until a key exists. Hardcover account, progress,
and journal sync are separate **Planned** work and remain **Blocked** on a
stable authenticated account API ([Provider status](/docs/developer/provider-status#metadata-providers),
[Hardcover integration](/docs/developer/hardcover-integration)). User-gated.

### 3. Coppice rename and the upstream split

Product-facing documentation and UX copy use **Coppice**. The repository slug,
Rust/package/binary identifiers (`stump_*`, `stump_server`, `stump_worker`,
`@stump/*`), environment keys, routes, storage fields, app IDs/schemes, Docker
slugs, and upstream URLs remain compatibility-sensitive. Renaming those
identifiers and splitting fork-local additive work into separate upstreamable
PRs against `stumpapp/stump` nightly is **Blocked** and user-gated. If resumed,
sequence core lifecycle and feature gates first, then protocol profiles
(`komga`, `kavita`, `kobo`, `koreader`, `liseur-sync`, `abs`, `kindle`), then the
provider host/theme engines, then ingest and tools. See [incremental upstream PR
sequence](/docs/developer/server-architecture#incremental-upstream-pr-sequence).

### 4. ABS Socket.IO lane — implemented; broader verification open

The Engine.IO v4 / Socket.IO v5 lane is **Shipped** in
`crates/abs/src/socket/mod.rs` and `crates/abs/src/socket/protocol.rs`, with
`/socket.io` mounted by `apps/server/src/routers/abs_backend.rs::compose`.
`crates/abs/src/socket/tests.rs` exercises authenticated websocket frames
against a real listener. The scoped official ABS app run does not establish
complete parity, so broader official-client/device verification remains
**Pending**. Lissen's REST-shaped profile does not need this socket lane. The
compatibility contract is [Audiobookshelf compatibility](/docs/developer/abs-compat).

### 5. Ebook ↔ audiobook sync — partially shipped; product lanes open

`reading_heads` can hold a locator or millisecond offset (`m20260933`).
Confirmed/suggested edition pairing, editable chapter maps, and read-time
chapter/percentage conversion bridge those position kinds approximately;
GraphQL exposes `Media.pairedPosition`. Persisted `media_sync_maps`, import and
enqueue mutations, deterministic cache paths, and result validation are
**Shipped** through `crates/library/src/sync_maps.rs`,
`crates/graphql/src/mutation/sync_map.rs`, and
`apps/server/src/routers/api/v2/read_aloud.rs`. The generic remote-worker
protocol, `worker_jobs`, and transcode/challenge runners are also **Shipped**.

`crates/worker/src/alignment.rs` supplies the typed alignment input,
capability, `SyncMapV1`, identity check, and duration-aware validation
contracts; it is not a native aligner. Native CTC/Viterbi alignment, full
synchronized playback, a user-facing synchronized-playback UI, and
deployment/device evidence remain **Planned** or **Pending**. Ordinary EPUB
playback and ordinary audiobook playback remain separate.

Implementation order, from [§9 of Read-aloud](/docs/developer/read-aloud#9-implementation-order):

1. Pairing, `media_chapter_map`, and tier-1 conversion — **Shipped**; readiness
   remains **Planned**.
2. Worker protocol, `crates/worker`, and `worker_jobs` — **Shipped**.
3. Sync-map persistence, import/enqueue, cache delivery, and `Media.syncMap` —
   **Shipped**.
4. Import exact Storyteller/SMIL timing, then make an operator's existing
   Storyteller instance the first optional worker-side executable backend.
5. Add native known-text CTC/Viterbi and portable manifest import/export.
6. Add full synchronized playback and read-aloud EPUB delivery after the
   virtual source-M4B ZIP experiment has evidence.
7. The request ledger and backend approval/release/polling path are **Shipped**;
   live MAM deployment, physical-device delivery, and post-merge verification
   remain **Pending**.

## Request orchestration status

The requests/wanted ledger, request table, gateway settings, approval/release
GraphQL mutations, automation defaults, and bounded download polling processor
are **Shipped**. The source surfaces are
`crates/models/src/entity/book_request.rs`,
`crates/graphql/src/query/book_request.rs`,
`crates/graphql/src/mutation/book_request.rs`,
`core/src/request_gateway.rs`,
`core/src/request_gateway_automation.rs`, and
`core/src/request_gateway_poll.rs`.

The backend does not claim a Requests page, live MAM download, or
physical-device delivery. The implemented flow is:

```text
internal media/work or external work reference
  -> optional destination device/shelf
  -> approval (automation defaults off)
  -> Torznab caps/search through private mam-gateway
  -> opaque release selection and grab
  -> bounded download polling
  -> existing ingest staging + source verification
  -> destination queue
```

Shelfmark remains absent. The implemented `mam-gateway` is a narrow connector:
MAM credentials/raw tracker URLs remain inside the Gluetun namespace, while
Coppice stores only its private endpoint/token. Live MAM authentication,
VPN-egress proof, qBittorrent download, ingest replay, and physical-device
delivery are **Pending**. The post-merge gate and fixture replay set are also
**Pending**; `.omp/PROJECT_STATE.md` is authoritative. Coppice must not ship an
arbitrary downloader or imply that a catalog result has acquired a file. See
[Integration architecture](/docs/developer/integration-architecture).

## Future

Unordered, unscheduled, and some of these will end up non-goals. Peer-shipped
items name the peer, because that peer's *behaviour* is the specification to
read — never its code: BookOrbit and Grimmory are AGPL-3.0 and this tree is MIT.
Every cell behind them is cited in [Feature comparison](/docs/developer/comparison).

### Peers ship it, we do not

- **Achievements.** The console nav is Dashboard, Library, Reading, Annotations,
  Devices, Account (`docs/content/docs/developer/home-app.mdx:64`). Peer:
  BookOrbit.
- **Configurable dashboard.** `/dashboard` is a fixed composition — stat cards,
  a 53-week heatmap, continue-reading and recently-added shelves, device sync,
  job queue — with no user-arranged widgets
  (`docs/content/docs/developer/home-app.mdx:49`). Peers: BookOrbit, Kavita,
  Calibre-Web Automated.
- **Bulk metadata edit outside ingest.** `bulkApplyIngestMetadata` still only
  touches staged drop items. Peer: Calibre-Web Automated.
- **One annotation model.** Native rows and liseur CAS rows are stored side by
  side and surfaced together in the annotation hub, but never reconciled into a
  single head with a repair state. Peer: BookOrbit.
- **Calibre-Web facade for Liseur.** No `/opds/...` web-form contract and no
  Calibre-Web login/token/delete lane ([Liseur providers](/docs/developer/liseur-providers)).

### Engineering carried forward

- **Metadata post-processing** (the tail of phase 5): title-language selection,
  book ordering, score tags, publisher tag names, and actually writing the
  chosen cover — `CoverUrl` is outside `STORABLE_FIELDS`, so today's decision
  returns `applied: false`.
- **Processor-sized Cargo features** (the tail of phase 2): `metadata`, `email`,
  and a `pdf-render` split, so a KOReader-only or comics-only build stops
  linking PDFium, unrar, and the metadata tree.
- **Federation via peer tokens** (phase 8) and the **Komga/Kavita federation
  provider** (the unstarted half of phase 3): a remote host authenticates with a
  revocable scoped token, not a user account. No ActivityPub.
- **wasmtime source sandbox**, deferred until the definition schema and catalog
  flow stop moving.
- **Operations:** a `/metrics` or OpenTelemetry export, a backup/restore
  surface, dependency-specific readiness, and a CI profile matrix for
  `minimal`, `headless,liseur-sync`, default, and a compatibility replay
  (`.github/workflows/ci.yaml` still runs default checks only).
- **CBZ KOReader hash**, still commented out in
  `crates/media/src/media/format/zip.rs:61,68-75`.
- **A liseur-sync attachment blob route:** Kobo markup snapshots and notebooks
  are described (id, anchor, sha256) but not transported, which is a protocol
  change to design rather than an omission to fix.

## Non-goals

Explicitly out of scope; do not open tracks for them.

- **ActivityPub federation.** Peer-token API access is the whole federation
  story.
- **Full Komga API parity.** The Komelia/Mihon target profile is the contract;
  persisted settings, artwork CRUD, and event parity beyond Komf's needs are not
  goals ([Komga compatibility](/docs/developer/komga-compat)).
- **DRM removal.** Detection only (`drm_protected`, weight 0, non-blocking); the
  study is `docs/drm-study.md` and the verdict stands.
- **Bundling third-party scraper sources.** The catalog is fetched at runtime;
  no extension code, Kotlin, or APK is ever executed ([Source definitions](/docs/developer/source-definitions)).
- **Any GPL/AGPL code in tree.** Calibre is shell-out only; peer behaviour and
  published specs are the only thing read from BookOrbit, Grimmory, cbzit,
  MangaManager, Sigil, or DeDRM.
