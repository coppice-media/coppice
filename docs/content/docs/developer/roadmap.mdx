# Roadmap

Snapshot 2026-09-07 at `7de64602`. Two sections carry weight: **[Open](#open)**
— five items, each blocked on something nameable — and **[Future](#future)**,
candidates that are neither scheduled nor promised. Everything above them is
history, kept because each phase names the document it came from and because
"done" here means evidence exists, not that a plan said so; the evidence itself

## Open

Five items. Nothing else is in flight, and each of these names what it is
waiting on — none of them is waiting on a design decision.

### 1. Device runs that need hardware or an account we do not have

Blocked on physical access, not on code. The **official Audiobookshelf app**
phone test is the one that matters most, because it is the only way to find out
what the profile still gets wrong for a non-Lissen client, and it needs the
socket.io lane (item 4) before bookmarks can work at all
(`crates/abs/README.md:12`, `docs/audiobook-study.md` §2).

The same blocker covers three smaller gaps, all recorded honestly in
[Current state › verification](/docs/developer/state#verification-per-client): no
physical Kobo has ever run against `/kobo/{api_key}`; `stump.koplugin` has never
been loaded by KOReader on a device; and no Kindle mail has ever been delivered
to a real `@kindle.com` address.

### 2. API keys for Hardcover, Metron, Open Library, Google Books

The four clients are implemented and unit-tested against recorded payloads, and
the editor's API-keys page already stores their tokens, but no live request has
ever been made with a real credential. Until a key exists, their field mappers,
rate-limit handling and error paths are source-level only
([Provider status](/docs/developer/provider-status#metadata-providers),
[Hardcover integration](/docs/developer/hardcover-integration)). User-gated.

### 3. Coppice rename and the upstream split

Rename the fork to **Coppice** (product and repository name; binary and package
names follow later) and split the fork-local additive work into separate
upstreamable PRs against `stumpapp/stump` nightly — core lifecycle and
feature-gate changes first, then the protocol profiles (`komga`, `kavita`,
`kobo`, `koreader`, `liseur-sync`, `abs`, `kindle`), then the provider host with
its theme engines, then ingest and tools. **User-gated, not started**: the name
appears nowhere in the tree, and `.github/CONTRIBUTING.md` still describes the
unchanged upstream flow. Sequencing rationale:
[incremental upstream PR sequence](/docs/developer/server-architecture#incremental-upstream-pr-sequence).

### 4. ABS socket.io lane — in flight

The Engine.IO v4 / Socket.IO v5 lane is **not** in `7de64602`. The protocol is
pinned in `docs/audiobook-study.md` §2 (Socket.IO protocol revision 5,
Engine.IO revision 4, path `/socket.io`, plus a second server under a
router base path), and the official ABS app makes bookmarks unreachable without
it, while Lissen needs none of it. Implementation is under way in this batch;
the contract lives in [ABS compatibility](/docs/developer/abs-compat).

### 5. Ebook ↔ audiobook sync — design accepted, not implemented

`reading_heads` can hold a locator *or* a millisecond offset (`m20260933`), so
both position kinds already round-trip on their own protocols. What does not
exist is a conversion between them: switching from reading to listening does not
move the head. The design is settled and written up in
[Read-aloud, remote workers, and requests](/docs/developer/read-aloud) — tier 1
is chapter + percentage and free, tier 2 is forced alignment on a remote worker
rendered as a Storyteller-compatible EPUB 3 Media Overlays publication on
demand, and the remote-worker protocol (`crates/worker`, `worker_jobs`, workers
dialling *out* over one WebSocket) plus the requests model come with it. Nothing
in that page exists in the tree except the pieces it marks *exists*.

Implementation order, from
[§9 of that page](/docs/developer/read-aloud#9-implementation-order):

1. `pair_editions` + `media_chapter_map` + read-time position conversion
   (tier 1) — `crates/library`, `models::domain::reading_state`, console
   "Also available as".
2. Worker protocol + `crates/worker` + `worker_jobs` + console Workers page,
   with `transcode` first because it has a local fallback and is testable
   without a GPU.
3. `align` job kind + the aligner container + `media_sync_maps` +
   `Media.syncMap`.
4. On-demand read-aloud EPUB route + OPDS link + console highlighting.
5. `requests` table + Requests page + provider-host auto-fulfilment.
6. Storyteller app profile (`crates/storyteller`), evidence-first like ABS.

## Future

Unordered, unscheduled, and some of these will end up non-goals. Peer-shipped
items name the peer, because that peer's *behaviour* is the specification to
read — never its code: BookOrbit and Grimmory are AGPL-3.0 and this tree is MIT.
Every cell behind them is cited in [Feature comparison](/docs/developer/comparison).

### Peers ship it, we do not

- **Achievements.** The console nav is Dashboard, Library, Reading, Annotations,
  Devices, Account (`docs/content/docs/developer/home-app.mdx:64`). Peer:
  BookOrbit.
- **Configurable dashboard.** `/dashboard` is a fixed composition — stat cards,
  a 53-week heatmap, continue-reading and recently-added shelves, device sync,
  job queue — with no user-arranged widgets
  (`docs/content/docs/developer/home-app.mdx:49`). Peers: BookOrbit, Kavita,
  Calibre-Web Automated.
- **Bulk metadata edit outside ingest.** `bulkApplyIngestMetadata` still only
  touches staged drop items. Peer: Calibre-Web Automated.
- **One annotation model.** Native rows and liseur CAS rows are stored side by
  side and surfaced together in the annotation hub, but never reconciled into a
  single head with a repair state. Peer: BookOrbit.
- **Calibre-Web facade for Liseur.** No `/opds/...` web-form contract and no
  Calibre-Web login/token/delete lane
  ([Liseur providers](/docs/developer/liseur-providers)).

### Engineering carried forward

- **Metadata post-processing** (the tail of phase 5): title-language selection,
  book ordering, score tags, publisher tag names, and actually writing the
  chosen cover — `CoverUrl` is outside `STORABLE_FIELDS`, so today's decision
  returns `applied: false`.
- **Processor-sized Cargo features** (the tail of phase 2): `metadata`, `email`,
  and a `pdf-render` split, so a kobo-only or comics-only build stops linking
  PDFium, unrar and the metadata tree.
- **Federation via peer tokens** (phase 8) and the **Komga/Kavita federation
  provider** (the unstarted half of phase 3): a remote host authenticates with a
  revocable scoped token, not a user account. No ActivityPub.
- **wasmtime source sandbox**, deferred until the definition schema and catalog
  flow stop moving.
- **Operations**: a `/metrics` or OpenTelemetry export, a backup/restore
  surface, dependency-specific readiness, and a CI profile matrix for `minimal`,
  `headless,liseur-sync`, default, and a compatibility replay
  (`.github/workflows/ci.yaml` still runs default checks only).
- **CBZ KOReader hash**, still commented out in
  `crates/media/src/media/format/zip.rs:61,68-75`.
- **A liseur-sync attachment blob route**: Kobo markup snapshots and notebooks
  are described (id, anchor, sha256) but not transported, which is a protocol
  change to design rather than an omission to fix.

## Non-goals

Explicitly out of scope; do not open tracks for them.

- **ActivityPub federation.** Peer-token API access is the whole federation
  story.
- **Full Komga API parity.** The Komelia/Mihon target profile is the contract;
  persisted settings, artwork CRUD, and event parity beyond Komf's needs are not
  goals ([Komga compatibility](/docs/developer/komga-compat)).
- **DRM removal.** Detection only (`drm_protected`, weight 0, non-blocking);
  the study is `docs/drm-study.md` and the verdict stands.
- **Bundling third-party scraper sources.** The catalog is fetched at runtime;
  no extension code, Kotlin, or APK is ever executed
  ([Source definitions](/docs/developer/source-definitions)).
- **Any GPL/AGPL code in tree.** Calibre is shell-out only; peer behaviour and
  published specs are the only thing read from BookOrbit, Grimmory, cbzit,
  MangaManager, Sigil or DeDRM.
