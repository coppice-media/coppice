This page is the single record of client-facing verification. A row never claims
more than its evidence:

- **Device-tested** — a person exercised a real app or device against the
  fixture server (`scripts/dev-fixture-server.sh`, headless debug build, LAN or
  emulator address). Date and app version are given where available.
- **Contract-tested** — an external `komga-compat` Hurl replay, reference
  comparison, or server-side probe exercised the wire contract. This proves the
  server contract, not the app.
- **Source-only** — implementation was checked against pinned client source, but
  no run is claimed.
- **Shipped**, **Planned**, and **Blocked** describe product state rather than
  substituting for client evidence.

Only **Device-tested** counts as “works in the app.” Harness/source evidence
never becomes app/device proof. The snapshot below includes runs through
2026-09-07.

## Historical resource observation

`14.5 MB` RSS idle and `110 MB` peak during a parallel KEPUB batch were
recorded from a debug build after five hours of uptime. This is a historical
machine observation, not compatibility proof or a production capacity
guarantee. It is separate from the app/device rows above.

## How a device report is triaged

1. Every failed response logs `method` + `uri` (`TraceLayer` span at DEBUG in
   `apps/server/src/http_server.rs`); read the fixture log via the
   `stump-komga` process logs and match the app's error text to the request.
2. Reproduce with `curl` against the LAN address using the same credentials and
   client headers, then against the pinned client source to confirm the expected
   shape (DTO types, status code).
3. Fix at the adapter boundary (never in Coppice's native routes), add a
   focused test, and pin the shape in the relevant Hurl spec so the class cannot
   regress.
4. Redeploy the fixture (`hub restart stump-komga`), re-run the relevant replay,
   and ask for a retest. Update this page with the exact evidence label.

## Known client-side limits (not Coppice bugs)

- Liseur has no OPDS 2 parser; use the OPDS 1.2 URL.
- Komelia's Readium DTOs are stricter than the Readium spec (`rel` must be a
  string, `published` a calendar date, contributors lists); the Komga alias
  normalizes to those types and native routes keep the spec shapes.
- The `replay-readium` spec needs a book with no existing reading session for
  its `PUT /progression`; on a book the phone has opened it returns `409` by
  design (older timestamp than the live session).
- Kamigura's EPUB image request returns 404 because that client is an image
  reader; Turnleaf/Inkita/Kover are the EPUB-capable Kavita routes in the pinned
  inventory.
- The official Audiobookshelf app's tap-only seek and stale/duplicate download
  queue are client-side interaction states. A clean seek drag and one-track
  download were **Device-tested**; see [Audiobookshelf profile](/docs/developer/abs-compat).
- Kobo stock firmware does not render WebP in CBZ or KEPUB. The required JPEG
  conversion remains **Planned** ([clients](/docs/developer/clients)).
