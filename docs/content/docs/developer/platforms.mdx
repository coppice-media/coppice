This page covers hardware, firmware, external reference systems, and
platform-specific limits. It is not a client evidence matrix: dated app/device
runs and source pins belong in the [client verification matrix](/docs/developer/client-verification).
Client setup, protocol, and authentication notes are in [Client apps](/docs/developer/clients).

Coppice device credentials can carry a per-device `library_scope`; the shared
query funnel enforces it across protocols. See [Devices — library scope](/docs/developer/devices#library-scope).

## Kobo eReaders

Stock Nickel renders JPEG, GIF, PNG, BMP, and TIFF, not WebP in CBZ or KEPUB
([Kobo file formats](https://help.kobo.com/hc/en-us/articles/360017763713-File-formats-your-Kobo-eReader-and-Kobo-Books-app-support)).
Coppice serves ordinary EPUB through Kobo sync. Optional EPUB-to-KEPUB conversion
uses `KOBO_KEPUB_CONVERSION=true`. The separate comics transform can package
CBZ/ZIP/CBR/RAR/PDF pages as CBZ or fixed-layout KEPUB with a device profile;
it is **Shipped** but disabled by default (`STUMP_TRANSFORM_ENABLED=false`).

Stock Kobo initialization, library sync, ReadingState, and KEPUB conversion are
covered in [Kobo sync capabilities](/docs/developer/kobo-sync-capabilities).
Shelf, tag, and tag-item handlers write through to collections and reading
lists. `/auth/device` returns non-persistent compatibility data; stock Kobo
sync has no annotation transport. Physical-device evidence is tracked only in
the [client verification matrix](/docs/developer/client-verification).

Stylus annotations are a separate source-only path. The `nickelcoppice` sibling
repository reads `.kobo/markups` SVG/JPEG files and maps them to annotation side
objects; this is not part of stock Kobo sync and has no device test recorded.
Device database and bookmark details are in
[Kobo device database](/docs/developer/kobo-device-database).

## KOReader

The server's KOSync protocol is available at `/koreader/{api_key}` through
`GET users/auth`, `PUT syncs/progress`, and
`GET syncs/progress/{document}`. Progress uses KOReader's binary partial-MD5
`koreader_hash` for EPUB/PDF; ZIP/RAR media have no hash. The protocol does not
carry annotations and its page/DOM x-pointer is not a Readium locator.

The first-party plugin is `coppice.koplugin` in sibling repository
`koreader-coppice`. Its source reference is KOReader v2026.07.1 at
`9192014d`; it has not been loaded into the native KOReader app. Liseur's
KOReader-sync route is a separate client flow. See
[KOReader sync](/docs/guides/integrations/koreader),
[plugin notes](/docs/developer/koreader-plugin), and the
[client verification matrix](/docs/developer/client-verification).

`NickelMenu` and `NickelDBus` are possible device-side launch/control tools, not
Coppice clients. `NickelHardcover` is an independent stock-Nickel progress
publisher; Coppice has no stock server pull of the device database. Its
read-only data model is documented in [Kobo device database](/docs/developer/kobo-device-database).

## Amazon Kindle

Kindle has no Coppice sync protocol or credential. Delivery is one-way:
Amazon's Send to Kindle service uses the address stored in the device row
(`devices.kindle_email`), while USB sideloading saves an exported file into the
mounted device's `documents/` directory. Neither path returns reading progress
or annotations.

The server can convert accepted EPUB input to AZW3 with the operator-installed
`boko` tool; email delivery can otherwise rely on Amazon's conversion service.
CBZ/CBR are refused for email delivery. The USB route returns a converted file
with `X-Stump-Kindle-Converted`; that header is a compatibility identifier.

## Reference servers and desktop tools

| System | Role in Coppice | Boundary |
| --- | --- | --- |
| Komga | Protocol reference for the Komga compatibility profile. | The current source-query version and replay oracle are separate records; see [Komga compatibility](/docs/developer/komga-compat). |
| Kavita | Reference implementation for Coppice's Kavita-shaped profile. | Profile behavior is documented in [Kavita compatibility](/docs/developer/kavita-compat); client evidence remains per-client in the matrix. |
| Audiobookshelf | Reference API for the REST and Engine.IO/Socket.IO compatibility profile. | Current source pin `2.36.1` (`4b67c170`) and the `2.36.0` replay capture are separate. See [Audiobookshelf compatibility](/docs/developer/abs-compat). |
| Calibre / Calibre-Web | Desktop conversion and Kobo USB workflow; Calibre-Web's Kobo endpoint is a wire-shape reference. | They are external tools/services, not Coppice clients or bundled components. See [Calibre tooling](/docs/developer/calibre-tooling) and [Kobo sync capabilities](/docs/developer/kobo-sync-capabilities). |
| Home and Editor | Active static SvelteKit browser applications served at `/app` and `/editor`. | Separate app assets, not hardware clients; see [modular deployment](/docs/guides/configuration/modular-deployment). |
| `stump-worker` | Remote worker client for jobs such as transcode and configured alignment. | It dials the server's worker socket and uses authenticated input/output routes; see [Workers](/docs/developer/workers) and [read-aloud](/docs/developer/read-aloud). |

For exact client versions, device dates, test scope, and unverified flows, use
the [client verification matrix](/docs/developer/client-verification).
