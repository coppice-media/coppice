This page is the source map for Coppice providers. The evidence labels are
literal: **Shipped**, **Contract-tested**, **Device-tested**, **Source-only**,
**Planned**, and **Blocked**. A source inspection or server replay never becomes
app/device proof; [Client verification](/docs/developer/client-verification)
records that boundary. Integration ownership is summarized in [Integration
architecture](/docs/developer/integration-architecture).

## Metadata providers

Remote clients live in `crates/integrations/metadata/src/{providers/*,mangaupdates.rs}`
and implement `metadata_integrations::MetadataProvider`
(`search_media`/`search_series`, `fetch_*`, `verify_credentials`). The ingest
layer wraps them in `IntegrationProvider`
(`crates/ingest/src/providers/facade.rs:40-224`) and lists them in `INTEGRATIONS`
(`crates/ingest/src/providers/registry.rs:68-140`). Two providers are native to
the ingest contract: `builtin:embedded` and `llm`.

| id | Domain | Key / configuration | Capabilities | Default | Evidence |
| --- | --- | --- | --- | --- | --- |
| `builtin:embedded` | all media kinds, including `Unknown` | none; configured unconditionally | Identify, Lookup | yes | **Shipped**, **Contract-tested** (`builtin_embedded.rs`) |
| `comic_vine` | comics (`Comic` → CBZ/CBR) | API key in `metadata_provider_configs`; [ComicVine API](https://comicvine.gamespot.com/api/) | Identify, Lookup, Search | no | **Shipped**, **Contract-tested** offline |
| `hardcover` | books (`Book` → EPUB/PDF) | Bearer token; [Hardcover API account](https://hardcover.app/account/api) | Identify, Lookup, Search | no | **Shipped**, **Contract-tested** offline; live credential **Blocked** |
| `anilist` | manga (`Manga`, `LightNovel`) | no token | Identify, Lookup, Search | yes | **Shipped**, **Contract-tested** offline |
| `mal` | manga (`Manga`, `LightNovel`, `Webtoon`) | `X-MAL-CLIENT-ID` encrypted token; [MAL API config](https://myanimelist.net/apiconfig) | Identify, Lookup, Search | no | **Shipped**, **Contract-tested** offline |
| `mangadex` | manga (`Manga`, `Manhwa`) | no token | Identify, Lookup, Search | yes | **Shipped**, **Contract-tested** offline |

Provider mappers fill candidate fields; they do not make a catalog/source
provider or fulfillment connector. Series mapping adds fields such as
`alternative_titles`, `status`, `publisher`, `volume_count`, and `age_rating`
where that provider exposes them. The offline test records are not live-vendor
verification.

### Hardcover boundary

Hardcover metadata lookup and field mapping are **Shipped** and
**Contract-tested** against offline payloads. Live credential verification and
the owner-scoped Connections flow are implemented but remain **Blocked** until
an operator supplies a PAT; no external-network smoke is run without one.
Manual journal import is read-only and preserves unresolved provenance when no
exact media link/page locator exists. Progress projection is opt-in and
non-regressing. Remote quote writes are not shipped.

### How the ingest trait works

- **Contract:** `IngestMetadataProvider`
  (`crates/ingest/src/contract.rs:334-365`) exposes `id`, `name`, `version`,
  `supported_media_kinds`, `capabilities`, `settings`, `identify(book,
  settings) -> Vec<ProviderIdentity>`, `lookup(book, identity, settings) ->
  Vec<MetadataCandidate>`, and a default `search` returning
  `ProviderError::Unsupported`. Capabilities are `Identify`, `Lookup`,
  `Search`, `Tags`, and `AiEnrichment` (`contract.rs:305-314`); no built-in
  provider advertises `Tags` or `AiEnrichment`.
- **Settings schema:** `SettingDefinition { key, label, description, kind,
  default, required, secret, help_url }` (`contract.rs:196-211`) reaches the
  editor as `helpUrl` (`crates/graphql/src/object/ingest.rs:799-811`).
  Integration adapters return no settings; `llm` and quality checks define
  their own settings.
- **Credential stores:** token-bearing integrations use
  `metadata_provider_configs` (`encrypted_api_token`, `enabled`, auto-apply
  policy); the registry decrypts through `ProviderClientCache` with the server
  encryption key (`crates/ingest/src/providers/registry.rs:641-667`). Native
  providers such as `llm` use `ingest_plugin_settings` via
  `setIngestProviderSettings`; secret values are redacted on read.
- **Keyless providers:** `requires_api_token: false`
  (`crates/ingest/src/providers/registry.rs:51-55`) means an enabled config row
  counts as configured and scheduling skips the missing-token check. The editor
  lists them in a collapsed “no key” card.
- **Discovery:** `ProviderRegistry::catalog`
  (`crates/ingest/src/providers/registry.rs:166-285`) emits embedded,
  `INTEGRATIONS`, `llm`, and an unavailable descriptor for an unknown persisted
  `PROVIDER` plugin id, sorted by id.

### Facade fan-out and scoring

`identify_and_lookup_selected`
(`crates/ingest/src/providers/registry.rs:303-404`) runs embedded first, then
every selected integration that supports the snapshot kind, has an enabled
config row, and has a token when required. Each provider composes a
`SearchQuery` from embedded title/writer/ISBN/year/number, calls media and
series search, tags each hit with `result_kind`, and sorts by confidence,
external id, and display. `best_identity` keeps confidence `> 0.5`; lookup
normalizes detail through `normalize_metadata`.

`crates/integrations/metadata/src/scoring.rs` defines the common scorer (ISBN
≥ 0.98, exact title ≥ 0.90, alternate title ≥ 0.80, fuzzy 0–0.75, author +0.05).
Every candidate field inherits candidate confidence. Free-text search fans out
concurrently, requires `Search`, and orders hits by score, provider id, and
external id.

### Apply path and policy

Candidates are persisted per drop item or media row
(`crates/ingest/src/store.rs:812-905`) by the coordinator's Identify/Lookup
phases (`crates/ingest/src/coordinator.rs:342-359,433-447`). A user recipe of
`FieldPick`s (`crates/ingest/src/providers/contract.rs:367-396`) is validated,
resolved against the same drop item and source digest, the locked-field list,
and the existing `MergeStrategy`, then written with an audit row in one
transaction. Only `STORABLE_FIELDS` reach `media_metadata`/tags; `CoverUrl` and
`Identifiers` remain candidate-only (`crates/ingest/src/providers/apply.rs:28-46`).

#### What the policy layer covers

The per-field policy is **Shipped** in `crates/ingest/src/policy.rs`: each field
has an ordered provider list, a strategy (`FIRST`, `MERGE_UNION`, `LONGEST`,
`PREFER_EXISTING`, `HIGHEST_RESOLUTION`), and `lock_respected`, with a server
default and a per-library override in `library_configs.metadata_policy`.
Design and mapping: [Modular ingest — Policy](/docs/developer/modular-ingest#policy).

| Policy item | Evidence | Notes |
| --- | --- | --- |
| Field/provider priority | **Contract-tested** | `FieldPolicy { providers, strategy, lock_respected }`; offers are collected in list order, then by confidence (`priority_order_decides_the_winner`) |
| Merge tags/genres | **Contract-tested** | `MERGE_UNION` unions stored and provider values case-insensitively, keeping first spelling (`union_dedupes_case_insensitively_and_keeps_stored_values`) |
| Title language preference | **Planned** | Current choices are fixed per client (AniList English → Romaji → native; MangaDex `en` → `ja-ro`); no user setting |
| Cover pick / thumbnail replacement | **Shipped**, **Planned** | `HIGHEST_RESOLUTION` ranks candidates and is the `COVER` default, but `CoverUrl` is outside `STORABLE_FIELDS`, so the decision returns `applied: false`; writing the chosen cover is **Planned** |
| Per-library provider rules | **Contract-tested** | `library_configs.metadata_policy` overrides server defaults; `metadataPolicy`/`setMetadataPolicy` and the editor Policy tab read/write it |
| Auto-match | **Contract-tested** | `approveIngestItem` stages the policy plan as pending fields; `applyBestIngestMetadata` runs the same resolver on demand |

### Remaining metadata providers

MangaBaka and BookWalker DB (manga) are **Planned**; port them with the same
module-header pin used for AniList/MangaUpdates. They remain metadata providers,
not remote catalog fulfillment.

## Catalog/source providers are separate

Catalog/source providers own popular/latest/search/details/chapters/pages and
materialized or virtual remote content. They are not this metadata registry.
The current host and source definitions live in `crates/provider`,
`crates/provider-mangadex`, and `crates/provider-themes`; their source contract
is documented in [Provider host](/docs/developer/provider-host) and [Source
definitions](/docs/developer/source-definitions). Storyteller is not a catalog or
metadata provider. Acquisition is deferred and outside this registry; any future
integration must use a separate authenticated provider sidecar. See [Integration
architecture](/docs/developer/integration-architecture).

## Common feature gates and settings

`apps/server/Cargo.toml` makes `headless` include `opds`, `kobo`, `koreader`,
`komga`, and `liseur-sync`; `kobo` also enables `stump_kepub`. Runtime mounting
differs by provider: KOReader, Kobo, Komga, Kavita, and ABS check runtime
settings; liseur-sync and OPDS mount whenever their Cargo features are compiled.
The setting names intentionally are not uniform: `ENABLE_KOBO_SYNC`,
`ENABLE_KOREADER_SYNC`, and `ENABLE_OPDS_PROGRESSION` have no `STUMP_` prefix,
while `STUMP_ENABLE_KOMGA`, `STUMP_ENABLE_KAVITA`, and `STUMP_ENABLE_ABS` do.

| Provider or setting | Cargo feature | Env key | TOML key | Effect | Evidence |
| --- | --- | --- | --- | --- | --- |
| Komga | `komga` | `STUMP_ENABLE_KOMGA` | `enable_komga` | Mounts the root Komga profile and `/komga` Grimmory alias; both feature and setting gates are required | **Shipped**, **Contract-tested** |
| Kavita | `kavita` | `STUMP_ENABLE_KAVITA` | `enable_kavita` | Mounts `/api` Kavita routes when both gates are open | **Shipped**, **Contract-tested** |
| Audiobookshelf | `abs` | `STUMP_ENABLE_ABS` | `enable_abs` | Mounts root ABS routes when both gates are open | **Shipped**, **Contract-tested** |
| OPDS routes | `opds` | — | — | Mounts `/opds/v1.2` and `/opds/v2.0`; compile-time only | **Shipped**, **Contract-tested** |
| KOReader | `koreader` | `ENABLE_KOREADER_SYNC` | `enable_koreader_sync` | Mounts `/koreader/{api_key}/*`; both gates are required | **Shipped**, **Contract-tested** |
| Kobo | `kobo` + `stump_kepub` | `ENABLE_KOBO_SYNC` | `enable_kobo_sync` | Mounts `/kobo/{api_key}/*`; both gates are required | **Shipped**, **Contract-tested** |
| liseur-sync | `liseur-sync` | — | — | Mounts the native `/v1/...` protocol; no runtime gate | **Shipped**, **Contract-tested** |

If a runtime setting is true while its Cargo feature is absent, no route is
mounted; the configuration warning is not compatibility evidence. See [Server
architecture](/docs/developer/server-architecture) for the complete profile
matrix, including the lean base, `minimal=["formats"]`, and WebUI → GraphQL
implication.

## Komga, OPDS, Kobo, KOReader, and liseur-sync status

The protocol pages below summarize the current boundaries; each is **Shipped**
with the contract evidence linked in the table above:

- **Komga:** `/api/v1/*`, `/api/v2/*`, and `/sse/v1/events`; Komelia/Mihon
  profile, Basic/Bearer/session/API-key auth, remember-me cookie, Readium
  positions, Tachiyomi tracker, metadata writes, and mutation SSE. Full Komga
  parity remains **Planned** and is not implied.
- **OPDS 1.2:** `/opds/v1.2/*` plus the key-in-path alias; Basic/session/API-key
  auth, catalog/search/acquisition, PSE pages, and optional
  `ENABLE_OPDS_PROGRESSION=true`. Strict compliance and additional facets are
  **Planned**.
- **OPDS 2.0:** `/opds/v2.0/*`; JSON catalog, auth document, acquisition, and
  explicit progression GET/PUT. Every feed pages on `page`/`page_size`, search
  has a paged route per kind (`/libraries/search`, `/series/search`,
  `/books/search`), and a feed links only to pages and routes that exist.
  Facets, chapter/resource streaming, and a v2 key-in-path alias are
  **Planned**.
- **Kobo:** `/kobo/{api_key}/*`; initialization, sync, ReadingState, metadata,
  thumbnails, EPUB/KEPUB and `Range`. Device-auth persistence, tags/shelves,
  annotations, and physical-device verification are **Blocked** or **Planned**
  as recorded in [Client verification](/docs/developer/client-verification).
- **KOReader:** `/koreader/{api_key}/users/auth`, progress PUT, and progress
  GET by document hash; binary partial-MD5 matching for EPUB/PDF when library
  hash generation is enabled. Filename-MD5, ZIP/RAR hashes, x-pointer
  translation, and device-management UI are **Planned**.
- **liseur-sync:** `/v1/*`; login, token lifecycle, work/edition resolution,
  positions, changes, heads, sessions, CAS annotations, and device catalog.
  Attachment blobs, upload/delete, insights, and series claims are **Planned**;
  Kobo markup is described but not transported.
