This page is the source map for Stump's compatibility providers. **[observed]** means the
route, setting, or behavior is present in this worktree. **[inference]** marks a conclusion
or recommendation drawn from observed source. **[future]** marks a capability that is not
implemented. In the tables below, `implemented`, `partial`, and `future` describe the
current implementation status, not a protocol's theoretical capabilities.

## Metadata providers

Remote clients live in `crates/integrations/metadata/src/{providers/*,mangaupdates.rs}` and
implement `metadata_integrations::MetadataProvider` (`search_media`/`search_series`,
`fetch_*`, `verify_credentials`). The ingest layer wraps them in `IntegrationProvider`
(`core/src/ingest/providers/facade.rs:40-224`) and lists them in `INTEGRATIONS`
(`core/src/ingest/providers/registry.rs:68-140`). Two providers are native to the ingest
contract: `builtin:embedded` and `llm`. The Komf reference is master `428dac6`
(`komf-core/src/commonMain/kotlin/snd/komf/providers/`), cited only where the Rust module
header names it.

### How the trait works

- **Contract.** `IngestMetadataProvider` (`core/src/ingest/contract.rs:334-365`): `id`, `name`, `version`, `supported_media_kinds`, `capabilities`, `settings`, `identify(book, settings) -> Vec<ProviderIdentity>`, `lookup(book, identity, settings) -> Vec<MetadataCandidate>`, and a default `search` that returns `ProviderError::Unsupported`. Capabilities are `Identify`, `Lookup`, `Search`, `Tags`, `AiEnrichment` (`contract.rs:305-314`); no built-in provider advertises `Tags` or `AiEnrichment`.
- **Settings schema.** `SettingDefinition { key, label, description, kind, default, required, secret, help_url }` (`contract.rs:196-211`); `help_url` reaches the editor as `helpUrl` (`crates/graphql/src/object/ingest.rs:799-811`). Integration adapters deliberately return no settings (`facade.rs:96-101`); only `llm` (`llm.rs:113-166`) and the quality checks define any.
- **Two credential stores.** Token-bearing integrations use the existing `metadata_provider_configs` row (`encrypted_api_token`, `enabled`, auto-apply policy); the registry decrypts through `ProviderClientCache` with the server encryption key (`registry.rs:641-667`). Provider-level `helpUrl` for that store is a hard-coded map in `crates/graphql/src/object/ingest.rs:671-686`. Native providers (`llm`) persist `ingest_plugin_settings` rows via `setIngestProviderSettings` (`crates/graphql/src/mutation/ingest.rs:80-119`); secret values are redacted on read (`object/ingest.rs:822-843`). **[observed]** That write path stores `values` as plain JSON; the encryption promised by the `secret` doc comment (`contract.rs:205`) is not visible in `save_plugin_settings`.
- **Keyless providers.** `requires_api_token: false` (`registry.rs:51-55`) means a config row with `enabled = true` counts as configured (`registry.rs:169-180`) and scheduling skips the missing-token check (`registry.rs:361-367`). The editor's API-keys page lists them in a collapsed "no key" card (`editor/src/routes/(app)/settings/keys/+page.svelte:271-276,393-436`).
- **Discovery.** `ProviderRegistry::catalog` (`registry.rs:166-285`) emits embedded, `INTEGRATIONS`, `llm`, then an `available: false` descriptor for any persisted `PROVIDER` plugin id it does not know, sorted by id. **[observed]** `unknown_plugin_ids` treats only embedded and `INTEGRATIONS` ids as known (`registry.rs:594-618`), so an `llm` settings row also produces a second, unavailable `llm` descriptor; the registry test uses empty rows and does not cover this (`registry.rs:742-811`).

### Facade fan-out and scoring

`identify_and_lookup_selected` (`registry.rs:303-404`) runs embedded first, then every `INTEGRATIONS` entry that supports the snapshot kind (`registry.rs:685-698`), is in the optional allowlist, has an enabled config row, and has a token when required. Per provider: `identify` composes one `SearchQuery` from embedded title/writer/ISBN/year/number with the filename parse as fallback (`facade.rs:241-268`), calls `search_media` **and** `search_series`, tags each hit with `result_kind`, and sorts by confidence desc, external id, display (`facade.rs:103-150`). `best_identity` keeps only confidence `> 0.5` and takes the first (`registry.rs:670-683`); `lookup` fetches the media or series detail and normalizes it through `normalize_metadata` (`facade.rs:152-201,371-401`). Failures are logged and isolated per provider. **[observed]** `llm` is catalogued and verifiable (`registry.rs:534-536`) but is not part of this loop or of `search` (`registry.rs:409-470`); the LLM module itself documents the missing `rank_candidates` hook (`llm.rs:16-20`).

Confidence comes from the wrapped client's `MatchScorer` (`crates/integrations/metadata/src/scoring.rs:8-35`: ISBN ≥ 0.98, exact title ≥ 0.90, alt title ≥ 0.80, fuzzy 0–0.75, author +0.05). Every field in a candidate inherits the candidate confidence (`facade.rs:387-390`). Free-text search fans out concurrently with `join_all`, requires the `Search` capability, and orders hits score desc, provider id, external id (`facade.rs:319-369`); unscored hits fall back to `title_similarity` (`facade.rs:292-317`; `scoring.rs:98-103`).

The mapper (`facade.rs:403-482`) produces `MetadataField` values: Title, Summary, Series, SeriesIndex, Authors (from `writers` only), Genres, Tags, Isbn (`isbn` else `isbn_13`), PublishedDate (`YYYY[-MM[-DD]]`), PageCount, CoverUrl, Identifiers (`{provider, externalId, url}`); series candidates add AgeRating when numeric. **[observed]** `Publisher`, `Language`, `SortTitle`, and the artist/colorist/letterer credits are never emitted by this mapper even when the client fills them.

### Apply path

Candidates are persisted per drop item or per media row (`core/src/ingest/store.rs:812-905`) by the coordinator's Identify/Lookup phases (`core/src/ingest/coordinator.rs:342-359,433-447`). A user recipe of `FieldPick`s (`contract.rs:367-396`) is validated (`core/src/ingest/providers/apply.rs:71-110`), resolved against the candidate rows with the same drop item and source digest, the locked-field list, and the existing `MergeStrategy` (`apply.rs:144-221`; strategies in `crates/integrations/metadata/src/merge/config.rs:11-21`), then written with an audit row in one transaction (`apply.rs:420-509`). Only `STORABLE_FIELDS` reach `media_metadata`/tags; `CoverUrl` and `Identifiers` stay candidate-only (`apply.rs:28-46`). `approve` merges pending picks and commits together with the source move (`store.rs:566-603`).

### What the policy layer covers

**[observed]** The per-field metadata policy is implemented in
`crates/ingest/src/policy.rs`: per field an ordered provider list, a merge
strategy (`FIRST`/`MERGE_UNION`/`LONGEST`/`PREFER_EXISTING`/`HIGHEST_RESOLUTION`),
and `lock_respected`, with the server default in code and a per-library
override in `library_configs.metadata_policy`. Design and Komf mapping: [modular
ingest — Policy](/docs/developer/modular-ingest#policy). Komf's remaining
*post-processing* (title language selection, book ordering, score tags,
publisher tag names) is still unimplemented; roadmap owner: [Phase 5 — native
metadata engine](/docs/developer/roadmap#phase-5--native-rust-metadata-engine).

### KOReader matching: binary versus filename

At pinned KOReader commit `009367df7ac7142bc0d1eb5782d061260b11baa6`, `main.lua` defines
`CHECKSUM_METHOD.BINARY = 0` and `FILENAME = 1`, defaults `checksum_method` to
`CHECKSUM_METHOD.BINARY`, and presents the menu labels “Binary. Only identical files will be
kept in sync.” and “Filename. Files with matching names will be kept in sync.”:

- Enum and default: `https://github.com/koreader/koreader/blob/009367df7ac7142bc0d1eb5782d061260b11baa6/plugins/kosync.koplugin/main.lua#L46-L67`
- Menu labels: `https://github.com/koreader/koreader/blob/009367df7ac7142bc0d1eb5782d061260b11baa6/plugins/kosync.koplugin/main.lua#L421-L440`
- Digest selection: `https://github.com/koreader/koreader/blob/009367df7ac7142bc0d1eb5782d061260b11baa6/plugins/kosync.koplugin/main.lua#L666-L691`

**[observed]** In `getDocumentDigest`, Binary returns
`self.ui.doc_settings:readSetting("partial_md5_checksum")`; Filename takes the basename from
the document path and returns `md5(file_name)`. Therefore Binary is the Stump-compatible mode;
Filename is not supported by Stump. The pinned digest-selection source is
`https://github.com/koreader/koreader/blob/009367df7ac7142bc0d1eb5782d061260b11baa6/plugins/kosync.koplugin/main.lua#L666-L691`.

Stump's `generate_koreader_hash` samples 1 KiB at offset 0 and then offsets
`1024 << (2*i)` for `i = 0..10`: `core/src/filesystem/hash.rs:68-105`. EPUB and PDF processors
call it only when `generate_koreader_hashes` is true: `core/src/filesystem/media/format/epub.rs:72-90`;
`pdf.rs:56-74`. ZIP/CBZ generation is visibly commented out at
`core/src/filesystem/media/format/zip.rs:60-73` and returns `None`; RAR does the same at
`rar.rs:126-145`. The library flag defaults false: `crates/models/src/entity/library_config.rs:31-37,112-119`.

**[observed]** Stump has unit vectors matching the KOReader EPUB/PDF fixtures:
`https://github.com/koreader/koreader/blob/009367df7ac7142bc0d1eb5782d061260b11baa6/spec/unit/util_spec.lua#L338-L345`.
**[inference]** Stump's implementation consumes a fixed zero-filled 1 KiB buffer for a short
final read, whereas current KOReader hashes only the bytes returned by `file:read(size)`:
`https://github.com/koreader/koreader/blob/009367df7ac7142bc0d1eb5782d061260b11baa6/frontend/util.lua#L1109-L1125`.
Ordinary EPUB/PDF vectors match, but exact identity for short or truncated sampled reads is a
narrow caveat.
