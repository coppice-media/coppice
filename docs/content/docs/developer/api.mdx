The core API which a Coppice server exposes is a GraphQL API. There are some
RESTful endpoints, as well, but these are generally reserved for integrations
and features which require them (for example, fetching thumbnails). Protocol
adapters and their evidence are mapped in the [integration
architecture](/docs/developer/integration-architecture). The API is backed by
several [authentication methods](#authentication).

The API is constantly being developed. It is generally stable, but remains
subject to change.

## Authentication

### Sessions

Coppice uses server-side sessions to authenticate users. These sessions are
stored in the database. The expiry sweep runs every 24 hours by default, so an
expired session is removed by a later sweep rather than exactly at its expiry
timestamp. Set `SESSION_EXPIRY_CLEANUP_INTERVAL` to change the sweep interval.
See the [configuration guide](/docs/guides/configuration/server-config).

### Basic Authentication

<Callout type="warning">
	Basic authentication is accepted only on the OPDS and Komga compatibility paths. It is not
	a general authentication method for native REST or GraphQL routes.
</Callout>

Coppice always accepts valid Basic credentials on OPDS paths. The
`X-Stump-Save-Session: true` compatibility header controls whether that OPDS
login also creates a server-side session; it never controls whether Basic
authentication itself is accepted. Komga-shaped paths use their own
Basic/remember-me session behavior, including the logout exception documented
in the [Komga contract](/docs/developer/komga-compat).

### JWT Tokens

Short-lived JWT access tokens are available for API access, aimed at better
enabling third-party applications and extensions to interact with Coppice. There
are also longer-lived refresh tokens that can be used to obtain new access
tokens, but cannot be used to authenticate requests.

#### JWT Generation

The generation of JWTs is fairly standard. Each type of token (access and
refresh) is encoded with its own unique secret, and the payload is signed using
the HS256 algorithm. The important bit to highlight here is that Coppice
generates two secrets for you on boot and stores them in the database. If you
need to rotate these secrets for any reason, you can do so by deleting them from
the database. They will be automatically regenerated on the next boot, but note
that all existing tokens will effectively be invalidated.

### API Keys

<Callout title="Permission required">
	This functionality is gated behind the `ACCESS_API_KEYS` user permission. To learn more about
	permissions, see the [permissions](/docs/guides/access-control/permissions) guide.
</Callout>

You can generate user-scoped API keys to authenticate requests to the REST API.
These keys are stored in the database and can be revoked at any time. API keys
are not subject to the same expiry as sessions and are intended for long-term
use.

#### Special API Key Routes

There are instances where you can embed an API key in the URL directly. This is
only available for features and integrations where passing the key in a header
is otherwise impossible:

- `/koreader/{api_key}/*` — Used for the [KOReader sync](https://koreader.rocks)
  integration. See [KOReader](/docs/guides/integrations/koreader) for setup details.
- `/kobo/{api_key}/*` — Used for the [Kobo sync](/docs/guides/integrations/kobo)
  integration.
- `/opds/{api_key}/v1.2/*` — Optional OPDS 1.2 routes for clients which do not
  support authentication headers.

For more information on API keys, see the [API keys](/docs/guides/features/api-keys)
guide.

## GraphQL Playground

The playground is available at `http(s)://your-server(:10801)/api/graphql` when
the effective web UI profile is enabled and either the server is running in
debug mode or the `enable_playground` config variable is set to `true`. Headless
builds and servers running with `STUMP_ENABLE_WEBUI=false` do not mount the
playground route.

If you're new to GraphQL, I would recommend giving the [GraphQL
documentation](https://graphql.org/learn/) a quick read, and then trying out the
playground.

### Disabling GraphQL Playground

For release builds with the web UI enabled, set `STUMP_ENABLE_PLAYGROUND=false`
to disable the playground. Debug builds enable it whenever the web UI is
enabled; set `STUMP_ENABLE_WEBUI=false` or use a headless build to remove
browser UI routes. See the [configuration guide](/docs/guides/configuration/server-config)
for more information.

## Compatibility APIs and tested apps

Protocol adapters are public compatibility contracts, but evidence is scoped to
the listed routes and clients:

| API surface | Implementation | Best current evidence | Important limit |
| --- | --- | --- | --- |
| Native GraphQL/REST/Readium | Shipped | Device-tested through Coppice clients | A first-party run does not prove a third-party protocol profile. |
| Komga-shaped API | Shipped | Device-tested and Contract-tested with Komelia, Grimmory, and Mihon flows | Not full Komga parity. |
| Kavita-shaped API | Shipped | Device-tested and Contract-tested with Turnleaf/Kamigura flows | Other Kavita clients remain Source-only unless listed separately. |
| OPDS 1.2/PSE | Shipped | Device-tested and Contract-tested with Liseur | Generic OPDS clients are not blanket-certified. |
| OPDS 2.0 | Shipped | Contract-tested | No universal app/device claim. |
| Kobo sync/KEPUB | Shipped | Contract-tested | Physical Kobo testing remains Blocked. |
| KOReader/KOSync | Shipped | Contract-tested; Liseur sync is Device-tested | Native KOReader and `stump.koplugin` remain Source-only/Blocked. |
| liseur-sync | Shipped | Device-tested and Contract-tested with Liseur | Attachment blobs are not transported. |
| Audiobookshelf-compatible REST | Shipped | Device-tested and Contract-tested with Lissen | The official Audiobookshelf app remains Blocked on the missing Engine.IO/Socket.IO lane. |

These labels never promote a source review or replay into physical-client
support. Exact versions, dates, route coverage, and known failures live in
[Client verification](/docs/developer/client-verification); the human summary is
[Compatibility and integration status](/docs/guides/integrations/compatibility).
