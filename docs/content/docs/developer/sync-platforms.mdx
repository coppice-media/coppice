This page describes Coppice's current server-side synchronization contracts.
Client versions, device dates, and test scope belong in the
[client verification matrix](/docs/developer/client-verification); client setup
belongs in [Client apps](/docs/developer/clients).

## Shared authentication boundary

KOReader and Kobo put a full API key in the URL path rather than sending a
bearer credential. Their adapters validate the key and then apply the
protocol-specific permission: `AccessKoreaderSync` or `AccessKoboSync`. A key
owner must be the server owner or retain `AccessApiKeys`; custom key permissions
replace inherited user permissions. The KOReader username/password fields are
not used for authentication because its legacy MD5 password form does not match
Coppice's API-key scheme.

Both adapters are optional Cargo features and have runtime configuration
switches. The release defaults are disabled; debug defaults are enabled. The
server mounts each router only when its runtime switch is active. Feature and
configuration definitions live in `apps/server/Cargo.toml` and
`core/src/config/protocols.rs`.

## KOReader progress sync

The adapter exposes three routes under `/koreader/{api_key}`:

| Method and path | Contract |
| --- | --- |
| `GET /users/auth` | Returns `{ "authorized": "OK" }` after key and permission checks. |
| `PUT /syncs/progress` | Accepts `document`, `progress`, `percentage`, `device`, and `device_id`; stores the progress for the authenticated user and returns a timestamp. |
| `GET /syncs/progress/{document}` | Reads the current user's progress for the KOReader document hash. Absent optional values are omitted. |

`document` matches the optional `media.koreader_hash`, generated for EPUB and
PDF by the media processors when enabled. ZIP and RAR do not currently receive
a KOReader hash. Numeric `progress` is interpreted as a page; a non-numeric
page string or KOReader DOM x-pointer is preserved verbatim. An x-pointer is
not a Readium locator. Percentage uses KOReader's `0..=1` range; timestamps
are milliseconds since the Unix epoch.

A PUT updates the device record and the shared reading-session service. The
session stores the KOReader progress string separately from its normalized
page/percentage state. On GET, an active `Reading` session wins; a finished
session returns `percentage: 1.0` without a progress string; no session returns
the document identity only.

KOSync is progress-only. Its routes and DTOs carry no annotation, note,
bookmark, or portable locator object. `coppice.koplugin` in sibling repository
`koreader-coppice` is source-derived against KOReader v2026.07.1 (`9192014d`);
it has not been loaded into the native app. Liseur's KOSync flow is a separate
client and evidence record.

## Kobo sync

Kobo uses a path-scoped key at `/kobo/{api_key}`. The adapter serves
initialization, library sync, ReadingState, metadata, thumbnails, book access,
and tag/shelf routes. The `POST /v1/auth/device` response is compatibility data
only: it returns generated token-like identifiers but does not persist device
authentication or create a login session.

`GET /v1/initialization` rewrites the advertised library, state, metadata, tag,
profile, and book-access resource URLs to the Coppice key-scoped routes. Store
account, product, and other store-only resources remain official Kobo URLs.
The compatibility `x-kobo-apitoken` value is not a second authentication
credential.

`GET /v1/library/sync` returns a JSON array and a server-generated
`x-kobo-synctoken`. A full sync sends visible media; subsequent tokens represent
an incremental or incomplete sync. The device ID and optional `x-kobo-*`
metadata are retained with the persisted sync session. The server can emit
`NewEntitlement`, `ChangedProductMetadata`, and `ChangedReadingState` items.

`GET` and `PUT /v1/library/{book_id}/state` read and write Kobo ReadingState.
PUT accepts `ReadingStates[0]`, applies its progress/location/status fields to
the current user's reading state, and retains the native payload in
`reading_sessions.kobo_state`; GET reconstructs the one-element response.
Shelf/tag and tag-item calls are write-through operations that create or update
collections and reading lists, retain `source_device` provenance, and use
delete tombstones. They are not empty-success stubs.

Stock Kobo sync does not transport annotation objects or pull
`KoboReader.sqlite`. Its ReadingState progress/location fields are not a
bookmark/highlight API. `nickelcoppice` contains a separate source-derived
reader for device `.kobo/markups` data; that is not a stock-server annotation
import and has no device run recorded.

Ordinary EPUB remains the default delivery. `KOBO_KEPUB_CONVERSION=true`
enables the optional pure-Rust EPUB-to-KEPUB converter. The comics transform
is a separate shipped feature, disabled by default with
`STUMP_TRANSFORM_ENABLED=false`. KEPUB byte-parity evidence and the separate
36-book / 37 MB performance measurement are documented in
[Kobo sync capabilities](/docs/developer/kobo-sync-capabilities); neither is a
physical Kobo test.

## Native EPUB bookmarks and annotations

Coppice's native GraphQL annotation model is distinct from the KOReader and
Kobo protocol adapters. `media_annotations` stores a required `ReadiumLocator`,
optional annotation text, media/user IDs, and timestamps. `bookmarks` stores
optional preview text, a locator or page, media/user IDs, and creation time.
Queries filter by both the authenticated user and media.

| GraphQL surface | Behavior |
| --- | --- |
| `createBookmark(input: BookmarkInput!)` | Creates a user-owned bookmark with a `ReadiumLocator` and optional preview. |
| `deleteBookmark(id: String!)` | Deletes only the authenticated user's bookmark. |
| `createAnnotation(input: CreateAnnotationInput!)` | Creates a user-owned highlight/note with a `ReadiumLocator` and optional text. |
| `updateAnnotation(input: UpdateAnnotationInput!)` | Updates note text after filtering by annotation and authenticated user. |
| `deleteAnnotation(id: String!)` | Deletes only the authenticated user's annotation. |
| `bookmarksByMediaId(id: ID!)`, `annotationsByMediaId(id: ID!)` | Return only the current user's rows for that media. |

The relevant implementation is in `crates/models/src/entity/media_annotation.rs`,
`crates/models/src/entity/bookmark.rs`, and `crates/graphql/src/{input/media.rs,mutation/epub.rs,query/epub.rs}`.
Neither stock KOReader KOSync nor Kobo sync writes those GraphQL rows.

Liseur-sync has a separate CAS annotation store with opaque locators and
conflict/tombstone behavior. Its attachment routes and storage also ship, but
current attachment evidence is source/contract-level rather than a client
device test. See [Liseur sync integration](/docs/developer/liseur-sync-integration)
and the [client verification matrix](/docs/developer/client-verification).
