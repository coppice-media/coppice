**Shipped:** edition pairing, the free
chapter/percentage map, the generic worker protocol, strict pair-scoped
`SyncMapV1` import/enqueue, source-EPUB native SMIL import, the optional
worker-local Storyteller delegate, an operator-configured external native
CPU/fp32 CTC runner, and server-finalized deterministic read-aloud EPUB
delivery. The `align` wire contract and `SyncMapV1` validator live in
`crates/worker`; the host validator checks the exact requester, pair, source
digests, durations, output bytes, and prepared EPUB targets before persisting a
map and publishing its cache. `Media.syncMap`, `Media.readAloud`, the
authenticated status/download routes, and cache-only OPDS acquisition links
never enqueue work or run ML. An in-process Rust model runtime, virtual
composite delivery, and readiness quality checks remain **Planned**. The
metadata-backed request ledger, permissions, per-user visibility,
approval/rejection decisions, notifications, and social handoff are
**Shipped**. Acquisition is deferred and is not part of the read-aloud worker
contract. Storyteller and native model paths stay in the worker process and
never enter the server or job payload.

**Integration status:** The implementation and its focused read-aloud tests are
green in the 2026-09-22 full Rust/Bun/build gate. This is source and automated
contract evidence, not physical-reader playback proof.

The three rows below are **cost/input tiers, not three independent product
features**. Coppice ships the deterministic first tier, strict native SMIL
reuse, and optional Storyteller or external native CTC worker backends; it has
no in-process ML alignment engine. Tier 2 remains one product capability with
replaceable worker backends; tier 3 is audiobook-only ASR and remains out of
scope.

## 1. The problem in one table

| Have | Want | Evidence / cost tier |
| --- | --- | --- |
| an audiobook (`media_audio`, chapters) and the same book as an EPUB | “you were at 41 % of chapter 7 on the phone” → open the EPUB there, and back | **Shipped** — chapter + percentage |
| both, plus a worker | sentence-level sync: tap a sentence, hear it; playback highlights text | **Shipped** — explicit alignment, validated `SyncMapV1`, and cached EPUB 3 delivery; synchronized console playback remains separate |
| only the audiobook | a transcript / search | out of scope — full ASR is not a read-aloud prerequisite |

The canonical portable output for the alignment tier is **EPUB 3
Media Overlays** (SMIL) — the format Storyteller produces and Readest/Thorium
consume. SMIL is the timing document inside the EPUB: it pairs one XHTML
fragment with one audio interval. It is neither the complete audiobook EPUB nor
Coppice's compact internal `SyncMapV1`; Coppice validates the latter and
deterministically renders the former from an accepted map.

## 2. Pairing: which audiobook is which ebook

Neither ISBN nor ASIN is a safe key on its own: print, ebook and audio editions
carry different ISBNs, and audiobooks usually carry an Audible ASIN and no ISBN.
The key is the **work**, and the tree already has one.

| Piece | Evidence | Where |
| --- | --- | --- |
| `works` / `editions` / `aliases` / `media_links` (a work has editions; a media row links to an edition by identifier) | **Shipped** (liseur-sync model, `POST /v1/works/resolve`) | `crates/migrations/src/m20260904_000000_add_liseur_sync.rs`, `apps/server/src/routers/liseur_sync/` |
| identifiers on media metadata: `identifier_isbn`, `identifier_amazon`, `identifier_google`, `identifier_mobi_asin`, `identifier_calibre`, `identifier_uuid` | **Shipped** | `crates/models/src/entity/media_metadata.rs` |
| Audible ASIN from the `audible` provider | **Shipped** | `crates/integrations/metadata/src/providers/audible.rs` |
| **Pairing rule**: two media rows are the same work when (a) they link to the same work id, or (b) an identifier matches through a provider's edition list (Audnexus and OpenLibrary both expose “other editions”), or (c) normalised `title + first author` match and the user confirms | **Shipped** | `crates/library` (`pair_editions`), surfaced as `Media.editions: [Media]` in GraphQL and an “Also available as” row in the console |

**Shipped:** same work id; identifier through a provider's edition list
(Audnexus `GET /books/{asin}` → the print ISBN; Open Library
`/isbn/{isbn}.json` → `works[…]` → `/works/{id}/editions.json`); and normalised
`title + first author` as a suggestion.
`stump_library::editions::pair_editions` computes the rules on demand and
caches every verdict; `metadata_integrations::editions::EditionLookup` is the
provider half.

Pairing is a suggestion until confirmed; a confirmed pair is a `media_links`
row. There is no pair table: a pair is two `liseur_sync_media_links` rows for
one user sharing a `work_id`, and `m20260946` adds the two columns the liseur
lane cannot carry — `pair_status` (`confirmed` | `suggested` | `rejected`,
defaulting to `confirmed` so every existing row keeps its meaning) and
`pair_evidence`. A rejection is a row, not a deletion, because suggestions are
recomputed on every book-page query. `resolution_status` is not the carrier: it
means “was the edition digest verified against the file” and the liseur lane
rewrites it on every re-resolve.

The ebook is always the **canonical text**; the audiobook is the canonical
**time**.

## 3. Tier 1 - chapter + percentage (free)

No compute, no worker, no storage beyond a chapter map. Both sides already have
chapters: the EPUB's nav/TOC (spine items, character counts per item are
computed by the Readium positions generator — **Shipped**,
`crates/media/src/media/readium.rs`) and the audiobook's
`media_audio_chapters`.

1. **Chapter map** — match chapter lists by normalised title, then by ordinal
   when titles are unhelpful (“Chapter 12” ↔ “12”); front/back matter without a
   counterpart (dedication, credits) is skipped, not forced. Stored once per
   pair as `media_chapter_map`
   `(pair_id, ebook_spine_index, audio_chapter_index, confidence)`.
2. **Position conversion** — audio → ebook:
   `f = (t − chapter.start_ms) / chapter.duration_ms`, then a Readium locator at
   `f` of the mapped spine item's character count. Ebook → audio: the inverse
   from `locations.progression` inside the spine item.
3. **Accuracy** — narrators are not metronomes, so this is ±1–3 min on a
   30-minute chapter; good enough for “resume near here”, never for highlighting.
   The console shows the converted position as *approximate* and the unified
   head records no derived position.

**Shipped** (readiness remains **Planned**): `media_chapter_map`
(`m20260946`), normalised-title match then ordinal/position fallback, front/back
matter skipping and per-entry `confidence`
(`stump_library::editions::build_chapter_map`), both position conversions
(`models::domain::reading_state::{map_time_to_locator,map_locator_to_time}`),
console “Also available as” with **Open here** and an *approximate* badge,
GraphQL `Media.editions`, `Media.editionSuggestions`,
`Media.pairedPosition(fromMediaId)`, `chapterMap`,
`confirmEditionPair` / `rejectEditionPair`, and `setChapterMapEntry`.

Two deviations from the sketch above are deliberate:

- The map is keyed by `(ebook_media_id, audio_media_id, ebook_spine_index)`
  rather than by a `pair_id`. A pair has no row of its own to point at, so
  there is nothing a `pair_id` could reference; the composite unique index is
  what makes recomputing idempotent and one entry editable.
- The head records nothing. A mapped position is a `MappedPosition`, a type
  that cannot reach `reading_state::resolve`, so no derived position can
  overwrite a real position. See `docs/developer/unified-reading-state.mdx`
  § Mapped positions.

Where it plugs in: GraphQL `Media.pairedPosition(fromMediaId)` loads the source
reading head, confirms the pair, reads the chapter map plus audio spans and EPUB
spine, then calls
`models::domain::reading_state::{map_time_to_locator,map_locator_to_time}`.
It returns a read-only `MappedPosition`; the head is not changed until the user
actually reads or listens at the mapped location.

## 4. Tier 2 - forced alignment (cheap, needs a worker)

Because the text is known, this is **alignment**, not transcription: a CTC
acoustic model emits per-frame character scores and Viterbi finds the known
ebook text through those scores. Whisper takes the longer route: free-form
transcription followed by fuzzy reconciliation of ASR text to the EPUB.
Storyteller's web path validated below is a Whisper/fuzzy reference; its
separate CLI exposes CTC/Viterbi. Both remain external references. The
optional worker-local Storyteller adapter calls only an operator-managed
instance; Storyteller is never a search/catalog provider, bundled dependency,
or default server backend.

**Shipped** runner pipeline (the server-side finalizer remains authoritative;
the runner remains outside the server):

```text
paired EPUB ──► deterministic preparation (preserve source fragment ids;
                 assign deterministic ids only to missing targets)
single-file M4B ─► worker-local aligner (Storyteller delegate or configured
                   external native CPU/fp32 CTC executable)
                 └──► SyncMapV1 {
                        provenance: { exact input digests, implementation/model/runtime },
                        cues: [{ text: { spine_index, ordinal, element_id },
                                 audio: { track_index, begin_ms, end_ms },
                                 confidence }]
                      }
                 ──► server rechecks requester, pair, source, output, durations,
                     targets, then persists the map and deterministic EPUB cache
```

The **Shipped** `media_sync_maps` store is keyed by the ebook media, audio
media, granularity and immutable generator/input identity; there is no
`pair_id` row. `importSyncMap` validates the typed map against the confirmed
pair and real track durations before upserting it, while `enqueueAlignment`
reuses an active job for the same exact pair/input and granularity. The
original EPUB and M4B are never modified. Preparation preserves existing source
XHTML fragment IDs and adds deterministic IDs only where needed, so native
overlays and worker output share one target contract.

Fallback interpolation is bounded inside one confirmed chapter and marked with
`confidence`; never interpolate across front matter, an unmatched chapter or a
track boundary. The console does not highlight low-confidence cues.


### A Rust aligner: how hard, and whether it is worth it

The aligner is four parts; three are easy in Rust today, one is the decision.

| Part | Rust today | Effort |
| --- | --- | --- |
| Decode + resample to 16 kHz mono | `symphonia` (*exists* in `stump_media`) + `rubato` | hours |
| Text → model vocabulary (model-specific case, punctuation and script normalization; multilingual needs a `uroman` port) | trivial for English; `uroman` is a ~1k-line rule table, port when a non-Latin book shows up | days for the port |
| Trellis + Viterbi forced alignment over CTC emissions, per chapter (memory `T × N`, bounded by the chapter map) | ~200 lines, no dependency | a day |
| **CTC acoustic model inference** | `ort` (ONNX Runtime bindings, CUDA/ROCm/CoreML through the runtime's shared library - not a build dependency) with an ONNX export of the model; `candle` has no wav2vec2 and its GPU path is less mature | the real work: export, `ort` feature wiring, parity tests against the Python aligner |

Verdict: **Planned** — CTC/Viterbi is the leading tier-2 candidate, but still
second to reusing an existing valid timing map. Phase A can prove the `align`
job, map, and EPUB render through an external process/container boundary with a
permissively licensed runtime and model. An operator-managed Storyteller API is
an optional worker-side backend; the GPL-3.0 `ghost-story` CLI/toolchain is
external only and is never bundled or the default runner. Phase B may serve the
same wire contract from an in-binary `ort` aligner only when its `SyncMapV1`
matches the fixture corpus within a declared tolerance. Nothing above that
boundary changes.

Model licences decide what phase B may ship: `facebook/wav2vec2-base-960h`
(English, Apache-2.0) is fine; `MMS_FA` (1,100+ languages) is **CC-BY-NC 4.0**
and cannot be the default; NVIDIA NeMo CTC models are CC-BY-4.0 and are the
multilingual candidate. The worker advertises which model it carries in its
capabilities, and the job records `generator` + model id in `media_sync_maps`.

## 4a. Reference systems and BookBridge index

### Why Storyteller is in the test
[Storyteller](https://storyteller-platform.dev/docs/the-algorithm/) is a
producer and reader for the target interchange format: it takes a DRM-free EPUB
and audiobook, transcribes or emits CTC features, aligns the text, and writes an
EPUB 3 publication with Media Overlays. Coppice does not bundle it or call it
from the server. A worker-local adapter may call an operator-managed
Storyteller API and return only validated `SyncMapV1`; the server never treats
Storyteller as a search/catalog provider. The server and
`@storyteller-platform/align` package are MIT, but the current align package
depends on GPL-3.0 `ghost-story`; that CLI/toolchain stays an external
lab/container boundary. We use it as an independent oracle for preparation,
GPU behavior, and the EPUB/SMIL envelope.

The 2026-09-08 reference run used Storyteller web-v2.14.21 at
[`a1d5ad4`](https://github.com/smoores-dev/storyteller/tree/a1d5ad4ce4c7cb1dc6488e6fca9bf6e65a99bbc2),
the CUDA 13.1 image digest
`sha256:9250c71e611145fdfe4150e29649c69d262544ba6f526425235d2156f9e65e0b`,
and a GeForce RTX 3070. A real 13 h 26 min *Three-Body Problem* M4B plus its
EPUB completed the Whisper/fuzzy pipeline in 8 min 12 s with turbo mode 4:
35/35 narrative chapters, 9,057/9,266 sentences (97.74 %), 35 SMIL overlays,
9,266 resolved text targets, and no invalid or non-monotonic cues. This is
**Contract-tested** evidence for the external reference and corrected M4B, not
proof of a Coppice aligner.

Storyteller's current
[`align --ctc`](https://github.com/smoores-dev/storyteller/blob/a1d5ad4ce4c7cb1dc6488e6fca9bf6e65a99bbc2/libraries/align/src/cli/bin.ts)
is especially useful reference behavior: direct CTC emissions and
transcript/fuzzy alignment share EPUB markup and output stages. Coppice still
owns its worker protocol, map schema, quality thresholds, and edition-transfer
rules.

### Measured 10 % mode comparison

The private three-chapter fixture is 5,378 s of audio (11.12 % of the book) and
997 narrative sentences (10.76 %). Both modes used the same prepared tracks:

| External mode | Measured wall time | Direct sentence matches | Final EPUB |
| --- | ---: | ---: | --- |
| web Whisper/fuzzy, `tiny.en`, turbo 4, CUDA | 76.324 s (70.5× realtime) | 969 / 997 (97.19 %) | 997 cues, 3 SMIL, valid |
| CLI CTC/Viterbi, `Xenova/wav2vec2-base-960h` fp16, CUDA | 39.453 s including markup, emissions and Viterbi (136.3× realtime) | 984 / 999 (98.50 %) | 999 cues, 3 SMIL, valid |

The CTC emission pass was 22.57 s on the RTX 3070; Viterbi plus EPUB output was
16.60 s. The model is the Apache-2.0 English Wav2Vec2 model, not the
CC-BY-NC MMS default. Storyteller 0.1.58 needed three lab-only adaptations:
an ONNX Runtime CUDA image with the missing CUDA 12 libraries, renaming binary
`STEM` emissions from `.json` to `.emissions`, and upper-casing known English
text for this model's vocabulary.

The negative control matters more than the headline score. When front matter
remained in the spine, CTC falsely matched the character list and contents
against narration and produced five invalid cue intervals. Restricting search
to the three tier-1-mapped narrative chapters removed those failures. Coppice
must enforce chapter bounds and reject the artifact, not copy Storyteller's
interpolation. Across 987 common text targets the two modes differed by a
median 1.468 s and p95 17.268 s at cue starts; that is algorithm disagreement,
not ground truth. Machine evidence is in
`input/audio/experiments/three-body-10pct/experiment.json`.

Three follow-up controls make that a useful lead rather than a one-run result:

- A repeat CTC run produced identical reports, SMIL and audio bytes. Only
  Storyteller's wall-clock `dcterms:modified` changed, so its whole EPUB is not
  byte-deterministic; Coppice's cached renderer must be.
- fp16 and fp32 produced the same 984/999 direct matches. Of 999 cues, the
  median and p95 boundary delta were 0 ms and the maximum was 920 ms; fp16 took
  22.57 s for emissions versus 43.92 s for fp32. fp16 is the current choice.
- Without upper-casing known text for the English Wav2Vec vocabulary, the same
  bounded input matched zero chapters and emitted no SMIL. Normalization is a
  versioned cache-key input, not a hidden implementation detail.

A second private 9.73 % fixture from *Dark Eden* exercised an EPUB 2 upgrade,
one audio file containing six physical parts, and a different XHTML layout.
Bounded to the three narrative chapters actually covered by the audio,
CTC/Viterbi directly matched 794/801 sentences (99.13 %) and 98.83 % of audio;
upgrade/markup, emissions and Viterbi/export took 32.10 s including container
startup. The raw Storyteller EPUB was still rejected: aggregate
`media:duration` ended 188 ms before its last cue even though the refined
overlay durations and probed audio clock covered it. Recomputing only that
aggregate from the overlays produced a valid 801-cue, 3-SMIL EPUB. Evidence is
in `input/audio/experiments/dark-eden-10pct/experiment.json`.

So yes: CTC/Viterbi is the best mode tested so far for the known-ebook tier.
It is not yet a universal default. The two books are both English, timing
deltas against Whisper are not ground truth, and the external CLI exposed
case, chapter-bound and packaging traps. Next corpus expansion should target
another language, a materially abridged edition, narrator variation and a
small hand-checked timing set.

The pinned BookBridge adapter proves both useful Storyteller paths. It can
download an already processed exact book, or upload EPUB/audio through
Storyteller's TUS endpoint, trigger processing, poll the book, and download
`files?format=readaloud`. It then strips the large embedded audio from its local
locator cache and consumes the timing artifacts. Coppice should copy the
**boundary**, not BookBridge's loose title matching: exact media identity and
the `SyncMapV1` quality gates remain mandatory.

BookBridge's priority ladder is the main idea to adopt: **reuse a valid timing
artifact before spending GPU time**. Coppice should improve on a hard-coded
source order: collect the local `SyncMap`, exact-edition shared manifest,
native SMIL, and Storyteller timeline as zero-GPU candidates; validate content
identity, duration, monotonicity, coverage, granularity, and provenance; then
choose the strongest. Run known-text CTC only when none passes, and Whisper/fuzzy
ASR only as the final fallback. Persist why a candidate won.

Also adopt explicit provenance and durable resumable caches. Do not copy
BookBridge's weakest fallback: a Storyteller re-anchor may degrade to a
two-point linear map and still suppress SMIL/Whisper. Coppice quality gates must
try the next candidate when coverage or confidence fails.

## 4b. Readiness scoring

**Planned:** “Can this book be read aloud, and how well?” is a future
quality-check family in the existing ingest registry shape
(`crates/ingest/src/quality/`). It is not currently registered, and the console
has no readiness badge or Requests page. When implemented, each check will name
the action that fixes it without pretending that a missing source was acquired.

| Check id | Future pass condition | Future fix action |
| --- | --- | --- |
| `has_ebook_edition` | the work has a confirmed EPUB edition (`media_links`) | attach or ingest an ebook |
| `has_audio_edition` | the work has a confirmed audio edition | attach or ingest an audiobook |
| `single_file_audio` | the audio edition is one container (reuses the audio family's `single_file`) | `audio-assemble` |
| `chapters_present` | the audio edition has authored chapter marks (reuses `chapters_present`) | `audio-chapters` |
| `chapter_map_confidence` | ≥ 90 % of EPUB spine items map to an audio chapter with `confidence ≥ 0.8` | manual chapter map |
| `epub_alignable` | every spine item parses and segments into sentences; no DRM | `epub-polish` / `epub-check` |
| `sync_map_present` | a `media_sync_maps` row exists at sentence granularity | explicit `align` job (parks in `needs_worker` until a capable worker exists) |

The future aggregate may be a read-aloud readiness badge (none / approximate =
tier 1 only / aligned). The family must be `NOT_APPLICABLE` for a work with
neither an ebook nor an audiobook, so comics never carry it.

## 4c. Shareable alignment manifests

**Planned:** no public registry is being implemented. A public service requires
legal, privacy, and abuse review first. The useful output of alignment is mostly
mechanical timing data, but it must be separated from every copyrighted input
before even local export is considered.

The safe first deliverable is an **exact-edition manifest**:

```text
AlignmentManifestV1 {
  work_ids
  text_normalization_version
  audio_fingerprint_version
  exact_text_digest
  robust_audio_digest
  chapters [{
    ebook_spine_index
    audio_chapter_index
    sentence_shape: [{ ordinal, token_count, punctuation_class }]
    cues: [{ sentence_ordinal, begin_ms, end_ms, confidence }]
  }]
  generator { implementation, version, model, options }
  source { kind: ctc|storyteller|smil|asr, coverage }
  payload_digest
}
```

The canonical text digest ignores ZIP layout, CSS, insignificant markup, and
Unicode normalization differences. The audio digest is over robust acoustic
landmarks, not M4B bytes, so container tags or a lossless remux do not miss.
When both digests match, another server can trust the ordinal/timing map after
structural validation and skip all GPU work.

For a modified edition, reuse is deliberately partial:

1. Match the work and narration, then align chapter title/order and duration.
2. Run dynamic programming over the non-expressive sentence-shape sequence
   (ordinal, token count, punctuation class) to locate insertions, deletions,
   split paragraphs, and changed front/back matter.
3. Transfer only monotonic high-confidence cue runs and fit a piecewise time
   transform from the robust audio landmarks.
4. Re-run local CTC only for unmatched gaps. Never stretch one global linear
   map across an abridged, translated, revised, or differently narrated book.

This handles packaging changes and modest editorial variation without sharing
source expression. A second, optional format could add hashed word shingles for
stronger semantic anchoring, but hashes of every sentence are dictionary-
testable by anyone holding the book. They are not the default and need the same
legal/privacy review as excerpts.

Registry rules for a future public service:

- opt-in upload only; private books and possession metadata never leave a
  server by default;
- accept DRM-free, lawfully accessed inputs only; Coppice never circumvents DRM;
- publish manifests under CC0-1.0 with contributor attestation, immutable
  payload digests, signatures, generator provenance, and revocation;
- require proof of possession of a matching edition before download; useful
  risk reduction, not a claim that possession settles copyright;
- validate monotonic cues, duration, coverage, and content identity locally;
  bad or low-confidence community data only seeds a local repair job.

U.S. law says copyright does not protect facts, systems, or methods of
operation ([Copyright Office FAQ](https://www.copyright.gov/help/faq/faq-protect.html);
[17 U.S.C. §102(b)](https://www.law.cornell.edu/uscode/text/17/102)).
That supports, but does not guarantee, treating bare timestamps and ordinals as
shareable facts. It does **not** authorize sharing the source text/audio, and
compilation rights, contracts, privacy, and other jurisdictions still matter.
In the EU, text/data-mining exceptions require lawful access and can be
reserved in some cases
([Directive 2019/790, arts. 3-4](https://eur-lex.europa.eu/eli/dir/2019/790/oj/eng));
they do not automatically authorize publishing the mined work. U.S.
anti-circumvention law is a separate constraint
([17 U.S.C. §1201](https://www.law.cornell.edu/uscode/text/17/1201)).
Therefore exact manifests can ship locally first; a public federation waits for
legal, privacy, and abuse review.

## 5. Output: Storyteller-compatible EPUB from an accepted map

**Shipped:** preparation preserves source XHTML ids and assigns deterministic
ids only to otherwise-unaddressable text. The read-aloud EPUB is a mimetype-first
deterministic ZIP with one SMIL per spine item, `package.opf` `media-overlay`
references and `media:duration`, and the original single-file M4B streamed to
`audio/book.m4b`. The accepted `SyncMapV1` is the source of truth; the EPUB is
a replaceable delivery derivative. Synchronized Storyteller read-aloud playback
is not shipped; ordinary EPUB playback and ordinary audiobook playback remain
separate.

Two immutable cache identities stay separate:

- the map key covers exact text/audio digests, segmentation, algorithm,
  implementation/version, model/revision, execution provider, precision,
  options, and granularity;
- the EPUB key adds the accepted map payload digest and renderer/schema version.

The **Shipped** `enqueueAlignment` action owns an explicit alignment request for
a confirmed pair and granularity, and reuses an active identical `align` job
instead of launching a second model. It does not start ML itself. After a
worker result passes server validation, the renderer builds the ZIP and
publishes it before the job becomes `done`. A completed derivative is cached;
the original EPUB and M4B remain untouched.

`GET /api/v2/media/{id}/read-aloud.epub` is **Shipped** and cache-only: it never
starts ML, creates a job, or renders on demand. It serves an already published
cache hit, otherwise returns a not-ready response. The completed file has
`Content-Length`, `Accept-Ranges`, a stable ETag and single-range behavior.
The original single-file M4B remains verbatim; folder audiobooks return a
stable unsupported/not-ready response rather than being silently concatenated.
### **Planned** experiment: a virtual composite EPUB

The fully materialized ZIP is the conservative first implementation, not a
requirement. A future experiment will expose one deterministic logical EPUB
without copying the M4B into a second server-side file. The byte space is a
sequence of generated ZIP headers/XHTML/SMIL/OPF bytes, ranges from the original
M4B, and a generated central directory. The already-compressed audio entry uses
ZIP `STORE`; an HTTP range inside that entry maps directly to the same range in
the source M4B.

This is **not** generic non-seekable `ZipWriter` streaming. Before serving byte
zero, Coppice must know every entry's offset, size, CRC-32 and the final central
directory, including ZIP64 values for large books. It also needs a stable
`Content-Length`, representation ETag, and source identity for the lifetime of
the response. Computing a missing audio CRC/digest costs one source scan, but
does not create another audio copy.

The experiment is accepted only when:

1. a full virtual response is byte-identical to a materialized reference EPUB
   and passes `unzip -t` plus `epub-check`;
2. single-range reads work inside every generated segment, at the start/middle/
   end of the M4B, across segment boundaries, and in the central directory;
3. changing the source size/digest invalidates the representation rather than
   mixing old headers with new audio;
4. Thorium Reader, Readest, and at least one mobile EPUB reader open, seek, and
   resume it over HTTP.

If those checks pass, the cache keeps only the small immutable layout/metadata
plan and generated text resources. A materialized ZIP remains the compatibility
fallback for a client that cannot consume the virtual representation.

The console's own reader does not need the EPUB at all: it reads the **Shipped**
persisted SyncMap through GraphQL (`Media.syncMap(granularity)`), plays the track
route it already uses, and highlights `element_id`s in the rendered XHTML.
The field resolves a map from either the ebook or audiobook side; see
`crates/graphql/src/object/media.rs` and `crates/graphql/src/object/sync_map.rs`.

**External Storyteller references** are separate from Coppice's optional
worker-local adapter. Coppice does not bundle a Storyteller app or call it from
the server. The external server and apps are
[MIT-licensed](https://github.com/smoores-dev/storyteller/blob/a1d5ad4ce4c7cb1dc6488e6fca9bf6e65a99bbc2/LICENSE).
Thorium Reader, Readest, BookFusion, Colibrio, and Calibre can consume the
read-aloud EPUB directly, so standards-based delivery stays first. The
worker-side Storyteller API adapter returns only `SyncMapV1`.

## 6. Remote workers - the modular server

The server stays one Rust process; heavy or hardware-bound work is a **job**
that a worker somewhere else can claim. Workers dial *out* to the server (the
VPS never needs to reach the PC), so NAT and dynamic IPs are not a concern.

| Concept | Design |
| --- | --- |
| Worker identity | a device of kind `Worker` (*devices crate exists*): paired with a QR/API key like every other device, scoped to the `worker` permission, revocable in the console |
| Transport | one WebSocket `/api/v2/workers/socket` (the server already runs axum `ws`); worker sends `hello { capabilities }`, then `claim` / `progress` / `result` / `fail`; server sends `job` and `cancel`. Reconnect resumes claimed jobs by id |
| Capabilities | `{ align: { device: cuda\|rocm\|metal\|cpu, models: [...], algorithms: [...], precisions: [...] }, transcode: { ffmpeg, hwaccel: [nvenc,...] }, asr: {...} }` - free-form JSON matched structurally; the console's Workers page lists who advertises what |
| Job table | `worker_jobs (id, kind, input JSON, requires JSON, status: queued\|claimed\|running\|done\|failed\|needs_worker, worker_id, priority, progress, result JSON, error)`; `needs_worker` is shown, not hidden - "no worker advertises `align` right now" |
| Routing | a job kind declares `local: Option<fn>`; if a capable worker is connected it is offered first, else the local implementation runs (transcode has one: the `ffmpeg` ExternalTool), else the job waits. Priority is low by default: alignment never competes with a scan |
| Data path | input by authenticated download (`/api/v2/media/{id}/file`, `/audio/track/{i}`); output uploaded as raw bytes to `PUT /api/v2/workers/jobs/{id}/output` with a required SHA-256, then atomically published only after result validation |
| Events | job transitions are `CoreEvent::WorkerJobChanged` on the bus (*exists* as a pattern) → console live status, ntfy on completion |
| Worker binary | `crates/worker` (`stump_worker`): protocol client, transcode/browser runners, optional worker-local Storyteller delegate, and optional external native CTC runner; the server-side `AlignInput`, `AlignResult` and `SyncMapV1` contract remains shared |

An `align` runner is registered when the worker has either a configured
Storyteller endpoint or both `--native-aligner` and `--native-align-model`.
The native executable receives only local `--epub`, `--audio`, `--model`, and
`--output` paths and must emit typed `SyncMapV1`; its model identifier/revision,
implementation, version, CPU provider, fp32 precision, and CTC algorithm must
match the job profile. Both runners stream authorized source media to temporary
files. Without a capable worker, the row parks in `needs_worker`.
Audiobook-only `asr` remains later/out of scope.

### Optional Storyteller align backend

The practical `align` runner is a worker-side adapter for an operator who
already runs Storyteller. Storyteller can run on the same worker device or
anywhere that worker can reach. This keeps the existing topology: the worker
dials Coppice, and neither the Coppice server nor its job payload needs a route
or credentials for the Storyteller instance.

The current adapter implements the **delegate** path: it downloads the exact
paired EPUB and single-file M4B from Coppice, prepares the EPUB with the shared
deterministic target contract, uploads both through Storyteller TUS, triggers
processing, polls with a bounded budget, downloads the result, and converts it
to `SyncMapV1`. Verified UUID reuse remains a separate future mode.

Only the compact `SyncMapV1` returns to Coppice. Storyteller URL, username,
password, and remote-library lifecycle policy stay in worker-local
configuration. The worker advertises the configured implementation/profile
under `align`; a generic “Storyteller is installed” capability is not enough
for deduplication or provenance. A result is only a candidate until Coppice
checks exact digests, chapter correspondence, monotonic timing, duration,
targets, and coverage.

This backend is **Shipped** behind the worker client feature. Native
CTC/Viterbi remains the later independent backend; both produce the same map
contract. The adapter never sends Storyteller credentials to the server or
embeds them in an EPUB/archive.

## 7. Requests - asking for what is missing

Coppice ships its own metadata-backed request ledger and Home surface. The
server owns request creation, mine/all visibility, permissions, optional
destination intent, manager approval/rejection, notifications, and social
recommendation handoff.

Universal-style metadata search can seed a request, but approval ends the
Coppice request flow:

```text
metadata search or recommendation
  -> request
  -> permission and visibility checks
  -> operator approval or rejection
```

MAM acquisition is deferred. There is no active release selection, grab,
download polling, retry, or gateway configuration. If acquisition is added
later, it must run as a separate authenticated provider sidecar. This boundary
does not promise a provider, implementation, or schedule.

Alignment is a separate explicit path: a user confirms an ebook + audiobook
pair, then imports a validated map or enqueues an alignment job. The optional
worker-local Storyteller adapter can fulfill that job; Storyteller is never a
search/catalog provider.

## 8. What is deliberately not here

- No DRM handling (a DRM'd source is refused, as everywhere in Coppice).
- No transcript store: tier 2 keeps cues, not text; the EPUB remains the text.
- No public transcript or content-hash exchange: an alignment manifest contains
  timing, ordinals, structural shapes, and provenance only. Exact-edition local
  import/export comes before any federated registry.
- No automatic library-wide alignment: the enqueue mutation is explicit and
  pair-scoped; there is no scheduler or `AudioPolicy.auto_align` implementation.
- No GPU code in the Rust build: `whisper-rs`/`ct2rs` are worker-container
  concerns if they are ever wanted.
- No synchronized Storyteller read-aloud playback: ordinary EPUB playback and
  ordinary audiobook playback remain separate until a reader contract consumes
  the derivative.

## 9. Implementation order

1. `pair_editions` + `media_chapter_map` + read-time position conversion (tier
   1) — **Shipped**; the readiness check family (4b) remains **Planned**.
2. Worker protocol + `crates/worker` + `worker_jobs` + console Workers page,
   with `transcode` as the first job kind — **Shipped**.
3. `AlignInput`/capability requirements + `SyncMapV1` validation —
   **Shipped**; `media_sync_maps`, `Media.syncMap`, explicit enqueue/import,
   strict native SMIL import, the Storyteller delegate, and the external native
   CTC runner are **Shipped**. An in-process Rust model runtime remains optional
   future work.
4. Add verified Storyteller UUID reuse, exact-edition manifest export, and
   gap-only repair after the delegate path has evidence.
5. Read-aloud EPUB delivery, the OPDS acquisition link, and GraphQL readiness —
   the authenticated cache-only route, OPDS link, GraphQL map/artifact fields,
   and materialized deterministic ZIP are **Shipped**. Readiness quality
   checks and the virtual composite EPUB remain **Planned**.
6. Keep the request ledger, permissions, decisions, notifications, and social
   handoff separate from provider search and alignment. Acquisition remains
   deferred; any future integration must use a separate authenticated provider
   sidecar.
7. Public manifest federation only after legal/privacy review and abuse controls.
8. Optional Storyteller app serving profile (`crates/storyteller`), independent
   of the worker align backend.
