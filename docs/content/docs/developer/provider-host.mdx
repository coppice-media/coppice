# Provider host

The provider host (`crates/provider`, `stump_provider`) lets Stump serve
content from remote sources the way Mihon does: a `Source` can list popular
and latest series, search, describe a series, list chapters, list a chapter's
pages, and fetch page bytes. Remote series become ordinary `series`/`media`
rows whose `path` is a `provider://<source>/<remote_id>[/<chapter>]` URI, so
every existing reader route (native, Komga, OPDS, Kobo) serves them without
knowing about providers. This page covers the design; the metadata
providers that enrich local files are a different subsystem
(see [Provider status](/docs/developer/provider-status)).

## Enabling

| Layer | Switch | Default | Effect |
| --- | --- | --- | --- |
| Cargo | feature `providers` (server, `stump_core`, `graphql`) | on in `headless`/`full`, off in `minimal` | Links `stump_provider` + `stump_provider_mangadex` + `stump_provider_themes`, the GraphQL ops, and the Komga/OPDS branches |
| Runtime | `STUMP_ENABLE_PROVIDERS` / `providers.enable_providers` | `false` | Creates the `ProviderHost` at boot (`core/src/providers.rs::init`), installs the `provider://` media resolver, starts the GC scheduler. Off: GraphQL ops answer `Provider host is not enabled`, virtual branches fall through |

Other keys (`core/src/config/providers.rs`):

| Key | Env | Default | Meaning |
| --- | --- | --- | --- |
| `provider_cache_max_bytes` | `STUMP_PROVIDER_CACHE_MAX_BYTES` | 2 GiB | Bound of the on-disk page/cover cache under `<config>/cache/providers` |
| `virtual_series_ttl` | `STUMP_VIRTUAL_SERIES_TTL` | `300` s | How long one live browse page `(source, kind, page)` is cached |
| `provider_gc_days` | `STUMP_PROVIDER_GC_DAYS` | `30` | Materialised series with no reading head older than this are reclaimed |
| `provider_health_interval_secs` | `STUMP_PROVIDER_HEALTH_INTERVAL_SECS` | `21600` s (6 h) | How often the source-health job probes every catalog source (floored at 60 s) |
| `provider_health_dead_after` | `STUMP_PROVIDER_HEALTH_DEAD_AFTER` | `3` | Consecutive failed runs after which a source is `DEAD` and hidden from the catalog (floored at 1) |
| `source_definitions_url` | `STUMP_SOURCE_DEFINITIONS_URL` | `https://raw.githubusercontent.com/stumpapp/stump-sources/main/index.json` | Definition repository the theme engines are driven from; see [Theme engines and definitions](#theme-engines-and-definitions) |

## Sources and the catalog

- **Compiled implementations.** MangaDex ships as code
  (`crates/provider-mangadex`) because it is an API, not a themed site.
  A `SourceFactory` describes an implementation and builds an instance per
  language; instance ids are `<implementation>-<lang>` (`mangadex-en`).
- **Theme engines.** Everything else is data: `crates/provider-themes` runs
  four `lib-multisrc` themes against a `SourceDefinition` fetched at runtime.
  See [Theme engines and definitions](#theme-engines-and-definitions).
- **Catalog.** The Keiyoushi extension index is fetched daily into
  `<cache>/providers/keiyoushi-index.json`. `providerCatalog(lang, query,
  includeDead)` flattens it to one row per source with `hasImplementation`
  telling the operator whether Stump can actually run it and `health` the
  entry's badge (the `source_health` row). Dead sources are omitted unless
  `includeDead: true`.
- **Enabling a source.** `enableProviderSource(catalogId)` (or
  `implementation` + `lang`) upserts a `provider_sources` row and registers
  the instance; `disableProviderSource(id)` keeps materialised rows but stops
  page resolution and live browse.
- **Quotas.** Each source owns a `RateLimiter` (MangaDex: 5 requests/second,
  shared by API and image calls; MangaDex@Home fetches are reported to the
  network as its rules require). Manifests (page URL lists) are re-resolved
  after 10 minutes because at-home URLs expire.

## Mode A: materialised series in any library

`addProviderSeries(libraryId, sourceId, remoteId)` fetches details and
chapters and writes `series`, `series_metadata`, `media`, `media_metadata`
rows under deterministic ids (`uuid5("series:<source>:<remote>")`,
`uuid5("media:<source>:<chapter>")`). `refreshProviderSeries(seriesId)`
re-runs the same idempotent path. Pages are fetched on demand through the
`VirtualMediaResolver` and cached on disk; `pages` is learned on first
resolution.

## Mode B: virtual libraries

`createVirtualLibrary(sourceId, name)` creates a `libraries` row with
`path = provider://<source>`, `source_provider = <source>`, a deterministic id
(`uuid5("library:<source>")`), and `watch` off. Nothing else is written.

```
client ──▶ Komga series/list {libraryId is V}          ──▶ host.browse(source, kind, page)
                 │  (or OPDS /libraries/V)                    │  TTL cache, reverse index id→origin
                 ▼                                             ▼
        KomgaSeries cards with uuid5 ids, booksCount 0   no rows written
                 │
client ──▶ Komga series/{id}      ──▶ live details (id resolved from the reverse index)
client ──▶ Komga series/{id}/books ─▶ materialise (same ids) ──▶ ordinary DB path
client ──▶ books/{id}/pages/{n}    ─▶ provider:// resolver ──▶ page cache / source
```

Request mapping (`apps/server/src/routers/provider_virtual.rs::browse_kind`):

| Client request | `BrowseKind` |
| --- | --- |
| Komga `fullTextSearch` / OPDS `?search=` | `Search { query }` |
| Komga sort on `readCount`, `booksCount`, `readProgress` | `Popular` |
| Anything else (including the unsorted default) | `Latest` |

Rules:

- Only a lone `libraryId is <virtual>` condition (at any nesting depth) routes
  live; combined conditions are answered from the database, which has no
  virtual rows.
- Live results pass the same per-user library filter as stored rows
  (`library::Entity::find_for_user`); ids the user could not have browsed are
  treated as unknown.
- Live cards report `booksCount = 0`; the chapter count becomes real after
  materialisation. Live pages have no total: the Komga `Page` and OPDS feed
  report one phantom element past the current window while `has_next` is true.
- Materialisation happens on the first `series/{id}/books` (Komga) or
  `series/{id}` (OPDS 1.2) call for an id served by a live browse; a stored id
  never re-materialises on read (use `refreshProviderSeries`).
- The filesystem scanner treats a virtual library as a no-op and never marks
  `provider://` series missing (`library_scan_job.rs::init`, `walk.rs`).

Routes that answer from a virtual library today:

| Protocol | Route | Live / materialised |
| --- | --- | --- |
| Komga | `POST /api/v1/series/list` | live |
| Komga | `GET /api/v1/series/{id}` | live until materialised |
| Komga | `GET /api/v1/series/{id}/thumbnail` | live (source cover) or stored |
| Komga | `GET /api/v1/series/{id}/books` | materialises, then DB |
| Komga | `GET /api/v1/books/{id}`, `/pages/{n}`, `/thumbnail` | materialised rows via resolver |
| OPDS 1.2 | `GET /libraries/{id}` | live |
| OPDS 1.2 | `GET /series/{id}` | materialises, then DB (PSE pages as usual) |
| Kobo, Kavita, OPDS 2.0, native GraphQL | — | materialised rows only (they read the database) |

## Unavailable chapters

A source's chapter feed lists more than a source can serve. Every
`RemoteChapter` therefore carries `readable: bool` and
`external_url: Option<String>`, and materialisation writes rows only for
readable chapters — a row for an unreadable one is a book whose every page
404s.

MangaDex sets `readable = false` from three documented `ChapterAttributes`
fields ([API spec](https://api.mangadex.org/docs/static/api.yaml)):

| Field | Spec | Skip reason |
| --- | --- | --- |
| `externalUrl` | "Denotes a chapter that links to an external source." | `ExternallyHosted` (the URL is kept, so a client can be told where the chapter lives) |
| `pages` | "Count of readable images for this chapter" — `0` means none | `NoPages` |
| `isUnavailable` | `boolean`; the chapter is listed but withheld | `Unavailable` |

`Materialized.skipped` reports every skip as `{ remote_id, reason }`, and
`add_series` logs one `INFO` line per series with the skip count, the readable
count, and the distinct reasons. A licensed title such as *The Witch and the
Beast* on `mangadex-en` therefore materialises with zero books and a full
skip list, instead of books that cannot be opened.

A chapter can also stop being available *after* it was materialised. The page
manifest lookup (`/at-home/server/{chapterId}`, documented to answer
`404 Not Found`) is the moment that shows: `ProviderHost::pages` maps that
404 to `ProviderError::Unavailable { source_id }`, which converts to
`FileError::Unavailable` and then to `404 Not Found` with the message
`Chapter is not available from <source>` on every lane — native, Komga, OPDS
1.2/2.0, and Kavita all classify it through the single
`From<FileError> for APIError` mapper. Before this, that chain produced
`500 {"message":"File not found on disk"}`.

## Covers

A provider series has no file to render a thumbnail from, so its cover *is*
the source cover, cached under `cover:<remote_id>`:

- The MangaDex list, search, and detail queries all send
  `includes[]=cover_art`, so a series materialised straight out of a browse
  response carries `thumbnail_url` into `series_metadata.comic_image`.
- `ProviderHost::cover_url` falls back to a `details()` fetch when the stored
  row has no `comic_image` (an older row, or a source whose list response
  omitted the relationship) and writes the URL back, so the next request is
  one query again.
- `series/{id}/thumbnail` — native and Komga — serves that cover for both
  live-only and materialised provider series. An operator-uploaded thumbnail
  still wins; if the source cover cannot be fetched, the lane falls back to
  the first book as before.
- Book thumbnails are unchanged: page 1 of the chapter, through the page
  cache.

## Age rating

Stump stores age restrictions **per user** (`age_restrictions.age` +
`restrict_on_unset`) and filters content by `series_metadata.age_rating`.
There is no library-level age rating to set, so a source's rating is applied
to each series it materialises.

`RemoteSeries::content_rating` is MangaDex's `MangaAttributes.contentRating`
vocabulary, projected onto `age_rating`:

| `contentRating` | `age_rating` |
| --- | --- |
| `safe` | *(none)* |
| `suggestive` | 13 |
| `erotica` | 16 |
| `pornographic` | 18 |

`safe` deliberately stores no rating: a user whose restriction does not
`restrict_on_unset` must still see unrestricted titles, which is how locally
scanned books without metadata behave.

On top of that, a source whose Keiyoushi catalog entry is
`CONTENT_WARNING_NSFW` (`CatalogEntry::nsfw`) raises **every** series it
materialises to 18, regardless of the per-title rating
(`ProviderHost::source_is_adult` → `materialize::age_rating`). That is the
library-level rule expressed the only way the schema allows.

Mode B live rows carry the same value: `map_remote_series` fills
`metadata.ageRating` from `remote_age_rating(remote, adult_source)`, and the
Komga and OPDS 1.2 browse lanes drop rows the requesting user's restriction
hides (`provider_virtual::age_restriction_allows`, the same rule
`series::get_age_restriction_filter` applies in SQL). `series/{id}`,
`series/{id}/thumbnail`, and materialisation apply it too, so a restricted
title can be neither read nor written into the database.

## Garbage collection

`StumpJob::ProviderGc` runs two minutes after boot and then daily
(`core/src/providers.rs`). It deletes provider-backed series that have no
reading head for any user on any of their books and whose `created_at` is
older than `provider_gc_days`, removing reading-list/collection memberships
in the same transaction and sweeping thumbnails afterwards. Non-provider
series are never touched. The next browse simply serves the series live again
under the same id.

## Source health

`StumpJob::ProviderSourceHealth` (`core/src/job/provider_health.rs`) runs
five minutes after boot and then every `provider_health_interval_secs`
(`core/src/providers.rs::spawn_health_scheduler`), and on demand through the
`runProviderHealth` mutation, which enqueues the same job. One task is one
base URL: catalog sources sharing a host are probed once per run, enabled
instances first.

Per target (`crates/provider/src/health.rs`):

1. `HEAD` the base URL, falling back to `GET` when the host answers 403,
   405 or 501. 10 s timeout (`PROBE_TIMEOUT`).
2. Record `http_status`, `latency_ms` and `redirect_url` (set when the
   request landed on a different URL, ignoring a trailing slash).
3. Detect the site's theme from its landing markup once, then `GET` that
   theme's latest-updates path (`SourceTheme::latest_path`) and record
   `latest_path_ok`. A known theme skips the markup sniff.
4. Fold the result into the previous state: an unreachable base URL
   increments `consecutive_failures` and marks the source `DEGRADED`, or
   `DEAD` at `provider_health_dead_after`; a reachable one resets the count
   to zero and marks `OK`, or `DEGRADED` when only the latest path failed.

The result is one upserted `source_health` row per catalog source
(`status`, `http_status`, `latency_ms`, `redirect_url`, `latest_path_ok`,
`consecutive_failures`, `error`, `checked_at`). `providerSourceHealth`
exposes it with `dead`, `consecutiveFailures` and `lastCheckedAt`; dead rows
are omitted unless `includeDead: true`, matching `providerCatalog`.

## Cross-source dedupe

The same work is usually carried by several sources. Every materialisation
writes a `provider_series_identity` row (migration `m20260924`): the
normalised title (`identity::normalise_title` — lowercased, every
non-alphanumeric character a separator) and `external_key`, the strongest
cross-source id the source reported (`al:<id>` > `mal:<id>` > `mu:<id>`;
MangaDex fills these from `attributes.links`, dropping per-site URLs).

When a series materialises and an identity from a **different** source
matches — external key first, normalised title second — a
`provider_series_links (series_id, canonical_series_id, reason, created_at)`
row records the duplicate, where `canonical_series_id` is the oldest series
in the chain, so every duplicate of a work points at the same series.
Locally scanned series have no identity row and are never candidates.

The link is advisory: nothing is merged automatically, so a false positive is
a row an operator can inspect through `providerSeriesDuplicates` rather than
lost progress. `mergeProviderSeries(keep, drop)` performs the merge:

- Both ids must be provider-backed (`source_provider` set) and different;
  a local series is rejected with `NotVirtual`.
- Every reading head of `drop` is replayed onto the matching chapter of
  `keep` through `models::services::reading_state::apply`, so the normal
  conflict rule decides and the merge never un-reads a chapter (completion is
  sticky). Chapters match on `media_metadata.number`, falling back to the
  normalised chapter title; a head with no counterpart is reported as
  `headsUnmatched`.
- Links pointing at `drop` are repointed to `keep`, then `drop`'s identity,
  link, media (with their list/collection memberships) and `series` row are
  deleted in one transaction.

## Verification

```text
cargo test -p stump_provider            # browse TTL + reverse index, browse→materialise→page, GC, cache, catalog, health (dead/recovery), dedupe + merge
cargo test -p stump_provider_mangadex   # MangaDex mapping (incl. external ids) and rate limiting (no network)
cargo test -p stump_core --lib providers # health schedule/threshold plumbing and GC cutoff
cargo test -p stump_komga               # condition-DSL routing and DTO shapes
```

returns an image.
