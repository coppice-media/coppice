This page focuses on how clients connect, authenticate, and use Coppice
protocols. The [client verification matrix](/docs/developer/client-verification)
is the sole record of dated, version-specific replay and device evidence;
[integration architecture](/docs/developer/integration-architecture) defines
the evidence vocabulary. Hardware and device-side constraints are on
[platforms](/docs/developer/platforms).

## Komelia (Android)

- **Protocol:** Komga compatibility profile (`/api/v1`, `/api/v2`, Readium,
  SSE). See [Komga compatibility](/docs/developer/komga-compat).
- **Setup:** use the Coppice server URL with Komga-shaped credentials; Basic or
  `X-API-Key` are supported. `remember-me=true` issues a 14-day
  `komga-remember-me` cookie for the background download worker.
- **Client limits:** Readium DTOs are stricter than the spec (`rel` must be a
  string, `published` a calendar date, contributors lists); the Komga alias
  normalizes to those types. `GET read-progress` is 405; use the progression
  route instead.

## Mihon / Tachiyomi

- **Protocol:** the Keiyoushi Komga extension uses legacy `GET /api/v1/books`,
  `/api/v1/series`, and `/api/v1/series/{id}/books`. Mihon's built-in Komga
  tracker uses `/api/v2/series/{id}/read-progress/tachiyomi` and the read-list
  equivalent under `/api/v1/readlists`.
- **Setup:** enter the Coppice server URL and use username/password (Basic) or
  an API key (`X-API-Key`). The tracker path sends only Basic or `X-API-Key`.
- The profile covers these observed route families; other Komga-shaped clients
  are not implied. See the verification matrix for distinct source-analysis
  and replay-client pins and their evidence scope.

## Liseur (Android)

| Profile | Protocol / URL | Credentials | Setup and client-side limits |
| --- | --- | --- | --- |
| Komga | Komga REST profile; server base URL | API key (`X-API-Key`) | The Komga provider has no annotation, note, or bookmark client. |
| OPDS 1.2 | `/opds/v1.2` | Basic (OPDS user) | Coppice does not implement Calibre-Web form login, Kobo-token provisioning, or delete lanes. |
| OPDS 2.0 | `/opds/v2.0` | — | Liseur has no OPDS 2 parser; use OPDS 1.2. Coppice serves a separate OPDS 2.0 catalog. |
| KOReader sync | `/koreader/{api_key}` | KOReader pairing (`x-auth-user` + MD5-derived `x-auth-key`) | Liseur uses KOSync roots, not Coppice's API-key middleware shape; see [sync platforms](/docs/developer/sync-platforms). |
| liseur-sync | Native `/v1/*` | Bearer device token (login → token mint) | The server also has attachment side-object routes/storage. Client support for those routes must not be inferred from the server contract. |

See the [client verification matrix](/docs/developer/client-verification) for
the current Liseur pins and the exact coverage of older client runs.

## KOReader

- **Protocol:** sync under `/koreader/{api_key}` exposes `GET users/auth`,
  `PUT syncs/progress`, and `GET syncs/progress/{document}`.
- **Setup:** configure KOReader's custom sync server to the Coppice URL with a
  full Coppice API key embedded in the path. The key owner needs
  `AccessKoreaderSync`; header auth is not used because KOReader's MD5 password
  form does not match Coppice's scheme.
- **Client limits:** the protocol has no annotation/highlight/bookmark surface;
  ZIP/RAR media have no `koreader_hash` and cannot match.

## Kobo eReaders (stock firmware)

- **Protocol:** `/kobo/{api_key}` provides initialization, library sync,
  metadata, thumbnails, `/auth/device`, EPUB/optional KEPUB download, and
  `library/{id}/state` GET/PUT.
- **Setup:** point the device at the server with an API key in the path; the key
  owner needs `AccessKoboSync`. `KOBO_KEPUB_CONVERSION=true` enables KEPUB
  handling for ordinary EPUBs.
- **Format limit:** stock Kobo firmware renders JPEG, PNG, GIF, BMP, and TIFF,
  not WebP ([supported formats](https://help.kobo.com/hc/en-us/articles/360017763713-File-formats-your-Kobo-eReader-and-Kobo-Books-app-support)).
  The optional comics transform packages CBZ/ZIP/CBR/RAR/PDF as CBZ or
  fixed-layout KEPUB with a profile-selected JPEG output; it is disabled by
  default (`STUMP_TRANSFORM_ENABLED=false`). Ordinary EPUB handling remains
  controlled separately by `KOBO_KEPUB_CONVERSION`. KOReader can render WebP in
  CBZ ([koreader#3016](https://github.com/koreader/koreader/issues/3016)).
- **Sync limits:** shelf, tag, and tag-item handlers write through to
  collections and reading lists. `/auth/device` returns non-persistent
  compatibility data, not persistent device enrollment. Stock Kobo sync has no
  annotation transport. The separate `.kobo/markups` work lives in sibling
  repository `nickelcoppice`, not in this protocol.

## Grimmory

- **Protocol:** Grimmory connects to Coppice's Komga-shaped shim under
  `/komga`: `GET /komga/api/v2/users/me`, `GET /komga/api/v1/books` (GET, not
  Komga's `POST /books/list`), `/komga/api/v1/books/{id}/file`, and
  `/komga/api/v1/books/{id}/thumbnail`.
- **Setup:** point Grimmory's server URL field at the Coppice host and use
  Basic credentials for an OPDS user.
- **Client limit:** the shim omits progression; Liseur's Grimmory provider
  pairs KOReader sync separately for positions. See
  [Komga compatibility](/docs/developer/komga-compat).

## Komf API / Komelia

Coppice ships a built-in Rust implementation of the Komf 2.0.1 HTTP contract
used by Komelia 0.19.3; Komelia can call Coppice directly without a separate
Komf service. The Komf source pin is
[`5ad67370`](https://github.com/Snd-R/komf/commit/5ad67370c5da6d94372e7c51bff62dd75053ac64).
Create a Komelia device and paste its device-bound Komf URL into the client.
The default key is read-only for Komf metadata operations; the owner may opt
into `EditMetadata`, while provider-config writes remain separately privileged.

The API is contract-tested, but no live Komelia 0.19.3 device run is claimed;
Komelia's current source record is Source-only in the
[client verification matrix](/docs/developer/client-verification). This
Komelia-facing Komf API is distinct from running an external Komf server-side
workflow: automatic operation on a real `BookAdded` burst through that separate
workflow remains **Blocked**. See the
[Komf setup guide](/docs/guides/integrations/komelia-komf) and
[Komga/Komf compatibility](/docs/developer/komga-compat).

## Kavita clients

The Kavita adapter uses `x-api-key` plus the `Plugin/authenticate` JWT flow.
Enter the Coppice server URL and API key in a compatible client. Route-level
behavior and payload mappings are documented in
[Kavita compatibility](/docs/developer/kavita-compat).

Client behavior differs: Kamigura is an image reader, so its request for an EPUB
image returns 404 by design. Other Kavita-shaped clients may use different
route subsets; consult the [client verification matrix](/docs/developer/client-verification)
for the current evidence scope.

## Lissen (Android)

- **Protocol:** the Audiobookshelf-compatible profile exposes server-root
  `/status`, `/login`, `/auth/refresh`, `/api/libraries/{id}/items`,
  `/api/items/{id}` with `/play` and `/file/{ino}`, `/api/session/{id}/sync`,
  and `/api/me` with progress and bookmarks.
- **Setup:** use the Coppice server URL, username, and password. Login mints the
  Audiobookshelf token trio (legacy `token` with no expiry, 1 h `accessToken`,
  30 d `refreshToken`) and registers an `ABS` device row, so per-device library
  scope applies. Requires the `abs` Cargo feature and
  `STUMP_ENABLE_ABS=true`.
- **Client limits:** podcast libraries are not served, only audio-container
  media appear (an ebook is invisible to this client), and
  `GET /api/authors/{id}/image` returns `404`. See
  [Audiobookshelf compatibility](/docs/developer/abs-compat).

## Official Audiobookshelf app (Android)

The official app uses the Audiobookshelf REST profile plus the shipped
Engine.IO/Socket.IO lane. Configure the Coppice server URL and account
credentials; per-device library scope applies. Tap-only seek and stale/duplicate
download-queue states are client-side interactions. See the
[client verification matrix](/docs/developer/client-verification) for the
version-specific scope; the profile is not full Audiobookshelf parity.

## Generic OPDS readers (Panels, Moon+ Reader, Librera)

The [OPDS guide](/docs/guides/features/opds) describes generic readers; it does
not certify a client against Coppice. Use URLs of the form
`http(s)://your-server(:10801)(/baseUrl)/opds/v1.2/catalog` or
`/opds/v2.0/catalog`; an API-key variant
`/opds/(api_key)/v1.2/catalog` exists for clients that cannot send headers.
Panels supports OPDS 1.2 page streaming in its upstream guide. Moon+ Reader's
guide reports no page streaming. Librera's guide reports file names instead of
book titles for OPDS 1.2 and no OPDS 2.0 support. Coppice's OPDS 2.0 catalog
has no facets support.

## Annotation and sync boundaries

- The observed Komga profile has no annotation endpoint for Komelia or Mihon
  ([Komga compatibility](/docs/developer/komga-compat)).
- The liseur-sync annotation bridge stores revisions, sequences, and tombstones
  in adapter tables; projection into Coppice's native `media_annotations`
  remains **Planned** ([liseur-sync integration](/docs/developer/liseur-sync-integration)).
- Stock KOReader/KOSync and Kobo sync have protocol-specific annotation limits
  ([sync platforms](/docs/developer/sync-platforms)).
- Liseur's KOReader-sync pairing is a separate progress protocol alongside its
  catalog providers, not a catalog protocol
  ([Liseur providers](/docs/developer/liseur-providers)).
