# Coppice

Coppice is a self-hosted library for your own ebooks, comics, manga, and
audiobooks. It is the product-facing name of this fork of the open-source
[Stump](https://github.com/stumpapp/stump) media server.

This site is the **human wiki**: it explains the supported setup paths and
links to the developer pages that hold route matrices, source references, and
verification evidence. Technical identifiers remain unchanged where clients or
distributions depend on them (`stump_server`, `Stump.toml`, `STUMP_*`, and
related package names).

## What Coppice does today

- Hosts media from libraries you control. Universal-style search discovers
  metadata; it does not itself acquire or download media. Managers can explicitly
  request and confirm acquisition through the separate MAM Bridge sidecar.
- Serves the native API plus protocol adapters for OPDS, Komga-shaped clients,
  Kobo, KOReader, Kavita, Audiobookshelf-compatible clients, and liseur-sync.
- Supports ordinary EPUB reading and ordinary audiobook playback as separate
  flows.
- Provides staged ingest and identifier matching so an allowed external file
  handoff can become a library item.
- Provides Hardcover metadata mapping with offline fixture coverage. Live
  Hardcover credentials have not been verified.
- Keeps its own request ledger, permissions, per-user visibility, operator
  approval/rejection decisions, notifications, and social handoff.

An implemented route is not automatically an app or device guarantee. Read the
[compatibility and integration status](/docs/guides/integrations/compatibility)
for the evidence label attached to each claim.

## Current, planned, and blocked

### Current

The default `full` profile includes the `webui` GraphQL web resolver and
playground surfaces. `headless` omits those Rust surfaces; Home (`/app`) and
Editor (`/editor`) are separate static applications that can still be served
when their built directories are configured. The [modular deployment guide](/docs/guides/configuration/modular-deployment)
distinguishes compile-time Cargo features from runtime `STUMP_*` and
`ENABLE_*` switches.

The shipped request system supports manager-confirmed MAM Bridge acquisition
for approved requests. The bridge is a separate authenticated sidecar; Coppice
copies completed downloads into staged ingest, where Editor approval fulfils
the request. MAM credentials and torrent transport remain outside Coppice, and
there are no in-process downloader, automatic retries, or auto-grab.
Read-aloud readiness quality checks and full synchronized EPUB/audio playback
remain open.

### Blocked

Storyteller and native CTC alignment runners are available to remote workers
when an operator configures them; neither is bundled or used as server-local
ML. Pairing, `SyncMapV1`/SMIL import, alignment enqueue, and cache-only delivery
are implemented, but synchronized reader playback is not shipped.
Hardcover account, progress, and journal sync remain blocked on live-credential
and API prerequisites. The official Audiobookshelf app has a scoped
device-tested flow; this does not establish full client parity. See the
[client verification matrix](/docs/developer/client-verification).
