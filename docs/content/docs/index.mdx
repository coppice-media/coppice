# Coppice

Coppice is a self-hosted library for your own ebooks, comics, manga, and
audiobooks. It is the product-facing name of this fork of the open-source
[Stump](https://github.com/stumpapp/stump) media server.

This site is the **human wiki**: it explains the supported setup paths and
links to the developer pages that hold route matrices, source references, and
verification evidence. Technical identifiers remain unchanged where clients or
distributions depend on them (`stump_server`, `Stump.toml`, `STUMP_*`, and
related package names).

## What Coppice does today

- Hosts media from libraries you control. Universal-style search discovers
  metadata; it does not acquire or download media.
- Serves the native API plus protocol adapters for OPDS, Komga-shaped clients,
  Kobo, KOReader, Kavita, Audiobookshelf-compatible clients, and liseur-sync.
- Supports ordinary EPUB reading and ordinary audiobook playback as separate
  flows.
- Provides staged ingest and identifier matching so an allowed external file
  handoff can become a library item.
- Provides Hardcover metadata mapping with offline fixture coverage. Live
  Hardcover credentials have not been verified.
- Keeps its own request ledger, permissions, per-user visibility, operator
  approval/rejection decisions, notifications, and social handoff.

An implemented route is not automatically an app or device guarantee. Read the
[compatibility and integration status](/docs/guides/integrations/compatibility)
for the evidence label attached to each claim.

## Evidence labels

The wiki uses these labels consistently:

- **Shipped** — implementation exists in this fork.
- **Contract-tested** — a pinned fixture, replay, or server harness exercised a
  protocol surface; this does not prove a physical app works.
- **Device-tested** — a real app or device ran the flow against the server.
- **Source-only** — pinned source was inspected without a live run.
- **Planned** — a future capability or design item.
- **Blocked** — a prerequisite is missing, so the flow is not currently
  claimable.

## Current, planned, and blocked

### Current

The default `full` server is the compatibility baseline. The `headless` profile
keeps backend protocols without the web SPA, while leaf features allow a
smaller deployment. The [modular deployment guide](/docs/guides/configuration/modular-deployment)
distinguishes compile-time Cargo features from runtime `STUMP_*` and
`ENABLE_*` switches.

### Planned

Any future acquisition integration must run as a separate authenticated
provider sidecar; no provider, implementation, or delivery date is promised.
Worker-side read-aloud alignment remains future work after an ebook and
audiobook pair has been confirmed.

### Blocked

Synchronized Storyteller read-aloud EPUB playback is not shipped. Storyteller
is a future worker-side alignment backend, never a search/catalog provider or a
bundled dependency. Hardcover account, progress, and journal sync are not
implemented and remain blocked on their live-credential and API prerequisites.
The official Audiobookshelf app also remains blocked by the missing
Engine.IO/Socket.IO lane; the Lissen-shaped REST profile is a narrower,
separately evidenced path.
