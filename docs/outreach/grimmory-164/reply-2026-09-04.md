Hi — I've been implementing the same Komga-compatible profile for another server (Stump, Rust) and got Komelia 0.19.0, Mihon (Keiyoushi Komga extension + the built-in Komga tracker) and Liseur working end to end on a phone against it. Most of what I hit maps one-to-one onto what Grimmory's `KomgaController` and Komga security chain do on `main` today (`1682a98`, with #2333 and #2377 still open), so rather than a wall of text here I wrote it up as an attached report in the hope it shortens the loop for whoever picks this issue up.

What's in the report:

- **Pinned sources.** Every claim is checked against exact commits of Komelia, komga-client 0.11, the Keiyoushi extension, Mihon's tracker, Liseur, Komga and Grimmory — not against the Komga OpenAPI in the abstract. Facts are marked `[observed]`, conclusions `[inference]`.
- **§1 Authentication.** Why a `STATELESS` Basic chain works for login and then breaks everything else in Komelia (one Basic call, then cookies; one shared cookie jar across REST/SSE/image; a download worker that authenticates with `komga-remember-me` alone), why any `Set-Cookie …; Max-Age=0` on a 401 logs the whole app out mid-read, and the three credential modes a Komga path has to accept cold (Basic → session, session cookie, `X-API-Key`). Includes the exact response contract I ended up with.
- **§2 Route table.** Every route Komelia calls, what it uses it for, and Grimmory's current status for each (mounted / 501 / catch-all 404), with a priority order derived from call volume.
- **§3 Search-condition DSL.** Both dialects `POST /books/list` and `/series/list` must decode (Komelia sends untagged conditions, Liseur sends tagged), the sort keys, and the `Page` envelope details including the `size=0` count idiom.
- **§4 DTO strictness.** The enums the Kotlin client decodes with no guard (one of them — series thumbnail `type` — fails every offline download if you emit `GENERATED`), `book.url` as a filesystem-style path, required user fields, `PatchValue` semantics.
- **§5 Real EPUBs.** Four failures that synthetic fixtures never trigger, each keyed by the exact error string the app shows: the page list must be `[]` for non-Divina EPUBs (Komelia calls it before *downloading*, not just reading), and the Readium manifest must use a string `rel`, a date-only `published`, and array-typed contributor fields.
- **§6 Mihon.** The extension uses Komga's *legacy GET* list routes with a specific query-parameter set (not `POST /series/list`), and the tracker uses `GET/PUT /api/v2/series/{id}/read-progress/tachiyomi` with its own DTOs — under `/api/v2`, which is easy to leave outside the Basic/API-key scope.
- **§7 Liseur.** It has no OPDS 2 parser at all; everything else works once auth is right.
- **§8–§9 SSE minimum event set** for the UI to refresh after edits, and the sessions/cookies contract as a table.
- **§10 Harness.** Hurl specs that replay the phones' exact sequences (cold, both auth modes) against any base URL — I'm happy to contribute them in whatever form is useful.
- **§11–§12** What I deliberately did not implement (so nobody copies a gap), and a curl recipe to verify each item above in a minute.
