# stump_provider

## Purpose

`stump_provider` is the remote-source host: a Mihon-shaped `Source` trait
(popular / latest / search / details / chapters / pages / page bytes), the
process-wide `ProviderHost` (source registry, bounded on-disk page cache,
Keiyoushi catalog, health probes, virtual-browse cache), materialisation of
remote series into ordinary `series`/`media` rows, virtual-library live browse,
and the GC that reclaims unread materialised series. It deliberately does
**not** own any HTTP route, DTO mapping, or auth: the Komga and OPDS branches
live in `apps/server/src/routers/provider_virtual.rs`, and GraphQL in
`crates/graphql/src/{query,mutation,object}/provider.rs`. Only MangaDex is
compiled in (`crates/provider-mangadex`); other catalog entries are listed
for operators but cannot be enabled.

## Decisions

| Decision | Why | Evidence |
| --- | --- | --- |
| Cargo feature `providers` (core, graphql, server) **and** runtime `STUMP_ENABLE_PROVIDERS` (default `false`) | The feature removes reqwest/MangaDex code from `minimal`; the switch keeps the host dormant in default builds until an operator opts in | `core/Cargo.toml` `providers`; `core/src/providers.rs::is_enabled`; `apps/server/src/http_server.rs` init call |
| Provider rows keep `path` non-null as a `provider://<source>/<remote>[/<chapter>]` URI; the host is the `VirtualMediaResolver` for that scheme | Every page-serving route (native, Komga, OPDS, Kobo) keeps calling the same media functions | `src/virtual_path.rs`; `src/host.rs` `impl VirtualMediaResolver`; `crates/media/src/virtual_media.rs` |
| Deterministic ids: `uuid5(series:<source>:<remote_id>)`, `uuid5(media:<source>:<chapter>)`, `uuid5(library:<source>)` | The same remote series has one identity across live browse, search, materialisation, and clients that cache ids | `src/virtual_path.rs::{series_id,media_id,library_id}`; test `browse_ids_are_stable_and_materialise_under_the_same_id` |
| Mode A (`addProviderSeries`) materialises into any library; Mode B virtual libraries (`createVirtualLibrary`) browse live and write nothing until a series' books are opened | Browsing a source must not bloat the database; opening a series is intent | `src/materialize.rs::add_series`; `src/virtual_library.rs`; `apps/server/src/routers/provider_virtual.rs::materialise_virtual_series` |
| Live browse pages are cached per `(source, kind, page)` for `virtual_series_ttl` (default 300 s) with a reverse index from stump id to origin | UUID v5 cannot be reversed; the index lets `series/{id}` and materialisation resolve ids the browse just served | `src/browse.rs`; `core/src/config/providers.rs::virtual_series_ttl` |
| Komga mapping: `fullTextSearch` → search, engagement sorts (`readCount`, `booksCount`, `readProgress`) → popular, everything else → latest; only a lone `libraryId is` condition routes live | Mihon exposes exactly three feeds; combined conditions are answered from the database, which has no virtual rows | `apps/server/src/routers/provider_virtual.rs::browse_kind`; `crates/komga/src/routes/catalog.rs::virtual_library_id_from_search` |
| Live results honour the per-user library filter and live cards report `booksCount = 0` | No live path may bypass `find_for_user`; the chapter count is unknown until materialisation | `provider_virtual.rs::user_can_access_library`; `komga_backend.rs::virtual_series_list` |
| Scanner skips virtual libraries and never marks `provider://` series missing | A virtual library has no filesystem root; a scheduled scan must not flag materialised rows | `core/src/filesystem/scanner/library_scan_job.rs::init`; `crates/scanner/src/walk.rs` missing-series filter |
| GC: provider-backed series with no reading head on any book and `created_at` older than `provider_gc_days` (default 30) are deleted daily (`StumpJob::ProviderGc`) | Materialised rows are a cache of the source; unread ones are reclaimable | `src/gc.rs`; `core/src/providers.rs::spawn_gc_scheduler`; `core/src/job/services.rs::run_provider_gc` |
| Page cache bounded by `provider_cache_max_bytes` (default 2 GiB), manifests re-resolved after 10 min | MangaDex@Home URLs expire after ~15 min; disk use must be capped | `src/cache.rs`; `src/host.rs::MANIFEST_TTL` |
| Health: probe timeout 10 s, 8 concurrent probes, `DEAD` after `provider_health_dead_after` (default 3) consecutive failures, one reachable run resets the count | Operators see which catalog sources are reachable before enabling one, and a single blip must not bury a source | `src/health.rs:19-24`, `HealthProbe::next_state`; `core/src/config/providers.rs::provider_health_dead_after` |
| Health runs as `StumpJob::ProviderSourceHealth`, one task per base URL, every `provider_health_interval_secs` (default 6 h) or on demand via `runProviderHealth`; the job builds its own catalog reader instead of borrowing the host | Sources sharing a host are probed once per run and enabled instances first; jobs only ever receive the database and the config, and the catalog index is a file both sides read | `src/health.rs::{plan,probe_target}`; `core/src/job/provider_health.rs`; `core/src/providers.rs::spawn_health_scheduler` |
| `DEAD` sources are hidden from `providerCatalog`/`providerSourceHealth` unless `includeDead: true`, and every entry carries its health row as a badge | An operator should not be offered a source that has been unreachable for three runs, but must still be able to inspect it | `crates/graphql/src/query/provider.rs::provider_catalog`; `crates/graphql/src/object/provider.rs::ProviderSourceHealth` |
| Dedupe is recorded, never enforced: materialisation writes `provider_series_identity` (normalised title + strongest external id) and links a match from another source in `provider_series_links` | Sources overlap heavily; a false positive must be a row an operator can inspect rather than silently merged (and lost) reading progress | `src/identity.rs::record_identity`; migration `m20260924_000000_add_provider_series_links`; test `same_title_from_another_source_is_linked_to_the_first` |
| `mergeProviderSeries(keep, drop)` replays the dropped heads onto the kept chapters through `reading_state::apply` (chapter number, then normalised title) and refuses non-provider series | The conflict rule and provenance must stay the single writer of reading state; a locally scanned series is never deleted by a provider merge | `src/identity.rs::merge_series`; tests `merge_repoints_heads_and_deletes_the_dropped_series`, `merge_refuses_local_series_and_self_merges` |
| GC and identity write transactions open with `models::txn::begin_write` (SQLite `BEGIN IMMEDIATE`) | The GC sweep and `merge_series` read the rows they are about to delete or repoint, and a deferred `BEGIN` cannot promote that read snapshot to the write lock while a scan or materialisation holds it | `src/gc.rs`, `src/identity.rs`; `crates/models/src/txn.rs` |
| Chapters the source cannot serve (`RemoteChapter::readable == false`) are never materialised; `Materialized.skipped` reports each `{remote_id, reason}` and `add_series` logs the count | A row for an unreadable chapter is a book whose every page 404s; an operator needs to see "0 readable chapters here", not broken books | `src/source.rs::RemoteChapter`, `src/materialize.rs::{SkipReason,insert_chapters}`; test `unreadable_chapters_are_skipped_and_counted_with_a_reason` |
| A refresh hides (`media.deleted_at`, the tombstone every lane filters on) stored chapters the source will not serve, and lists them again only when their manifest resolves; reported as `Materialized.{removed,restored}` | Skipping only fixes new materialisations: series materialised before the rule kept rows advertising pages the manifest 404s on (One Piece, `pages: 14`). A tombstone keeps progress/bookmarks and stops a feed that still advertises the chapter from resurrecting it; `refreshProviderSeries` is the only trigger, the Komga books lane materialises live-only ids only | `src/materialize.rs::{insert_chapters,verify_stored_chapters,hide}`; tests `refresh_hides_rows_for_chapters_the_source_stopped_serving`, `refresh_hides_a_chapter_the_feed_still_calls_readable` |
| A refresh re-asks the source for the page manifest (`ProviderHost::verify_chapter`, cache bypassed), budgeted at 16 rows per run, least recently checked first | The feed lies: MangaDex reports `pages: 14, isUnavailable: false` for One Piece ch. 1191 while `/at-home/server/391c1555-…` answers 404, so flags alone cannot find every stale row — and a cached manifest only proves what was true up to `MANIFEST_TTL` ago. One request per chapter is why it is budgeted and why `updated_at` is the cursor | `src/host.rs::{verify_chapter,resolve_manifest}`, `src/materialize.rs::VERIFY_PER_REFRESH`; test `refresh_hides_a_chapter_the_feed_still_calls_readable` |
| A 404 from the page-manifest lookup becomes `ProviderError::Unavailable { source_id }` → `FileError::Unavailable` → `404 Chapter is not available from <source>`, not `FileError::NotFound` | A chapter the remote stopped serving is not a missing file, and every lane (native, Komga, OPDS, Kavita) must agree on 404 instead of the old `500 File not found on disk` | `src/host.rs::pages`, `impl From<ProviderError> for FileError`; `apps/server/src/errors.rs::From<FileError>`; test `a_chapter_whose_manifest_404s_is_unavailable_not_missing` |
| `cover_url` falls back to a `details()` fetch when the stored row has no `comic_image`, and writes the URL back | A series materialised from a browse response whose cover relationship was absent otherwise reports "Series does not have a thumbnail" forever | `src/host.rs::{cover_url,store_cover_url}`; test `cover_falls_back_to_a_detail_fetch_and_is_written_back` |
| `series_metadata.age_rating` comes from `RemoteSeries::content_rating` (`safe`→none, `suggestive`→13, `erotica`→16, `pornographic`→18), raised to 18 for every series of a catalog-NSFW source | Stump has no library-level age rating — `age_restrictions` is per user and compares against `series_metadata.age_rating` — so a source-wide rule can only be expressed per series | `src/source.rs::ContentRating`, `src/materialize.rs::age_rating`, `src/host.rs::source_is_adult`; test `content_rating_and_nsfw_sources_set_the_age_rating` |
| Mode B live rows carry the same `ageRating` and are filtered by the requesting user's restriction before listing, details, cover, or materialisation | A live row has no `series_metadata` for `find_for_user` to join, so the rule has to be re-applied in the adapter or age restriction is bypassed by browsing | `apps/server/src/routers/provider_virtual.rs::{age_restriction_allows,remote_age_rating}`; `komga_backend.rs::virtual_series_list`; `opds_backend/v1_2.rs::virtual_library_feed_or_none` |
| A `403`/`503` carrying `cf-mitigated: challenge` or a `cf-chl-*` header is classified as a Cloudflare managed challenge (`SourceError::Challenged` → `ProviderError::Challenged` → `FileError::Unavailable`), not a bad status | `readcomicsonline.ru` has answered every HTML path that way since 2026-06: the host is up and refuses only clients that cannot run the challenge script, which is a different verdict from "the site broke" and needs a different fix (a cookie) | `src/http.rs::challenge_host`, `src/source.rs::classify`, `src/host.rs` `From<SourceError>`; tests `a_cloudflare_challenge_is_told_apart_from_a_real_rejection`, `a_challenge_response_is_not_reported_as_a_bad_status` |
| A challenged probe is `DEGRADED` with `error: "cloudflare challenge"` and clears `consecutive_failures`; a challenge **never** escalates to `DEAD` | `DEAD` hides a source from `providerCatalog`, and hiding a live source for a reason an operator fixes with a cookie is wrong | `src/health.rs::{CHALLENGE_ERROR,HealthProbe::challenged,next_state}`; test `a_challenged_source_stays_degraded_and_never_dies` |
| A gated host is probed **twice**: anonymously first, then once per enabled instance with the headers that instance carries; the first probe that gets through is what the row records, and every instance the challenge survives is reported in `HealthRunSummary::challenged` | The anonymous probe is what keeps the row honest for a source nobody configured — it reports what any client sees. But it is the wrong question for a source somebody *did* configure: without the second probe, an instance whose clearance works would sit at `DEGRADED` forever with nothing to tell it apart from one that is genuinely gated, and the automatic solve would re-queue on every run. Headers stay out of `HealthTarget` (a serialised job task) so a `cf_clearance` never reaches a `jobs` row | `src/health.rs::{probe_target,clear_with_configured_headers,HealthChecker::probe_with,ChallengedInstance}`; test `a_challenged_source_stays_degraded_and_never_dies` |
| A challenged enabled instance queues a `challenge_solve` worker job (`requires {"browser": true}`); the server never solves one itself and never will | A managed challenge is exactly the test for "is there a browser here", and a server is the one machine that answers no. With no browser worker the job parks in `needs_worker`, which the console shows, rather than failing or spinning | `src/challenge.rs::{solve_challenge,solve_challenges}`; `crates/worker/src/kind.rs::CHALLENGE_SOLVE`; test `a_second_ask_is_refused_while_one_is_in_flight` |
| A solved clearance is **merged** into `request_headers` (`Cookie` + `User-Agent` only), the instance rebuilt, and the host re-probed; the probe is the verdict | `setProviderSourceHeaders` replaces the whole map because an operator typing one means to; a clearance arriving must not wipe a `Referer` they configured. Rebuilding is mandatory for the same reason it is on the mutation — the built source holds a copy of the row. And a cookie that does not actually get through must leave the row where it was, or the source would report `OK` while every page 404s | `src/challenge.rs::{apply_clearance,merge_clearance,reprobe_instance}`, `src/http.rs::RequestHeaders::merged_with`; test `a_solved_clearance_is_stored_rebuilt_and_reprobed` |
| Two dedupe guards: an in-memory set of instances a solve was decided for, and a `worker_jobs` scan for a non-terminal `challenge_solve` | They cover different windows. The enqueue happens on a spawned task, so a double-clicked "Solve now" would beat the row into existence; and a job parked in `needs_worker` since before a restart is still going to run and must not be queued again | `src/challenge.rs::claim_solve`; `crates/worker/src/service.rs::active_of_kind` |
| A finished solve nobody applied is **adopted** by the next ask rather than re-solved | A parked job drains the moment a browser worker connects, and by construction nothing is awaiting it then. Its clearance is sitting in `worker_jobs.result`; without adoption the source would stay broken until the next six-hourly probe and pay for a second browser session. `RequestHeaders` has no value getter, so "already carrying this one" is asked as "would applying it change anything" | `src/challenge.rs::{adoptable_result,carries}`; `crates/worker/src/service.rs::list_of_kind` |
| A clearance with no expiry of its own is trusted for seven days; nothing polls for expiry | Cloudflare issues `cf_clearance` with a site-set lifetime and the browser reports it; a session cookie has no moment in time to record. Getting the horizon wrong is cheap both ways — the next challenged probe queues a solve a connected worker answers in seconds | `src/challenge.rs::{DEFAULT_CLEARANCE_TTL,clearance_expiry}`; test `expiry_comes_from_the_cookie_and_falls_back_to_the_default_ttl` |
| **Measured limit, 2026-09-07:** a replayed `cf_clearance` does not get a `reqwest` client past `readcomicsonline.ru`. Verified live with a clearance a real Chrome earned 40 s earlier, the exact user agent, the full `sec-ch-ua`/`sec-fetch` header set and HTTP/2: every path answers `403 cf-mitigated: challenge` | That host binds the clearance to the client's TLS fingerprint as well as UA and IP, and no Rust HTTP client can present Chrome's handshake. It limits the manual `setProviderSourceHeaders` recipe exactly as much as the automatic solve — both store a credential this edge will not accept. The machinery is still correct and still worth having: hosts that bind only UA+IP heal by themselves, and because the re-probe is the verdict a fingerprint-bound host stays `DEGRADED` instead of reporting healthy and 404-ing every page. Making one reachable needs a Chrome-fingerprinted client or routing its fetches through the browser worker, which is a different change | `docs/content/docs/developer/provider-host.mdx` "What a clearance cannot do"; `src/challenge.rs::apply_clearance` (the re-probe that refuses to lie) |
| The browser's challenge-*state* cookies (`cf_chl_*`, `_cf_chl_*`) are dropped from the jar; only the clearance and ordinary cookies are stored | A live solve handed back `cf_chl_rc_ni=8` next to the clearance — "this client has retried eight times". Replaying that on every future request is at best noise and at worst an invitation to re-challenge, and it would sit in the operator's stored `Cookie` header forever | `crates/worker/src/challenge.rs::{collect,CHALLENGE_STATE_PREFIXES}`; test `challenge_state_cookies_are_not_part_of_a_clearance` |
| Per-instance `provider_sources.request_headers` (JSON object, migration `m20260941`) is applied to every request a source makes, before the engine's own headers so a configured `User-Agent` replaces Stump's; `setProviderSourceHeaders` replaces the whole map and rebuilds the instance | Getting past a challenge means replaying the `cf_clearance` cookie a human earned in a browser, and that cookie is only accepted with the user agent it was issued to. It is per-source operator state (each host has its own cookie), and the built source holds a copy of the row, so not rebuilding would keep sending the cookie that was just replaced | `src/http.rs::RequestHeaders`, `src/host.rs::{set_source_headers,source_headers}`, `crates/graphql/src/mutation/provider.rs::set_provider_source_headers`; tests `configured_headers_are_attached_to_every_request`, `setting_headers_persists_them_and_rebuilds_the_instance` |
| Header values are never logged and never returned: `RequestHeaders`' `Debug` prints names plus byte counts, the API answers `{name, preview, length}` (`cf_c…mnop`, or `…` when the value is short), and the entity field is `graphql(skip)` | A `cf_clearance` cookie is a live session credential; a `?row`-style log line or a settings screen that echoes it back is a leak, and the operator only needs to recognise which value is stored | `src/http.rs::{RequestHeaders::masked,mask}`, `crates/models/src/entity/provider_source.rs`, `crates/graphql/src/object/provider.rs::ProviderSourceHeader`; test `stored_headers_round_trip_and_are_masked_never_echoed` |
| The host announces catalog refreshes, materialisations, and source-health *transitions* through `ProviderEventSink` (installed once by `core/src/providers.rs`), and `probe_target` records a change only when a `source_health` row already existed and its status differs | A first observation is not a transition: one cold run over the Keiyoushi catalog would otherwise broadcast an event per source. The crate cannot name `CoreEvent` (the dependency runs `stump_core` → `stump_provider`), so it emits its own vocabulary and core maps it. `HealthRunSummary` carries both the transitions and the challenged instances out to whichever caller owns a channel and a worker queue | `src/event.rs`; `src/health.rs::{SourceStatusChange,probe_target,merge}`; `src/host.rs::emit`; `core/src/providers.rs::CoreProviderEventSink` |
| The provider health job reaches the already-installed `ProviderHost` through `JobServices`, sharing `Ctx`'s `OnceLock` rather than building one | The probe that finds a gated instance is the only thing that knows to ask a browser about it, and queueing that needs the host (the source registry, the header store, the worker queue). Sharing the cell keeps "one host per process" true and leaves the job unable to install one | `core/src/job/services.rs::{with_provider_host,provider_host}`; `core/src/context.rs::job_runtime`; `core/src/job/provider_health.rs::execute_task` |
| Enabling writes the `provider_sources` row inside `models::txn::begin_write` and **builds the instance before committing**: a build failure rolls back, so a new source leaves no row and a re-enable leaves the previous row untouched | The build is the only test of "can this server run it" (a selector no engine implements, a theme with no engine, a schema from the future), and it needs the row to build from. Persisting first turned every unrunnable source into a row the API reports as enabled, nothing resolves from, and every boot logs again — a catalog-wide sweep left 164 of them | `src/host.rs::enable_instance`; test `a_failed_build_persists_nothing` |
| `ProviderHost::open` flips every `enabled = true` row it could not build back to `enabled = false` (one aggregated `warn` naming them; each failure is logged by `reload_sources`), but only when the failure is a verdict — `is_transient` spares network, I/O, database, catalog and *any* definition-index failure | The rows an earlier build left behind have to heal without an operator, and the repair must be unable to cause the damage it repairs: a boot with no network, or with the local definition directory wiped, would otherwise disable every definition-backed source | `src/host.rs::{open,reload_sources,disable_unbuildable,ProviderError::is_transient}`, `src/definition.rs::DefinitionError::is_transient`, `src/source.rs::SourceError::is_transient`; test `boot_disables_unbuildable_rows_but_never_on_an_outage` |
| A definition matches an extension package exactly first, then with a trailing `.<lang>` stripped from its id, and the catalog source's language picks between the blocks (`DefinitionIndex::find_by_pkg_lang`) | A multi-language extension is one APK with several `source {}` blocks, so the generator disambiguates the ids (`all.seraphicdeviltry.en`, `.es`) while the catalog still knows one package: without the fallback those sources reported `hasImplementation: false` and `enableProviderSource(catalogId:)` answered `NotImplemented`, and without the language the `es` entry would enable the `en` definition. Exact-first keeps a single-source extension from being shadowed by a multi-language sibling | `src/definition.rs::{DefinitionIndexEntry::pkg_without_lang,DefinitionIndex::find_by_pkg_lang,DefinitionLoader::definition_for_pkg}`, `src/host.rs::enable_catalog_source`, `crates/graphql/src/query/provider.rs::provider_catalog`; tests `a_package_matches_its_language_disambiguated_definitions`, `an_exact_package_beats_a_stripped_one` |

Routes that answer from a virtual library (Mode B):

| Route | Behaviour |
| --- | --- |
| Komga `POST /api/v1/series/list` with `libraryId is <virtual>` | live browse page, deterministic ids, no rows; rows above the user's age restriction dropped (`crates/komga/src/routes/catalog.rs::virtual_series_page`) |
| Komga `GET /api/v1/series/{id}` | live details while unmaterialised (`get_series_by_id` → `virtual_series_by_id`) |
| Komga / native `GET /series/{id}/thumbnail` | source cover via host cache for live **and** materialised provider series; uploaded thumbnail still wins |
| Komga `GET /api/v1/series/{id}/books` | materialises readable chapters on first call, then the ordinary database path (`get_series_books`) |
| Komga `GET /api/v1/books/{id}/pages/{n}` | `provider://` media resolved by the host; `404 Chapter is not available from <source>` once the source stops serving it |
| OPDS 1.2 `GET /opds/v1.2/libraries/{id}` | live browse feed with phantom next-page count (`v1_2.rs::virtual_library_feed_or_none`) |
| OPDS 1.2 `GET /opds/v1.2/series/{id}` | materialises on first call, then books/PSE pages as usual |

## Layout

| File | Responsibility |
| --- | --- |
| `src/source.rs` | `Source` trait, `RemoteSeries`/`RemoteChapter`/`RemotePage`, `ContentRating`, `SourceError` |
| `src/host.rs` | `ProviderHost`, `SourceFactory`, page/cover/archive resolution, `VirtualMediaResolver` impl |
| `src/browse.rs` | `BrowseKind`, `VirtualBrowseCache` (TTL + reverse index), `RemoteOrigin` |
| `src/virtual_library.rs` | idempotent `create_virtual_library` (deterministic library id, `watch` off) |
| `src/materialize.rs` | `add_series` / `refresh_series` → `series`/`media`/metadata rows |
| `src/gc.rs` | `gc_materialised_series` + `GcReport` |
| `src/virtual_path.rs` | `provider://` URI encode/parse, deterministic ids |
| `src/cache.rs`, `src/http.rs`, `src/rate_limit.rs` | bounded disk cache, shared HTTP client, per-source limiter |
| `src/catalog.rs`, `src/health.rs` | Keiyoushi index snapshot/refresh, health plan/probe → `source_health` rows |
| `src/challenge.rs` | Automatic Cloudflare clearance: queue a `challenge_solve`, adopt or apply what it earned, re-probe |
| `src/mock.rs`, `src/mock_http.rs` | `MockSource` and a canned HTTP server for tests (feature `mock`); `set_route_when_header` mocks a gated host |

## How to verify

```text
cargo test -p stump_provider                       # 69 unit tests: browse TTL/ids, materialise, skip/hide/restore reconciliation, enable/boot-repair, definition pkg matching, cache, GC, catalog, health, dedupe/merge
cargo test -p stump_provider_mangadex              # MangaDex mapping + rate-limit tests (no network)
cargo check -p stump_server --no-default-features --features minimal   # feature-off build
STUMP_ENABLE_PROVIDERS=true ./scripts/dev-fixture-server.sh            # live: enableProviderSource → createVirtualLibrary → Komga series/list
```
