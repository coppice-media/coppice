# `stump_devices`

## Purpose

Unified device registry: a _device_ is a registered client (Kobo, KOReader,
CrossPoint Reader, Coppice, Mihon, Komelia, Liseur, Kavita, an OPDS reader, a
script, a browser, a compute worker, or a source worker) owned by a user. The
crate mints the credential(s) a device authenticates with (a prefixed API key,
a liseur-sync token, or both for Coppice), tells the client which endpoints to
configure, and records last-seen / last-sync state every time a credential
authenticates.

It is persistence-only: SeaORM entities from `models`, no HTTP. The server
calls `DeviceService::touch` from its protocol auth paths and forwards the
returned `DeviceSeen` through the core event channel. Pairing (`device_pairing`
rows, QR flow) lives in `apps/server/src/routers/api/v2/device_pairing.rs` and
`crates/graphql`, not here.

## Decisions

| Decision                                                                                                                                                                                                                         | Why                                                                                                                                                                                                                                                                                                                                                                           | Evidence                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `set_transform_profile` still stores the document verbatim and this crate takes no `stump_media` dependency to interpret it                                                                                                      | The readers (`TransformProfile::from_device_profile` at delivery, the GraphQL mutation at write time) own the vocabulary; a registry that reshaped the JSON would silently drop the `audio` section every audio delivery reads back out of it                                                                                                                                 | `src/service.rs::set_transform_profile`; tests `transform_profile_round_trips`, `audio_transform_preset_round_trips_verbatim`                                                                                                                                                                                                                                                                                  |
| `touch` coalesces plain sightings in memory: one `last_seen_at` write per credential per `TOUCH_INTERVAL` (60 s); a coalesced call reads nothing                                                                                 | Page streams and cover bursts must not hammer SQLite; the map is shared by every clone of the service, so the debounce is process-wide                                                                                                                                                                                                                                        | `src/service.rs::touch`, `seen_within_interval`; test `touch_coalesces_sightings_per_credential_for_an_interval`                                                                                                                                                                                                                                                                                               |
| A sync summary always writes (`last_sync_at` + `last_sync_summary`)                                                                                                                                                              | Sync events are rare and are what the UI shows                                                                                                                                                                                                                                                                                                                                | `src/service.rs::touch`; test `touch_records_sighting_and_sync_summary`                                                                                                                                                                                                                                                                                                                                        |
| `DeviceSeen.first_seen` is `true` when the row had no `last_seen_at` before the write                                                                                                                                            | Notification rules key on "device first seen" without a second lookup                                                                                                                                                                                                                                                                                                         | `src/event.rs`, `src/service.rs::touch`                                                                                                                                                                                                                                                                                                                                                                        |
| `device_for_credential` is the single credential → live device lookup                                                                                                                                                            | Adapters (Kobo transform profile) need per-device state; one lookup convention, revoked devices excluded                                                                                                                                                                                                                                                                      | `src/service.rs::device_for_credential`; test `device_for_credential_resolves_live_devices_only`                                                                                                                                                                                                                                                                                                               |
| Protocol kinds get narrowed API keys (`api_key_permissions_for`); creation requires the owner to hold those permissions plus `ACCESS_API_KEYS`                                                                                   | A key must never grant what the user does not have                                                                                                                                                                                                                                                                                                                            | `src/credential.rs`; test `create_device_requires_the_kind_permissions`                                                                                                                                                                                                                                                                                                                                        |
| Credential issuance carries `InteractiveSession` or `DelegatedCredential`; delegated callers may mint narrowed device credentials but may not create or rotate `api`/`web` credentials that inherit the user's permissions       | A restricted API key must not be able to launder itself through the device registry into a full-permission key                                                                                                                                                                                                                                                                | `src/credential.rs::authorize_credential_issuance`, `src/service.rs::{create_device,rotate_credential}`; test `delegated_credentials_cannot_mint_or_rotate_inherited_api_keys`                                                                                                                                                                                                                                 |
| Komelia API keys are download-only unless an owner explicitly requests Komf metadata editing; the service requires that owner to hold `EditMetadata` and preserves the grant through credential rotation | Least privilege is the default, and a device key may narrow but never expand the owner's authority | `src/credential.rs`; `src/service.rs`; `src/tests.rs`; `apps/server/src/middleware/auth.rs` Komf mutation authorization |
| Revocation deletes credential rows and keeps the device row                                                                                                                                                                      | History stays visible; `touch` can no longer resolve the credential                                                                                                                                                                                                                                                                                                           | `src/service.rs::revoke`, `discard_credentials`; test `revoke_deletes_credentials_and_blocks_rotation`                                                                                                                                                                                                                                                                                                         |
| Liseur device tokens are bound to the device id (`liseur_sync_tokens.device_id`)                                                                                                                                                 | The liseur ops push only knows the token's device id and must reach the registry device                                                                                                                                                                                                                                                                                       | `src/credential.rs::liseur::mint`; `apps/server/src/routers/liseur_sync/storage.rs::record_device_sync`                                                                                                                                                                                                                                                                                                        |
| Default names are `"<Username>'s <Kind>"`, numbered on collision; names are unique per user                                                                                                                                      | Rename also renames the credential row so API key lists stay readable                                                                                                                                                                                                                                                                                                         | `src/service.rs::create_device`, `rename`; test `default_names_are_numbered_on_collision`                                                                                                                                                                                                                                                                                                                      |
| Every `DeviceService` write transaction opens with `models::txn::begin_write` (SQLite `BEGIN IMMEDIATE`)                                                                                                                         | `create_device` and `rename` read (`existing_names`, `find_credential`) before they write, and a deferred `BEGIN` cannot promote that read snapshot to the write lock while a scan job holds it                                                                                                                                                                               | `src/service.rs`; `crates/models/src/txn.rs`                                                                                                                                                                                                                                                                                                                                                                   |
| A device's `library_scope` is intersected with its owner's visibility, never unioned; `Only(vec![])` means the device sees nothing and `NULL` inherits. Entitlement deltas are recorded only for `DeviceKind::Kobo`              | The scope must not become a way to hand a device a library its user cannot open, so it is an `AND` in the shared query funnel and ids are validated against the owner's libraries on write. Every protocol but Kobo re-queries visibility per request; Kobo's incremental sync would otherwise never notice a book that entered or left the scope                             | `src/scope.rs`, `src/service.rs::set_library_scope`, `record_entitlement_deltas`; `crates/models/src/shared/visibility.rs`; tests `empty_array_is_a_restriction_to_nothing`, `malformed_column_falls_back_to_inherit`                                                                                                                                                                                          |
| A Kindle is an address (`devices.kindle_email`), not a `DeviceKind`: `record_delivery` writes `last_sync_at` + `last_sync_summary` and never `last_seen_at`; the address is validated syntactically and its domain is not pinned | A Kindle never authenticates — Stump mails a book out — so there is no credential to mint, no endpoint to describe, and no sighting to claim; Amazon runs several regional Send-to-Kindle domains and operators forward through their own hosts, so pinning `kindle.com` would refuse working setups                                                                          | `src/kindle.rs`, `src/service.rs::{set_kindle_email,record_delivery}`; tests `kindle_email_round_trips_and_clears`, `kindle_email_rejects_malformed_addresses`, `record_delivery_writes_a_sync_summary_without_a_sighting`; the delivery lane itself (format policy, conversion, attachment, `kindle_deliveries`) is `crates/kindle` and calls back into `record_delivery` — this crate stays persistence-only |
| `DeviceKind::Worker` is a device like any other: paired in the console, minted a prefixed API key narrowed to `ACCESS_WORKER` + `DOWNLOAD_FILE`, revocable, and it never inherits its user's permissions                         | A remote worker is exactly the thing a device registry is for — a credential the operator can see, name and withdraw — and reusing it means the worker socket needs no auth of its own, only the extra "must be this kind" rule. The narrow key matters because a worker downloads other users' books as job inputs: a stolen worker key must not be able to act as its owner | `src/credential.rs::{protocol_for,api_key_permissions_for}`; `src/endpoint.rs`; `apps/server/src/routers/api/v2/workers.rs::worker_device`; server test `the_worker_socket_requires_a_live_worker_device_credential`                                                                                                                                                                                           |
| `DeviceKind::SourceWorker` is a separate device role: its prefixed API key is custom-narrowed to `ACCESS_REMOTE_SOURCE` only, and its displayed source-worker command never reuses the compute worker authority | A source worker can advertise and serve only explicitly authorized remote-root reads; it must not inherit compute-job, download, or owning-user permissions even when one binary runs both roles | `src/credential.rs::{protocol_for,api_key_permissions_for}`; `src/endpoint.rs`; test `source_worker_has_only_source_authority` |

| Endpoint display labels use Coppice for the product name while endpoint paths, protocols, and credential formats remain unchanged | Clients consume the same URLs and credentials; only the human-readable API label changes | `src/endpoint.rs` |
| `DeviceKind::Kavita` is first-class but remains under `DeviceProtocol::Api`; its key is narrowed to `DOWNLOAD_FILE` and its endpoint is the Coppice server root labeled `Kavita server` | Kavita authenticates through the native API key lane, so adding a protocol enum would change the persisted/public protocol contract for no behavioral gain; the device kind still identifies the client in Home and sync-summary JSON | `src/credential.rs::{protocol_for,api_key_permissions_for}`; `src/endpoint.rs`; `apps/server/src/routers/kavita/backend.rs`; test `kavita_device_mints_download_only_api_key_and_server_endpoint` |
| `DeviceKind::Coppice` mints an API key (`Koreader` protocol) and a device-bound liseur token in one transaction; the API key is the singular primary for compatibility, while `credentials()` exposes both by metadata | Coppice's catalog/download/KOSync lane and annotation/read-state lane need different authentication scopes, and returning a deterministic primary preserves existing callers without making clients depend on list order | `src/credential.rs`, `src/service.rs`, `src/endpoint.rs`; tests `coppice_mints_and_replaces_both_bound_credentials`, `coppice_credentials_select_their_endpoint_lane` |
| `DeviceKind::Crosspoint` maps to the KOReader protocol but exposes only the keyed `/koreader/{secret}` base endpoint; rich `/api/v1` routes are nested below it and the key is never used for LAN delivery | CrossPoint stock sync needs only `ACCESS_KOREADER_SYNC`; server-initiated transfer is unauthenticated and separately validated on the private LAN | `src/credential.rs`, `src/endpoint.rs`, `apps/server/src/routers/koreader_backend/crosspoint.rs` |
| Typed telemetry is a separate partial snapshot: scalar fields merge only when reported and cumulative counters keep the greatest observation | Kobo/KOReader/Liseur summaries overlap only partially; preserving unrelated fields and rejecting stale counter regressions makes multi-protocol Home telemetry deterministic while `last_sync_summary` remains raw compatibility data | `src/telemetry.rs`; `src/service.rs::{record_sighting,merge_telemetry}`; `models::entity::device_telemetry`; migration `m20260953_000000_add_component_runtime` |

## Layout

| File | Responsibility |
| `src/lib.rs` | Re-exports; `liseur_token` helpers shared with the server storage |
| `src/service.rs` | `DeviceService`: list/get/create/rename/rotate/revoke/transform profile, `set_library_scope`, `set_kindle_email`, `record_delivery`, `device_for_credential`, `touch` with the in-memory debounce, `authenticate`, credential lists and endpoints |
| `src/scope.rs` | `LibraryScope`: the `devices.library_scope` column ↔ `Inherit`/`Only(ids)` mapping |
| `src/kindle.rs` | `KINDLE_EMAIL_PROTOCOL`, `KindleSendSummary`, `normalize_kindle_email`: the send-to-Kindle address and delivery summary |
| `src/credential.rs` | `CredentialRef`, kind → protocol / credential kind / permissions maps, transactional API-key and liseur-token minting |
| `src/endpoint.rs` | `Endpoint::for_kind` and `Endpoint::for_credential`: what to configure on each device kind and credential lane |
| `src/event.rs` | `DeviceSeen` |
| `src/error.rs` | `DeviceError` |
| `src/tests.rs` | Service tests against an in-memory SQLite schema |
